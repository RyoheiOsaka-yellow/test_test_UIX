# xAD UIハンドオフ仕様（UIX実装向け）

> **このドキュメントの役割**: 分析ロジック仕様（フル版・別ドキュメント）から、UI実装に必要な部分だけを抽出したもの。数理・推計の中身は含めず、「何を画面に出すか／どんなデータ構造で受け取るか／どう出し分けるか」に絞る。
>
> **読み方**: フル仕様を読む必要はない。本書だけでUI実装に着手できるよう自己完結させてある。各UIが「裏で何が動いているか」は概要だけ示し、詳細はフル仕様の該当セクションを参照（リンク表記）。

---

## 1. xADとは何か（UI設計の前提）

xADは2本柱のプロダクト。
1. **広告ダッシュボード**: クライアントの広告タイプに応じて最適なボードを選択して提供
2. **クリエイティブ自動生成（AI STUDIO）**: 既に実装が先行している領域

UIの最重要な前提：**1つの製品が、クライアントによって違う顔（ボード）を見せる**。メタ広告だけのクライアントにはシンプルなオンラインボード、販促広告のクライアントには人流・店舗を含むO2Oボード。この出し分けがUI設計の根幹。

---

## 2. ボード選択：3軸で最適ボードが決まる

ボードは「広告タイプ × 業種 × データ充足」の3軸で構成される。UIはこの3軸で表示要素を出し分ける。

### 広告タイプ（最上位の分岐）

| 広告タイプ | 表示するUI | 裏側 |
|---|---|---|
| メタのみ / オンライン横断 | 広告KPI・媒体比較・クリエイティブ（人流なし） | 通常の分析 |
| 販促ボード | 上記＋人流マップ・O2Oファネル・店舗別ビュー・推計の可視化 | 推計エンジン |

**重要**: 広告タイプが「どのUIを出すか」を決める最上位スイッチ。メタのみボードに人流UIを出してはいけない（データがないので無意味）。

### データ充足（グレーアウト制御）

未接続のデータに紐づくUIは**隠さずグレーアウト**し、「○○を接続すると有効化」と促す（アップセル導線）。

| データ状態 | UI挙動 |
|---|---|
| 人流ON＋CP ON＋POS有 | 全UI有効、推計に「校正済み」バッジ |
| 人流ON＋CP ON＋POS無 | 推計に「推定」バッジ |
| 人流ON＋CP OFF | ジオリフト系のみ、CP系UIはグレーアウト |
| 人流OFF | O2O系UIを丸ごと非表示、オンラインUIのみ |

| EC/D2C | 必須 | OFF | 任意 | OFF | 任意 |
| B2B SaaS | 必須 | OFF | OFF | OFF | OFF |

## 5. 重要UI① AIアクションカード（接続契約）

最重要のデータ構造。裏のロジックが生成し、UIが表示する。**この構造がUIとロジックの契約**。

```json
{
  "priority": "high | med | low",
  "category": "予算 | クリエイティブ | 計測 | 配信",
  "title": "LinkedInの予算を+30%配分",
  "reason": "理由テキスト（LLM生成）",
  "impact": { "metric": "CV", "delta": 12, "ci": 4 },
  "confidence": 0.87,
  "source": "L3-1 | geolift | creative | ...",
  "verification": { "status": "pending | confirmed", "result": "..." }
}
```

UI実装の注意：
- `priority` で並び順・色を決める（high=強調）
- `impact` は「CV +12件（±4）」のように幅つきで表示（点の数字でなく）
- `confidence` は3段階ラベルに変換して表示（高/中/低 ＝ 後述の統一表現）
- `verification` が confirmed なら「実行済み→効果確認」を表示（提案しっぱなしにしない）

## 6. 重要UI② 確信度の統一表現（全画面共通ルール）

裏では複数の検定・推計手法が動くが、**UIの表現は1つに統一**。どの数字も同じ3段階で見せる。

| 確信度 | 表示 | 意味 |
|---|---|---|
| 高 | 緑・「推奨」 | 行動してよい |
| 中 | 黄・「要サンプル」 | 材料不足・待て |
| 低 | グレー・「互角」 | どちらでもよい |

**全推計値・全比較の出力フォーマット**: `点推定 ± 信頼区間 ＋ 確信度ラベル`
例：「Meta増分 ¥980,000（¥820,000〜¥1,140,000）・確信度 高」

不確実性（幅）は正直に見せるが、行動指示（ラベル）は明快に。これで「数字が確定していない」と不安にさせず、何をすべきかは迷わせない。

## 7. 重要UI③ 推計エンジンの可視化（販促ボード）

深さ3層。デフォルトはL1、タップで深掘り。

### L1：成果分解ウォーターフォール（最重要）
総成果を要因に分解して積み上げ。**広告の手柄と自然発生を視覚的に分離**。
```
総売上 ¥4,820,000
├ ベースライン（広告なしでも来た分）  ¥2,100,000
├ Meta広告の増分                    ¥980,000
├ Google広告の増分                  ¥720,000
├ 人流（来店環境）の寄与             ¥620,000
└ 季節要因                          ¥400,000
```
各項に確信度ラベル（色）。これがxADの本質的差別化を1枚で見せる画面。

### L2：店舗別γの地域補正マップ（AREA MAP流用）
店舗ごとの「人流が広告効果を増幅する度合い」を地図で色分け。濃い=広告を厚くすべき店舗、薄い=立地で完結。

### L3：較正・検算ビュー（監査用・データ担当向け）
モデル推定vs実測の突合グラフ、信頼区間の幅表示。デモでは「本番で有効」と示すだけでよい。

## 8. 重要UI④ ジオリフト実験設計（AREA MAP・販促ボード）

AREA MAPに3状態を重ねる。

- **状態1 エリア選定**: マップ上でエリアを処置群（赤）/対照群（青）/除外（グレー）に塗り分け。製品が候補を自動提案、運用者がクリック調整。近すぎる処置/対照ペアは点線で警告表示。
- **状態2 検出力プレビュー**: 選定に応じて「予算¥Xで検出可能な最小効果 +Y%」をリアルタイム表示。検出不能なら赤字警告。
- **状態3 実験中モニタリング**: 処置/対照の推移を重ねたグラフ、介入時点に縦線。

---

## 9. 重要UI⑤ O2O FUNNEL（二重接続・販促ボード）

一直線のファネルでなく、上下2層構造で表示。

```
上段（集団・因果）：広告接触 → 増分来店 → iROAS
                            ↕ 突合バッジ
下段（個人・実購買）：CP応募 → 購買 → 再来店
```
- 上段は増分（幅つき）、下段は実数
- 上下がズレたら中央に警告（「来店は増えたが購買が伴わない」）
- 各ステージに「校正済み（緑）/推定（グレー）」バッジ

---

## 10. 重要UI⑥ AI STUDIO（クリエイティブ生成・実装済み）

既に実装が先行している領域。UI構造は完成済みなので、整合確認用に記載。

- 3モード：プロンプト生成／テンプレート選択／A/B自動作成
- 出力：Canvas描画でPNG書き出し、一覧保存
- A/B：勝ちそう度バッジ＋予想CTR＋差分チップ

**今後の強化（ロジック側）**: 現状「勝ちそう度」は仮のスコア。将来は過去の勝ちクリエイティブ分析に基づく実データ駆動の予測に置き換わる。UI構造の変更は不要（数字の出所が変わるだけ）。

---

## 11. デザイン原則（フル仕様より・UIに効くもの）

- **毎日触りたくなるUX**: 変化の検知（異常があれば目立たせる）＋示唆の更新（毎日アクションが変わる）。裏返せば毎日うんざりさせない＝通知過多を避ける（1日の能動通知は上限を設ける）。
- **精度を正直に開示**: 推定値・相関には必ずバッジ。確定値と推定値を視覚的に区別。
- **情報過多を避ける**: デフォルトは結論（L1）、深掘りは任意。
- **既存の器を壊さない**: 新機能は既存UIの内部に「モード」として足す。

---

## 12. アーキテクチャ前提（UIに関わる範囲）

- **デモ/プロトタイプ**: ボード単位の単一HTML、scripted応答（実物のAAAAボードのパターン）
- **本番**: Vite + React + TS、重い計算（推計・ジオリフト）はサーバー、UIは結果表示
- デモではAIの応答・推計結果は事前計算したscriptedデータで見せる（CORS制約のため実API呼び出しはブラウザから不可）
