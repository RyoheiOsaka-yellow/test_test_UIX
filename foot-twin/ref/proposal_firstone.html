02

本当の資産は「形状」ではなく、4層が同一人物で紐付いていること

形状データだけなら他社にもあります。貴社のデータが替えのきかないものになっているのは、以下の4層が1人の顧客の中で連結しているからです。図のレイヤーを切り替えてご確認ください。

①だけを持つ企業は多数存在します。②③④を同時に、しかも同一人物IDで持つ事業者は国内にほぼ存在しません。 「形状 → 主訴 → 処方 → 予後」という因果の鎖こそが、貴社データの本体です。

03

勝負すべき軸は「人数」ではなく「深さ」

人数だけで比較すると、大手の自己計測サービスには到底及びません。しかしデータの層数（深さ）を縦軸に取ると、貴社は誰もいない領域に単独で立っています。

04

3つの活用シナリオ

短期の売上インパクト、中期の中核価値、長期の資産化。それぞれ独立して成立しますが、順序をつけることで投資効率が大きく変わります。

推 奨 ／ 第 1 手
A ── 接客・可視化プロダクト

FOOT TWIN｜あなたの足を、その場で見せる

6万人分を正規化した統計DBを背後に置き、店頭で「あなたの足は6万人の中でどの類型か」「このまま10年経つとどう変形するか」を3Dで即時提示します。貴社が既に掲げている「足の現状と未来を予知する3D計測」というメッセージを、実装レベルまで引き上げるものです。

効果／説明時間の短縮、上位グレードへの引き上げ、計測単体の商品化、来店動機の創出

YELLOW側／DENTAL TWIN（3D口腔可視化）で構築済みのビューア基盤をほぼ転用可能。最短で動くものが出せます。

C ── 設計支援AI

職人の設計判断を、形式知にする

「この形状の足に、義肢装具士はどの骨を何mm持ち上げたか」——6万件の（形状 → 補正量）ペアは、そのまま学習データです。設計の半自動化は、技術が属人的でスケールしないという経営リスクに直接効きます。

前提：補正値がデジタルで構造化保存されていること。紙カルテの場合は先にデジタル化工程が必要です。

推奨する順序

A → C → B。 まず A で「自社のデータが資産である」ことを社内外に可視化し、予算と合意を取る。次に C で中核価値（設計）を強くする。最後に B で外へ売る。A は単体でも投資回収が早く、C・B の説得材料そのものになります。

成果物：稼働システム／統計DB

6ヶ月〜

設計支援AI（C）・外販（B）への展開

蓄積された正規化データを基盤に、Cの学習・Bのライセンス設計へ進みます。

成果物：設計支援モデル／ライセンス商品
06

次回、確認させていただきたいこと

以下の回答によって A / B / C の実現可能性と優先順位が変わります。フェーズ0の中心はこのヒアリングです。

  1. 6万は人数か、件数かうち3Dスキャン（点群）が現存するのは何件か
  2. データ形式計測機のメーカーと保存形式。STL / 点群としてエクスポート可能か
  3. 設計値の保存方法「どの骨を何mm持ち上げたか」がデジタル記録か、紙カルテか
  4. 主訴・症状の記録形式自由記述か、選択式か。構造化の余地があるか
  5. 再計測データの紐付けアフターフォロー時の計測が、同一人物IDで連結されているか
  6. 二次利用の同意状況現行のプライバシーポリシーがカバーする範囲、および同意の再取得可否
  7. 石こう（3次元）現物の扱いフルオーダーで作製された石こう型が保管されているか。3Dスキャンによる資産化余地
