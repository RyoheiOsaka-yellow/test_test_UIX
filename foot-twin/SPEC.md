## 0. 目的とスコープ

### 0-1. 目的

ファーストワン社が保有する **約6万人分の足部3D計測データ**（片足30,000点／両足60,000点）を、
店頭接客・設計支援・資産化のいずれにも使える **正規化された3Dビューア基盤** に載せる。

Phase 0 の本デモが証明すべきことは1点のみ：

> **「足の現状と未来を、その場で見せられる」**

### 0-2. Phase 0 のスコープ（本書の対象）

- 合成データ（手続き的生成）による完全動作デモ
- 実データを1件も受領せずに構築できること
- 単一HTMLファイル、`file://` で動作すること

### 0-3. 非目標（Phase 0 でやらないこと）

- 実スキャナからの直接取り込み
- **インソール形状の製造用CAD出力**（STL / STEP / CAM 経路）。
  v0.2 で追加した `L9_insole` は **接客時の説明を目的とした形状の可視化のみ**を行う。
  画面上のインソールは製造データではなく、出力機能を実装してはならない（§10-2 に出力形式を追加しないこと）
- 医療診断・診断的表現（後述の禁止表現を参照）
- サーバサイド、ログイン、DB接続
- 機械学習による予測（Phase 0 の「未来予測」は**パラメトリックな外挿**であり、そう明示する）

## 2. 座標系と単位

### 2-1. 座標系（厳守）

```
右手系 / Y-up
原点   : 踵接地点の中心（heel contact center）を床面上に置く
+X     : 外側（lateral）方向
+Y     : 上方（床面から離れる方向）
+Z     : 前方（つま先方向 / anterior）
単位   : mm（すべて。cm・m・正規化値をモデル内に混在させない）
```

### 2-2. 左右足の扱い（**重要／過去の失敗を踏襲しないこと**）

左足は右足のミラーだが、**ミラー変換は行列式の符号を反転させる**。
DENTAL TWIN で `axis_mesial` を外積から導出して符号が破綻した事例と同じ罠がある。

**したがって：**

- `side` は `"R" | "L"` を **モデルに明示保存する**
- `axis_medial`（内側方向の単位ベクトル）を **明示的に保存する**。外積や `side` からの導出で求めてはならない
- 法線・接線・回転量を扱うすべての箇所で `side` を参照し、ミラーによる符号反転を明示的に補正する
- 統計比較時は **左足を右足空間へ正規化してから** 比較する（`normalizeToRight(scan)`）

## 3. データモデル

### 3-1. `FootScan`

```jsonc
{
  "scan_id": "S000001-R-20260817",
  "subject_id": "S000001",
  "side": "R",                       // "R" | "L"
  "measured_at": "2026-08-17",
  "source": "synthetic",             // "synthetic" | "scanner" | "plaster"

  "axis_medial": [-1, 0, 0],         // 明示保存（導出禁止）

  "grid": {                          // 高さ場表現（Phase 0 の主表現）
    "nx": 96, "nz": 208,
    "pitch_x": 1.2, "pitch_z": 1.4,  // mm/セル
    "origin": [-57.6, 0, 0],         // グリッド(0,0) のワールド座標
    "height": [ /* Float32, nx*nz, mm。足外のセルは NaN */ ],
    "mask":   [ /* Uint8, nx*nz, 1=足内 */ ]
  },

  "landmarks": {                     // 3-3 参照。すべて mm / ワールド座標
    "pternion":        [x,y,z],
    "acropodion":      [x,y,z],
    "metatarsale_tib": [x,y,z],
    "metatarsale_fib": [x,y,z],
    "navicular":       [x,y,z],
    "sphyrion":        [x,y,z]
  },

  "metrics": { /* 3-4 参照。landmarks + grid から算出、キャッシュ */ },

  "notes": "",
  "quality": { "coverage": 0.98, "holes": 2, "confidence": "high" }
}
```

**なぜ点群（xyz列）でなく高さ場か**：足底面は床面に対して単一値関数として十分近似でき、
グリッド化により (a) 個体間比較が要素ごとの引き算になる、(b) 等高線抽出が安定する、
(c) 6万件のメモリ・転送量が桁で下がる。
実スキャンの生点群は Phase 1 で `rasterizeToGrid()` を通してこの表現に落とす。

### 3-3. ランドマーク（6点・Phase 0）

| キー | 和名 | 定義 |
|---|---|---|
| `pternion` | 踵後端 | 踵の最後端点 |
| `acropodion` | 最長趾先端 | 足長の前端 |
| `metatarsale_tib` | 母趾側中足骨頭 | 内側最突出点 |
| `metatarsale_fib` | 小趾側中足骨頭 | 外側最突出点 |
| `navicular` | 舟状骨粗面 | MLA 高さの基準点 |
| `sphyrion` | 内果下端 | 足高の基準 |

Phase 0 では合成生成時に既知の値として埋め込む。Phase 1 で自動検出を実装する。

### 3-4. `FootMetrics`（算出指標）

| キー | 和名 | 定義 |
|---|---|---|
| `foot_length` | 足長 | `pternion → acropodion` の Z 距離 |
| `foot_width` | 足幅 | `metatarsale_tib ↔ fib` の X 距離 |
| `ball_girth` | 足囲 | 中足骨頭部の周長（グリッド断面から算出） |
| `heel_width` | 踵幅 | Z = 足長×0.16 位置での幅 |
| `instep_height` | 甲高 | Z = 足長×0.50 位置での最大 Y |
| `navicular_height` | 舟状骨高 | `navicular.y` |
| `asi` | アーチ高率 | `navicular_height / (foot_length − 趾長)` × 100 |
| `arch_volume` | アーチ容積 | MLA領域の height 積分（mm³） |
| `hva` | 外反母趾角 | 母趾軸と第1中足骨軸のなす角（度） |
| `width_ratio` | 幅長比 | `foot_width / foot_length` |

`asi` と `arch_volume` が **本デモの主役指標**。この2つでコホート内位置を示す。

### 3-5. `Complaint`（主訴）

```jsonc
{ "region": "MLA" | "MTH" | "HEEL" | "KNEE" | "LOWBACK",
  "severity": 1..5, "week": 0, "free_text": "" }
```

### 3-6. `Prescription`（処方）

```jsonc
{ "landmark": "navicular", "lift_mm": 6.5, "tilt_deg": 0.0,
  "week": 0, "grade": "full" }
```

`grade`: `"athlete" | "full" | "semi" | "pattern"`（ファーストワン社の4グレードに対応）

`landmark` に指定できるキー（v0.2 で確定。`L9_insole` の補正カーネル中心に使う）：

| キー | 補正の意味 | カーネル中心 `(u, v)` | カーネル半径 `(σu, σv)` |
|---|---|---|---|
| `navicular` | 内側縦アーチの支持 | `(-0.16, 0.44)` | `(0.15, 0.115)` |
| `cuboid` | 外側縦アーチの支持 | `(+0.20, 0.40)` | `(0.13, 0.105)` |
| `metatarsale_tib` | 第1中足骨頭の支持 | `(-0.13, 0.655)` | `(0.13, 0.060)` |
| `metatarsale_fib` | 第5中足骨頭の支持 | `(+0.19, 0.615)` | `(0.12, 0.060)` |
| `transverse` | 横アーチ（中足骨パッド） | `(-0.01, 0.600)` | `(0.19, 0.055)` |
| `heel` | 踵の支持 | `(0.00, 0.095)` | `(0.24, 0.085)` |

`(u, v)` は §4-2 の正規化グリッド座標。`u` は **右足空間での値**であり、
左足へ適用する際は `axis_medial` を参照して `u` の符号を反転させる（§2-2）。
`tilt_deg` は正でカーネル中心を軸に内側を持ち上げる（回転ではなく `u` 方向の線形勾配として実装する）。

### 3-7. `Cohort`（統計母集団）

```jsonc
{ "n": 60000,
  "bins": { "asi": { "edges": [...], "counts": [...] }, "arch_volume": {...}, ... },
  "by_age_sex": { "M_40s": { "asi": {"mean":.., "sd":..}, ... } },
  "archetypes": [ /* k=7 のクラスタ代表 FootScan.grid */ ]
}
```

Phase 0 では 6万件を実生成せず、**分布パラメータのみを持ち、必要時にサンプリング**する。
`archetypes` の 7 類型は、公表されている足型分類研究（男女各7クラスタ）に対応させ、
実データ投入時に再学習して差し替えられる構造にする。

## 4. 手続き的足型ジェネレータ（Phase 0 の心臓部）

実データがない段階でも「6万人のDB」を体験させるため、パラメータから足型を生成する。

### 4-1. 生成パラメータ

| パラメータ | 範囲 | 意味 |
|---|---|---|
| `length` | 210–300 mm | 足長 |
| `widthScale` | 0.85–1.20 | 幅の全体倍率 |
| `archAmp` | 0.0–1.4 | MLA の高さ（0=扁平, 1.4=凹足） |
| `archPos` | 0.38–0.50 | MLA 頂点の足長比位置 |
| `archSkew` | -0.3–0.3 | MLA の内外側偏り |
| `transAmp` | 0.0–0.6 | 横アーチ |
| `hvaDeg` | 0–35 | 外反母趾角 |
| `toeSpring` | 0.0–0.5 | トウスプリング |
| `age` | 20–85 | 加齢の効き（4-3） |

### 4-2. 形状生成

**シルエット**は半幅プロファイル `HALFW(v)` と中心線 `CLINE(v)` の制御点補間で定義する。
補間は**単調キュービック**を使う（smoothstep は不可。理由は §4-6-3）。
`v ∈ [0,1]`（0=踵, 1=趾先）。両端は `sqrt` キャップで丸める。

```
halfWidth(v)    = lerpSmooth(HALFW, v) · widthScale · capHeel(v) · capToe(v)
centerline(v)   = lerpSmooth(CLINE, v) + hvaShift(v)
hvaShift(v)     = v > HVA_V0 ? tan(hvaDeg) · (v − HVA_V0) / U_TO_LEN : 0
silhouette(u,v) = halfWidth(v) − |u − centerline(v)|
```

**外反母趾は中心線ごと平行移動させる**（`HVA_V0 = 0.78`、母趾の領域）。
内側縁だけをずらす実装にすると、趾先で半幅より振れ幅が大きくなった瞬間に
その行のマスクが消え、**足長が最大 5% 短くなる**。中心線をずらせば幅も足長も保存され、
内側縁の傾き `dx/dz` から `hvaDeg` が厳密に逆算できる（§3-4 `hva` の算出根拠）。

**高さ場**は解剖学的構造ごとのガウス項の重ね合わせ：

```
h(u,v) = archAmp · G(v; archPos, 0.155) · medialWeight(u)
       + lateralArch(u,v)
       + transAmp · G(v; 0.615, 0.075) · G(u; 0, 0.20)
       + heelPad(u,v)
       + toeSpring · G(v; 0.945, 0.075)
h(u,v) *= min(1, silhouette(u,v) / edgeFalloff)   // 縁を 0 に落とす
```

**円の合成（union of circles）で足形を作ってはならない。** 制御点間で必ず離散化した破片が出る。
半幅プロファイル方式を厳守すること。

### 4-3. 時間モデル（「未来予測」の実体）

**時間軸の単位は「インソール作製からの経過週」**（`0週` = 作製時、上限 `WEEK_MAX = 156週`）。
年単位ではフォローの実務と目盛りが合わない。無料の微調整は数週間ごとに発生し、
店頭で説明したいのは「次はいつ調整すべきか」であって「10年後」ではない。

Phase 0 の先の表示は **決定論的な外挿** であり、統計モデルでも機械学習でもない。
UI 上で必ずその旨を明示する（§9-4 の禁止表現を参照）。

時間で動くものは 2 つある。

#### (a) 足の形状 — 加齢

```
Δyears = Δweeks / WEEKS_PER_YEAR        // WEEKS_PER_YEAR = 52.18
archAmp   ← archAmp   × (1 − 0.006·Δyears)     // アーチ低下
widthScale← widthScale× (1 + 0.0025·Δyears)    // 前足部の開張
hvaDeg    ← hvaDeg    + 0.18·Δyears            // 外反母趾角の進行
length    ← length    × (1 + 0.0004·Δyears)    // 足長のわずかな伸長
```

係数は必ず `AGING_COEFF` として1箇所に定数定義する。週単位では動きはごく小さい。

#### (b) インソール — 沈み込み（compression set）

週単位で**目に見えて動くのはこちら**。素材は初期に速く沈み、その後漸近する。

```
settle(Δw) = SETTLE_MM · (1 − exp(−Δw / SETTLE_TAU_W))
             SETTLE_MM = 0.95 mm、SETTLE_TAU_W = 6 週
Δw = 現在の週 − 直近に材を足した週（＝直近の処方の週）
```

**調整で材を足したら Δw は 0 に戻る。** 沈み込みは上面から一様に引くが、
最小肉厚 `BASE_THICK` は保つ（薄い前足部は見かけ上ほとんど沈まない）。

いずれも暫定値。**Phase 2 で実データ（縦断計測・実物の経時計測）から再推定する。**

#### (c) 記録と補間

`subject.scanWeeks` が実際に計測した週。その間はパラメータを線形補間し、
最終計測週より先は (a) で外挿する。処方・主訴・記録は最終計測週までしか増やさない。
同じ部位の主訴は**最新の記録で置き換える**（軽快した訴えを古い強さのまま出さないため）。

### 4-4. コホート生成

各パラメータを性別・年代別の正規分布からサンプリングし、
`archAmp` と `hvaDeg` には相関（ρ ≈ −0.35：アーチ低下 ↔ HVA 増加）を入れる。
相関はコレスキー分解による多変量正規サンプリングで実装する。

## 4-5. インソール形状ジェネレータ（v0.2 追加 / `L9_insole` の実体）

`Prescription[]` を足底面の高さ場に適用し、**インソール上面の高さ場**を生成する。
本節の出力は接客説明用の可視化であり、製造データではない（§0-3）。

### 4-5-0. 表現（**足底面のグリッドとは別**）

インソールは高さ場グリッドではなく **パラメトリック曲面 `(s, t)`** で持つ。

```
s ∈ [0,1]   長さ方向。標本点の z 間隔は足グリッドの pitch_z と一致させる
t ∈ [-1,1]  幅方向。t=±1 が外形の縁そのもの
x(s,t) = ( centerline(s) + t · halfWidth(s) ) · U_TO_LEN · foot_length
```

**理由**：足底面と同じ `nx=96` のグリッドで持つと、列ピッチが約 1.6 mm になる。
足は面積に対して外周が短いので目立たないが、インソールは全面が「縁の見える板」であり、
輪郭が**はっきり階段状に見える**。`t` を縁に固定すれば外形が標本点そのものになり、
側面・底面も同じ点列から張れるので継ぎ目も開かない。

長さ方向は足グリッドの行に整数でそろえる（前後に `zPad` 行ぶんはみ出す）ため、
差分の計算に z 方向の補間誤差は入らない。`x` 方向のみ行内で線形補間する。

### 4-5-1. アウトライン（**足のシルエットをそのまま使ってはならない**）

インソールの外形は足の輪郭ではなく **靴のラスト（木型）の底面形状**に従う。
実物（ファーストワン社 BestPosition のトップカバー）を観察すると、足型と次の点で異なる：

- 趾が分離せず、**先端は単一の丸みで閉じる**
- 踵は足の輪郭より絞られ、円弧に近い
- ウエストの締まりが足型より浅く、全体に平滑

そこで**専用の半幅プロファイル `LAST_PROFILE(s)`** を持つ。足の `HALFW` の加工では
足の趾やウエストの特徴が残ってしまい、実物と結び付かない絵になる。
値は足囲部の半幅に対する比で与える：

| s | 0.00 | 0.10 | 0.24 | 0.33 | 0.43 | 0.53 | 0.61 | 0.72 | 0.86 | 0.95 | 1.00 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 比 | 0.30 | 0.625 | 0.685 | 0.670 | 0.692 | 0.790 | 0.915 | **1.000** | 0.918 | 0.735 | 0.560 |

```
halfWidth(s) = lerpSmooth(LAST_PROFILE, s) · BALL_HALF · widthScale · LAST_WIDTH
lastLength   = foot_length × LAST_SCALE                  // LAST_SCALE = 1.045
先端 s > TOE_MERGE(=0.88)  : 楕円キャップへ置き換えて丸く閉じる
踵端 s < HEEL_ROUND(=0.10) : 楕円キャップへ置き換えて丸く閉じる
halfWidth は MIN_HALF_W を下限とする
```

キャップに**楕円**を使うのは、制御点補間だけで 0 へ落とすと smoothstep の端で
接線が寝て、先端が丸みではなく平らに見えるため。
`MIN_HALF_W` の下限は、両端で幅方向の標本点が 1 点に潰れて三角形が縮退し、
法線が暴れて先端に黒い縁が出るのを防ぐ（実物の縁も角ではなく丸い）。

`hvaDeg` はインソール外形に**反映させない**。ラストは母趾の変形に追従しないため。

### 4-5-2. 上面

```
base(x,z)   = extend( blur( foot.height, SMOOTH_ITER ), DILATE )
lift(u,v)   = Σ_p  p.lift_mm · Kp(u,v)  +  p.tilt_deg 由来の勾配項
cup(s,t)    = CUP_MM · G(s; 0.10, 0.09) · clamp01(1 − dEdge/RIM_MM)^1.5
top(s,t)    = max( base + lift + cup,  BASE_THICK )
```

- `Kp` は §3-6 の表に定義した異方性ガウス核。`v` 方向と `u` 方向で σ が異なる
- `BASE_THICK`（= 2.5 mm）は最小肉厚。底面は床面（Y=0）に接する平面とし、
  厚みは `top` そのものになる
- `blur` は `[1,2,1]` の可分フィルタを `SMOOTH_ITER` 回。マスク外セルは平均に含めない
- **`extend`（マスク外への拡張）は省略できない。** インソールは足より一回り大きいので、
  足の縁の外を単に 0 にすると縁で高さが数 mm 落ちる崖ができ、
  面に折れ目として出る。近傍平均を `DILATE` セルぶん外へ伸ばし、
  外へ行くほど床へ寄せる（係数 0.72）ことで縁が自然に寝る
- `dEdge` は縁からの距離 `(1−|t|)·halfWidth·U_TO_LEN·foot_length`

### 4-5-3. 差分表示

`top(u,v) − foot.height(u,v)` を §8 の発散カラーマップ（±5mm 固定）で塗る。
これが「義肢装具士が足に対して何をしたか」の可視化そのものであり、本レイヤの目的である。
値が 0 の領域は足底が接している箇所、正の領域が持ち上げた箇所を示す。

### 4-5-4. 定数

すべて `CONST.INSOLE` に集約する（CLAUDE.md 規約9）。

| 定数 | 値 | 意味 |
|---|---|---|
| `LAST_SCALE` | 1.045 | ラスト長 / 足長 |
| `LAST_WIDTH` | 1.02 | ラスト幅倍率 |
| `TOE_MERGE` | 0.88 | 先端を楕円キャップへ置き換え始める s |
| `HEEL_ROUND` | 0.10 | 踵を楕円キャップへ置き換え始める s |

## 4-6. 立体化（v0.3 追加）

足底面はグリッドで持つ（実データの受け皿がそれだから）が、**表示は閉じた立体**にする。
足底面のシートだけでは、歯型模型のように「回して見られる物体」にならない。

### 4-6-1. 断面リング

```
リング1周 = 足底側（内→外、NB 点）→ 甲側（外→内、NT−2 点）
tt ∈ [−1, 1]   断面内の正規化座標。tt = ±1 が接地シルエットの縁
足底 y(tt) = 高さ場 h(u, v)
甲   y(tt) = max( THICK(v)·足長·(1−tt²)^DORSAL_P·(1 + DORSAL_SKEW·(−tt)),
                  足底 y + SOLID_MIN_GAP )
```

- `tt = ±1` で厚みが 0 になるので、上下面が縁で厳密に一致して閉じる。
  **グリッドのマスク境界で突き合わせてはならない。** 境界セルではまだ厚みが残っており、
  縁が数 mm 開く
- **甲側は床からの絶対高さで決める。** 足底面からのオフセットにすると、
  トウスプリングや横アーチの膨らみがそのまま甲の凹凸として出る
- **甲側の標本は `cos` で刻む**（両端が密）。断面 `(1−tt²)^p` は縁で接線が立つので、
  等間隔だと縁の隣の点が一気に数 cm 上がり、側面が粗いファセットになる
- 平面外形と厚みには**接地シルエットとは別のキャップ**を掛ける。
  `sqrt` キャップのままだと、踵で幅が 0 に潰れているのに断面高さが 0.09·足長 残り、
  立てた板のような楔になる

### 4-6-2. 定数

| 定数 | 値 | 意味 |
|---|---|---|
| `SOLID_NB` / `SOLID_NT` | 40 / 40 | 断面の足底側／甲側の標本数 |
| `DORSAL_P` | 0.42 | 断面のふくらみ。0.5 が楕円 |
| `DORSAL_SKEW` | 0.13 | 内側（母趾側）を高くする量 |
| `SOLID_PLAN_POW` | 0.35 | 平面外形の端キャップ指数 |
| `SOLID_CAP_HEEL` / `_TOE` | 0.055 / 0.045 | 厚みの端キャップ範囲 |
| `SOLID_MIN_GAP` | 3.0 mm | 足底面と甲の最小の隔たり |
| `THICK(v)` | 表 | 断面高さ ÷ 足長。v=0.18 で最大 0.255 |

### 4-6-3. 制御点補間（**smoothstep を使わない**）

`HALFW` `CLINE` `THICK` `LAST_PROFILE` の補間は **単調キュービック（Fritsch–Carlson）**。

smoothstep は各制御点で傾きが 0 になる。単調に増減するプロファイルを繋ぐと
制御点ごとに平坦部ができ、**立体化したとき面に横縞として出る**。
単調性を保ったまま C1 で繋ぐこと。

## 5-4. 表示モード（v0.4 追加）

| モード | カメラ | 操作 | 描くもの |
|---|---|---|---|
| **3D** | 透視（`PerspectiveCamera`） | ドラッグで回転／右ドラッグで移動／ホイールで拡大／自動回転 | 閉じた立体（§4-6） |
| **2D** | **正射影**（`OrthographicCamera`）を床の下に固定 | ドラッグで移動／ホイールで拡大。**回転しない** | 足底面の平面図 |

**2D を正射影にする理由。** 透視だと手前が大きく写り、画面上で長さを比べられない。
図面として使うには正射影でなければならない。視点は足底面を見るので床の下、
つま先が画面の上を向く（`up = +Z`）。

### 2D の描き方（**深度ではなく描画順**）

2D は図面なので、重なりを深度テストではなく `renderOrder` で決める。
深度を残すと、土踏まずでインソールが足底面より上に来て互いを虫食い状に隠し合う。

| 順 | 対象 |
|---|---|
| 1–3 | インソール上面（側面・底面は**描かない**。真下から見ると手前に来て上面を覆う） |
| 4 | 足底面（`MeshBasicMaterial`。**無照明**にする。照明を残すと光の当たり方で色が変わり、カラーマップの値が読めなくなる） |
| 5 | インソール外形線 |
| 7 | 足の外形線 |
| 8–9 | 等高線 |

**外形線は 2D の必須要素。** 陰影がないので、線がないと足底面の縁が背景
（ほぼ同じ明度）に溶けて図面にならない。マスク境界から取った輪郭は
列ピッチ 1.6mm の階段になるため、移動平均で平滑化してから描く。

インソールを表示するときは足底面を伏せ、代わりに足の外形線を重ねる。
両方を塗ると互いを隠すうえ、「足がどこに載るか」は線のほうが読みやすい。
