0. 回答の要点

結論: ANGLEX は ブラウザで動く Web アプリで、AI 処理（図面認識・部材推定・リスク判定・見積生成）はすべて利用者 PC のブラウザ内で実行します。AI 用 GPU サーバーは不要です。インターネット接続のない環境でも、ライブラリ同梱のオフライン版（単一 HTML ファイル、約 21 MB）と、社内 LAN に置く小型サーバー（Node.js、既存サーバー／仮想環境で可）の組合せで利用できます（対応済）。
項目回答の要約対応状況
① 提供・設置方式オンプレミス推奨。インターネット非接続環境は「オフライン版 HTML ＋ 社内サーバー」で利用可。閉域内で完結し外部通信は発生しない対応済
② 利用者 PC最小: 4 コア / 8 GB / SSD 128 GB / 内蔵 GPU（WebGL2）。推奨: 6〜8 コア / 16 GB / SSD 512 GB / 独立 GPU 4〜8 GB。Windows 10/11・macOS、Chrome / Edge。AI 処理端末と 3D 閲覧端末は同一仕様で可（閲覧専用は最小構成で十分）対応済
③ サーバー専用サーバー・AI 用 GPU とも不要。見積の社内共有を行う場合のみ小型サーバー 1 台（2 vCPU / 4 GB / 20 GB）。既存サーバー・仮想環境・コンテナで可対応済
④ 周辺機器必須なし。推奨: 24〜27 型モニター 2 台、A3 スキャナー（図面は PDF/DXF の電子データ推奨）、A3 カラープリンター。サーバー運用時は日次バックアップと UPS を推奨対応済
⑤ 推奨機種動作確認済み環境と、仕様で指定する推奨機種例（Dell / HP / Lenovo のワークステーション・ビジネス機）を記載。型番は調達時点の後継機で可対応済

1. 製品の技術的な前提（回答の根拠）

  • 実行形態: HTML / JavaScript（ES Modules）による単一ページ Web アプリ。3D は WebGL 2（three.js）、帳票 PDF・XLSX の生成もブラウザ内で完結します。
  • 「積算AI」の中身: 図面（DXF / PDF）の線分・寸法・注記からの部材認識、ルールベース推論（形鋼仕様・穴・仕上げの推定と信頼度）、リスク行列（信頼度 × 手戻りコスト）による「推論／要判断／確定」の 3 状態判定、BIM モデルからの重量・集計・見積の自動生成。いずれも CPU 上の JavaScript で数秒以内に処理し、学習済みモデルの推論サーバーや GPU は使いません。
  • 生成 AI 連携（任意）: 日本語指示入力の解釈は内蔵パーサーで動作します。外部 LLM（Astra GPT 等）との連携は任意機能で、利用時のみインターネット接続が必要です。閉域運用では無効化できます。
  • データ保存: 単体利用時はブラウザのローカル保存（IndexedDB / localStorage）と JSON 書出し。共有利用時は社内サーバーの JSON ストア（ファイル）または REST API。
  • 検証済みの負荷: デモ案件（5〜150 部材、約 260〜5,000 メッシュ）で、ソフトウェア描画（GPU なし・SwiftShader）でも起動・3D 表示・PDF/XLSX 出力・図面読込が動作することを自動テストで確認しています。独立 GPU があると高品質表示（環境光 HDRI、接触陰影、MSAA 4x）が 60 fps で滑らかになります。

2. ① 提供・設置方式

ご質問
先日のミーティングではオンプレミス型を推奨されていたかと存じますが、インターネット接続のない環境でも利用可能でしょうか。

回答: 利用可能です（対応済）。 次の 3 形態から選べます。小規模導入では 形態 B（社内サーバー型）を推奨します。

形態内容インターネット向いている規模
A. スタンドアロンオフライン版 HTML ファイル 1 つを各 PC に配布。データは各 PC のブラウザに保存、案件は JSON で受け渡し不要1〜3 名の試行
B. 社内サーバー型（推奨）社内 LAN の小型サーバーに ANGLEX を配置。各 PC はブラウザでアクセス。案件・見積・受け渡しリンクをサーバーで共有不要（閉域で完結）1 部署〜複数部署
C. クラウド型当方ホスティング（または貴社クラウド）に配置。社外の販売会社・加工工場との見積共有を同じリンクで行える必要社外連携が主目的の場合

閉域で制限される機能: 以下はインターネット上の素材・サービスを使うため、閉域では自動的に無効化または代替表示になります。業務機能（図面認識・3D・重量・見積・帳票）には影響しません。

  • 3D の環境光プリセット「倉庫／工場／屋外」（閉域ではスタジオ環境光を同梱して使用）と Poly Haven の写真テクスチャ（手続き的な金属質感で代替）
  • Web フォント（システムの日本語フォントで表示。帳票 PDF 用の日本語フォントは同梱）
  • IFC 読込（web-ifc ライブラリ。必要な場合はサーバーに同梱配置可能）、外部 LLM 連携

補足: 形態 B では、販売会社・加工工場への受け渡しリンクは LAN 内でのみ開けます。社外と共有する場合は、見積書 PDF / XLSX の送付、または形態 C の併用（社外向け見積のみクラウド）となります。

4. ③ サーバーの要否・仕様

ご質問
専用サーバーや AI 処理用 GPU は必要でしょうか。必要な場合は、推奨構成・台数についてお教えください。また、既存サーバーや仮想環境の利用は可能でしょうか。

6.5 補足: 20 営業所と工場で共通に使う場合の仕分け

ご質問（打合せでの懸念）
20 営業所が 1 ID ずつ使う場合、全営業所と工場で共通に使うのがシンプルだが、案件が営業所ごとに仕分けしづらいのでは。営業所ごとに分けると工場側が ID を何個も作る必要があり、サーバー容量やマスタ読込も不利では。

回答: 「全営業所と工場で 1 つのシステム・1 つの DB を共有し、案件・見積を営業所で仕分ける」方式に対応済みです。 工場は 1 ID で全営業所の案件を扱え、営業所の担当者は自営業所の案件だけが既定で見えます（必要なら全営業所に切替）。

  • ユーザーに所属営業所（拠点マスタ: 本社・東京・大阪・名古屋・福岡・仙台…追加可）を持たせ、案件・見積に営業所コードを付与。見積番号にも営業所コード（Q-TKY-2026-0001）。
  • 案件一覧・ダッシュボード・開くダイアログは所属営業所で絞込。工場・販売は全営業所を横断し、営業所チップで件数と「自分の番」を確認。サーバー API も所属で絞るため、他営業所の案件は一覧に出ません。
  • マスタ（カタログ・単価表・学習データ）は全社共通。サーバーは 1 台のまま（20 営業所 × 年 50 案件でも DB は数百 MB 以内）。
  • ID 数: 営業所 20 ID ＋ 工場 1〜2 ID ＋ 販売（必要な場合）で済みます。
