1. システム概要

1.1 目的

配管支持金具（架台・ブラケット・吊り金具・バンド・特注加工品）の積算業務において、図面の読み替え・部材の拾い出し・重量計算・見積作成・加工指示・他社との受け渡しを、1 つの 3D モデルを単一ソースとして自動化・可視化する。人が必ず確認すべき箇所（溶接・穴・アンカー・図面根拠）を明示し、確認なしに次工程へ渡らない仕組みで手戻りを防ぐ。

1.2 基本方針

  • 単一ソース: ファミリの parts() が生成する部品リストから、3D・質量・集計・見積・帳票のすべてを派生させる。入力は一箇所、出力はすべて整合。
  • 3 状態モデル: 認識結果を「推論／要判断／確定」で管理し、リスク行列（信頼度 × 手戻りコスト）で要判断の境界を決める。
  • 人の確認をゲートに: 未確認項目が残ると受け渡し・確定を止め、上書きは理由付きで監査ログに残す。
  • 役割で見える範囲を限定: A社（見積作成）・B社（販売）・C社（加工工場）でフィールド単位の閲覧・編集権限を分ける。
  • ブラウザ完結: 図面認識・3D・計算・帳票生成はすべてブラウザ内で動作し、GPU サーバーや外部サービスに依存しない。

3. 機能仕様

3.1 図面読込と部材認識

  • DXF / PDF / 画像の読込。線分・円・寸法・注記・レイヤから形鋼の輪郭・穴・寸法を抽出し、部材候補（ファミリ・寸法・仕様・仕上げ）を推定する。
  • 各推定に信頼度を付与し、リスク行列（部材の寸法区分 × 加工種別 × 手戻りコスト）で「推論（自動確定）／要判断（人が判断）」に振り分ける。根拠（図面の座標・注記）を保持。
  • 認識結果は一覧で確認し、図面上の矩形クリックと 3D の部材が連動する。
  • 日本語の加工指示入力（例「MF-1 と LB-1 を隅肉溶接 6 両側」「MF-1 に φ15 穴 2 個 @100 端から 50」）を解釈して接合・穴を追加する。

3.2 BIM モデル

  • ファミリ（34）は寸法・仕様・加工・配管などのパラメータ（タイプ／インスタンス スコープ、式）を持ち、parts() で部品リスト（部材・板・管・ボルト・ナット・座金・アンカー・全ねじ・U ボルト・溶接・曲げ品）を生成する。
  • タイプ → インスタンス（位置・回転・レベル・個別パラメータ・CAD 役割上書き・追加穴・状態・確認記録）。接合（溶接／ボルト）は 2 部材を指定して定義し、穴・溶接を派生させる。
  • カタログ（151 製品 / 700 SKU）からタイプを生成。ショールームで製品を選ぶと 3D に並び、サムネイルは事前生成して同梱。
  • Undo / Redo、作業スナップショット（名前・メモ付きの状態保存と復元）、自動保存。

3.3 3D ビューア

  • 視点: 3D / アイソメ / 平面 / 立面（正面・側面・背面）/ 下面。フィット、焦点移動（距離維持）、カーソル中心ズーム、手のひらパン、カメラのイージング。
  • 表示: リアル（HDRI スタジオ／倉庫／工場／屋外、GTAO、MSAA、ソフトシャドウ、PBR 材質、汚れ・粗さムラ、溶接の熱影響色）、陰影、エッジ、隠線、ワイヤ、半透明、CAD 図面色（役割別フラットカラー・凡例）。
  • 選択: 部材 → 部品の 2 段階、Shift+クリックで複数選択、アウトライン強調、ホバー吹き出し。
  • 編集: コンテキストバー（同じ部材を隣に／穴／溶接／ファミリ固有の追加／寸法ステッパー／軸ロック移動 5 mm／密着スナップ／単独表示／分解図／配管へ取付／等ピッチ配置／ズレ補正）、移動・回転ギズモ、矢印キー移動、複数選択の整列・複製・削除・一括取付。
  • 配管への取付: 取付先の呼び径に支持金具の配管パラメータ（pipes / od / nominal）を合わせてから再生成し、U ボルト穴ピッチ・位置・向きを同時に揃える。ホットスポット（◎ 呼び径）とゴースト プレビュー。
  • 分解: 部材単位／部品単位の分解表示、バルーン番号、部品表、個別部材化（組立品の分解）。断面ボックス、計測、レベル表示、溶接記号（JIS Z 3021）、工場／現場の区別。

3.4 確認（レビュー）とズレ補正

  • 確認事項を自動生成: 溶接（種類・脚長・長さ・工場／現場）、穴（径・長穴・用途・個数・位置）、アンカー、U ボルト、吊ボルト、仕上げ、図面根拠、リスク要因。3D に ⚑ フラグを立て、クリックで該当部材へ。
  • 確認リスト、まとめて確認ウィザード（カード送り・3D 自動フォーカス・溶接／穴あけ指示・部材の確定・同種一括）、確認済・指示済の記録（担当・日時・メモ）。
  • ズレ検出: 隙間（部材間）、レベル差、穴の板外・5 mm 単位外、配管との不整合、接合不良。補正: 相手に密着、レベルへ合わせる、部材長 L／架台高さ H の延長、穴の端あき・丸め。
  • ゲート: 未確認が残ると受け渡し・確定で停止。理由付き上書きは監査ログに記録。

3.5 重量・集計

  • 製品ごと・モデル全体の質量（鋼材 穴控除後／めっき付着／ボルト類／溶接金属）、表面積、溶接長、穴・長穴数。
  • 集計表: 部材、ボルト・ナット・座金、溶接、穴、仕上げ。CSV / XLSX / PDF。

3.6 見積と業務フロー

  • モデルから明細（品名・仕様・符号・数量・質量・基準原価）を自動生成。A社 マージン、B社 利益率、C社 工場単価・納期・受注可否をフィールド単位の権限で編集。
  • 受け渡し（A → B / C、B → C / A、C → A / B）: トークン付きリンクを発行し、メッセージ・回答期限を付けて通知文（メール／チャット用）を生成。改訂（Rev）として状態を凍結し、監査ログに記録。差戻し、確定（A社）。
  • 業務フロー パネル: モデル → 確認 → 重量・集計 → 見積 → 共有 → 確定 の 6 段階を、状態・数字・次の一手とともに 1 画面に表示。最上部に「次の一手」バナー（いま何をすべきかと、そのボタンを 1 つだけ。期限超過は赤）。共有カードに 作成 → 受け渡し → 差戻し → 確定 のタイムライン（いまボールがどこにあるか）。B社・C社は役割専用の簡略ビュー（同じく次の一手バナー付き）。
  • 催促文: 回答期限超過・未回答 3 日以上の相手に送る催促文（期限・未入力行数・リンク）を業務フローとダッシュボードから生成。
  • 期限通知の自動化: 判定ルール（期限超過／期限 1 日以内／未回答 3 日以上）を js/core/reminders.js に一本化。クライアントは起動時と 10 分ごとに数えてダッシュボード ボタンにバッジ、起動時にトースト、通知一覧（種類・経過日数・サーバー送信記録）。サーバー版は 1 時間ごとに担当会社のユーザー宛へメールを自動送信（依存なしの SMTP クライアント: STARTTLS / 465 / AUTH LOGIN。同じ見積・種類は 24 時間に 1 通。SMTP 未設定なら outbox ログに保存）。GET /api/reminders、POST /api/reminders/run（A社）。B社・C社ビューの最上部に期限帯、ダッシュボードは期限 1 日以内を上位に。B社・C社ビューは自社の番のとき未入力行を上に並べ、「未入力だけ表示（残り n 行）」で絞り込める。C社は「前回回答を流用」（単価マスタ履歴の中央値を未入力行へ）と「全行 受注可」で、B社は「前回の利益率を流用」（顧客 × 区分の履歴）で、ほぼワンクリック回答。
  • スキャン図面の要判断は、業務フロー ① から「図面上で修正」へ直接遷移。
  • 確定前チェック: 受注不可・未回答・利益率未入力・要求納期超過の行を一覧にして停止。
  • 比較ビュー: Rev 間の差分（役割で見える列、▲増▼減、追加・削除、変更理由）と会社間の金額（工場単価 → A社提示 → 販売単価、上乗せ率、粗利）。
  • ダッシュボード: 案件横断で見積状態・担当・合計・未確認・期限を並べ、「自分の番」と期限超過を上位に。

3.7 営業所（拠点）の仕分け

  • 全営業所と工場が 1 つのシステム・1 つの DB を共有し、案件・見積に営業所コード（branch）を持たせて仕分ける。拠点マスタはデータ駆動（追加・変更可）。
  • ユーザーは所属営業所を持つ。A社（営業所）は自営業所の案件が既定、工場・販売は全営業所を横断（営業所チップで絞込・自分の番の件数）。サーバー側でも所属で絞る。
  • 見積番号に営業所コード（例 Q-TKY-2026-0001）、通知文・役割ビューに営業所名。マスタ（カタログ・単価表・学習データ）は共通。

3.7.1 営業所・ユーザーの管理

  • 拠点マスタ（コード・名称・略称）とユーザー（氏名・メール・会社・所属営業所・全営業所スコープ）を管理画面で追加・変更・削除。CSV 取込（既存は上書き）・書出し・テンプレート。サーバーは /api/branches、/api/users/bulk。

3.8 標準単価マスタ（学習）

  • C社の回答（工場単価・納期・受注可否）を 部材種別 × 仕様 × 寸法区分 で蓄積。次回の見積作成時に中央値を基準原価・納期の初期値として適用（元値保持・監査ログ）。
  • 想定（モデル原価）と回答の乖離を集計し、見直し候補（乖離 ≥10%・3 件以上）を提示。履歴 CSV。

3.9 組立確認

  • 干渉チェックに工具スペース判定（締結部品の頭／ナット側 2.5M+20 mm × 1.6M）を追加。保温厚パラメータで U ボルト径・穴ピッチ・配管高さを保温外径で決定。分解図の組立順列と、工程表・現場作業付きの組立図 PDF。

3.10 ラスター図面と認識の学習

  • スキャン PDF・画像をブラウザ内でベクタ化（二値化 → ラン抽出 → 直線・矩形、残りの連結成分から斜線と円）し、縮尺と dpi から mm 化して認識器へ。仕様注記は読めないため要判断中心。
  • 限定 OCR: ベクタ化で残った小さな連結成分（文字の画）を行単位の領域にまとめ、Tesseract.js（WASM、ブラウザ内。単一ファイル版にも同梱）で読む。読む対象は部材仕様（L-50x50x6 / [-75x40x5x7 / FB-6x50 / PL-9x150）・穴注記（2-φ15）・長さ（L=600）に限定し、φ→9 / o、[ の脱落などの誤読を正規化。読めた注記は TEXT として既存の認識器に渡し、注記の長さと外形が一致する矩形に紐付ける（OCR 由来は確信度 −0.1〜−0.2、長さの根拠を「寸法注記(OCR)」と表示）。
  • 日本語 OCR（限定語彙）: 英数パスで仕様・穴・長さが読めなかった領域だけを日本語モデル（tessdata fast jpn、同梱）で読み、仕上げ（溶融亜鉛めっき / HDZ / 電気亜鉛 / SUS）・溶接（▷n 全周 / 隅肉）・長穴 n×m・Uボルト nA・アンカー Mn の語彙に当たる語だけを採用して注記にする。これにより要判断の理由「仕上げ（注記なし）」「溶接（注記なし）」が減る。
  • ボルト接合の提案: 接触する 2 部材の穴が接触面上で一致（±4 mm）する箇所をボルト接合候補として挙げ、適用時はその穴位置にボルトを立てる（穴は追加しない）。
  • 学習の見える化: 管理画面「学習の状態」に署名ごとの件数と次回の効果、読込ごとの要判断率の推移、図面様式 × 営業所 ごとの要判断率と目標ライン（既定 20%）を表示。学習・単価と利益率の履歴・読込統計を JSON で書き出し／読み込み（重複除外）。
  • 提案接合の確認: 推論状態の接合は確認ウィザードの先頭カードに出て、3D がその穴へ寄り、確定／外す を 1 クリック。
  • 外形の復元: 4 本の LINE で描かれた矩形もポリライン同様に部材外形候補にする（枠・表題欄レイヤは除外）。
  • 穴位置: 図面の円があれば実位置を 3D の穴に（単材は holes DSL、板は extraHoles DSL）。注記の穴数だけなら等ピッチで仮置きし、確認事項に位置確認を出す。
  • 検証結果の取込: 検証キットの feedback_template.csv（正誤・正しい仕様・長さ・署名）を管理画面から読み込み、○ は正例、× は修正／部材ではない として学習に反映。
  • 注記の部材紐づけ: 仕様を含まない注記（穴・アンカー・仕上げ・溶接・Uボルト）は最寄りの部材 1 つ（外形からの距離 400 mm 以内）に紐付け、穴数・径は配置時に 3D の穴になる。穴注記の行は英数に加えて日本語パスでも読み、「アンカー M12」を拾う。
  • デスキュー: 二値化後に黒画素の行投影分散が最大となる角度（±4°、0.25° 刻み）を推定し、0.3° 以上なら元画像を回して二値化し直す（紙の置きずれ対策）。
  • 図面上で修正: スキャン画像を薄く重ねた図面ビューで、矩形（部材）→ 仕様・長さ／部材ではない、円（穴）→ 穴径／穴ではない、文字（OCR）→ 読み直し をクリックで修正。修正は即座に再認識され（手入力は確信度 0.98）、「部材ではない」「仕様を直した」は署名ごとに学習（2 件以上で次回の候補に反映）。元に戻す対応。
  • 実スキャン検証キット: node dev/raster-real.mjs <フォルダ> [--scale 10] [--dpi 300] がフォルダ内のスキャン画像（PNG / JPG、スキャン PDF は 1 ページ目を dpi で描画）を順にデスキュー＋ベクタ化＋OCR し、検出を重ねた画像（青=直線 緑=矩形 赤=円 紫=斜線 橙=文字領域と OCR 結果）と report.md / report.json / report.pdf（回答書と同じ体裁。表紙・一覧・図面ごとのオーバーレイと部材表に確認欄）を出力。
  • 前処理: 3×3 近傍によるごま塩ノイズ除去（孤立黒画素の除去・微小白穴の充填）。円（穴）はラン除去の前に生の連結成分から判定（正方形に近い外接矩形・中心が白・16 方向の内外径が一定）し、円の弦として拾われた短いランを除外。
  • 確定した結果（署名 → ファミリ・パラメータ）を学習し、同じ様式・特徴の候補の確信度と初期値に反映。
  • 認識率（合成スキャン、乱数固定、デモ図面 直線 24・矩形 6・穴 10・仕様注記 5、dev/flows/raster_bench.js）: きれいな画像 200 / 300 dpi は直線・矩形・穴 100%、OCR 仕様注記 5/5・長さ 4/4・穴注記 2/3。スキャン相当（ぼかし＋ノイズ 2%）は直線・矩形 100%、穴 70%（200 dpi）／90%（300 dpi）、OCR 仕様注記 0/5（200 dpi）／3/5（300 dpi）。劣化スキャン 150 dpi（ノイズ 4%）は直線 88%・矩形 83%・穴 60%、OCR 0。円の誤検出は 0〜1。日本語注記（仕上げ・長穴・全周・Uボルト・アンカーの 5 語彙）はきれいな画像で 4/5、スキャン相当 300 dpi で 1/5。1.5° 傾けた 300 dpi 画像はデスキュー後に無回転と同じ成績（直線・矩形・穴 100%、OCR 仕様 5/5）。推奨スキャン条件は 300 dpi モノクロ PDF。

5. 計算仕様

5.1 重量

  • 形鋼・板: 断面積（JIS 寸法表または t × 幅）× 長さ × 7.85 g/cm³。穴・長穴は体積を控除。
  • めっき: 表面積 × 付着量（HDZ55 = 550 g/m² ほか仕様別）。電気亜鉛・塗装・SUS は仕様に応じた係数。
  • ボルト類: JIS B 1180 / 1181 / 1256 の質量表（呼び径・長さ）。アンカー・全ねじ・U ボルトも同様。
  • 溶接金属: 隅肉は脚長² / 2 × 長さ × 7.85、突合せは開先断面 × 長さ。

5.2 原価

  • 材料（鋼材単価 × 質量 × 歩留まり係数）、切断（本数・サイズ）、穴（個数・径）、溶接（長さ・脚長）、曲げ、組立、仕上げ（面積 × 単価）、副資材（ボルト類）。単価表は案件ごとに上書き可能。

5.3 見積

  • 工場単価 = C社回答（未回答時は A社基準原価）。A社提示単価 = 工場単価 × (1 + A社マージン%)。販売単価 = A社提示単価 × (1 + B社利益率%)。金額 = 単価 × 数量。消費税 10%。

9. 非機能要件

項目仕様
性能起動 2 秒程度（オフライン版、SSD）。部材 150 体（約 5,000 メッシュ）までを対話的に編集。オンデマンド描画（操作がない間は再描画しない）で CPU・電力を抑制。低性能 GPU では自動で軽量表示（後処理・写真テクスチャ省略）。
保存変更ごとの自動保存（ローカル）、作業スナップショット、案件 JSON の書出し・読込。サーバー型は JSON ストア（日次バックアップ推奨）。
セキュリティ閉域運用可（外部通信なし）。受け渡しリンクは推測不能なトークン。役割ごとのフィールド権限はサーバー側でも検証。監査ログ（作成・編集・受け渡し・確定・差戻し）。HTTPS はリバースプロキシで付与。
可用性サーバー停止時もローカル保存で作業継続。サーバーは静的配信＋軽量 API のため仮想マシン 1 台で十分。
保守性ES Modules による疎結合構成。ファミリはデータ駆動で追加可能。カタログ更新時はサムネイルを CI（GitHub Actions）で自動再生成。
テストPlaywright による画面フロー自動テスト（30 シナリオ以上）、オフライン検証、スクリーンショット比較。

11. 制約事項・今後の拡張

  • 図面認識はベクタデータ（DXF / ベクタ PDF）を前提とする。スキャン画像（ラスタ）は内蔵ベクタ化で形状（直線・矩形・円・斜線）を読むが、仕様注記（文字）は読めないため仕様・長さは要判断になる。必要に応じて外部 OCR と組み合わせる。
  • DWG / JWW / RVT は外部コンバータ（ODA File Converter 等）の HTTP ラッパ経由で読込む。
  • IFC 読込はオフライン版では web-ifc ライブラリの別配置が必要。
  • SSO（AD / Entra ID）、社内 LLM 連携、通知の自動送信（メール / チャット API）は要件に応じて追加する。
  • カタログは日栄インテック 第 1・13・14 章を収録。他章・他社カタログはシート追加で拡張可能。
