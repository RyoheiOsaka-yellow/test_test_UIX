# ANGLEX — Fabrication Intelligence（BIM 型 加工品 3D・見積プラットフォーム）

2D図面・CAD/BIMデータから配管サポート（架台・ブラケット・吊り金具・バンド）を **Revit 流のファミリ → タイプ → インスタンス** で 3D 化し、
穴・長穴・溶接ビード・ボルト・Uボルト・アンカーまで作り込んだ製作レベル（LOD400）のモデルから、重量・集計表・見積・加工指示書を **単一ソース** で生成します。
見積は **A社（見積作成）→ B社（利益上乗せ）→ C社（加工工場）** の多社ワークフローでフィールド単位の権限管理・改訂凍結・監査ログつきで受け渡せます。

## 配布ファイル（v1 / v2）
- `dist/ANGLEX_v1.html` — v1 UI（リボン＋プロジェクトブラウザ＋プロパティの BIM ワークスペース型）。分解図・中央へ・CAD 図面色を含む最新版（`index.html` = v1）
- `dist/ANGLEX_v2.html` — 新 UI（サインイン → モード選択 → 案件管理 / チャット見積 / 5 ステップ 3D 詳細）＋分解図・個別部材化。`dist/ANGLEX.html` は v1 と同じ内容。v2 のソースは `v2.html` + `css/app_v2.css`（`python3 tools/build_single.py v2.html css/app_v2.css dist/ANGLEX_v2.html`）
どちらも単一ファイルで、ブラウザで直接開けます（3D ライブラリと PDF ライブラリは CDN から読み込み）。

## 画面構成（v2 = 元デモの見た目）
1. **サインイン** — デモ認証。会社・役割（A社 設計 / B社 販売 / C社 工場）を選んでサインイン。サーバ運用時は `server/server.js` の認証に切り替わります。
2. **モード選択** — 「かんたん見積（チャット）」と「図面から加工指示（3D）」。「顧客・案件管理」からも入れます。
3. **顧客・案件管理** — 顧客ごとに案件（3D モデル）と見積の改訂・受け渡し状況（A社 → B社 → C社）を一覧。再開（3D）／見積／部材選択／削除。
4. **かんたん見積（チャット）** — 製品 → 配管径 → 仕上げ → 数量 を選ぶだけで、ファミリの既定寸法からモデルを配置し、工場原価の概算と「確認すべき加工指示」（溶接・穴・Uボルト・アンカー）をその場で表示。「3D で加工指示を確定する」で詳細モードへ、「見積書を作成」で A社 → B社 の受け渡しへ。自由入力（例: 125A の門型架台 ベース付 めっき 2台）も解釈します。
5. **3D 詳細モード（5 ステップ）**
   - ① CAD取込: ドロップ／サンプル DXF／サンプルモデル／空のモデル／保存済みを開く
   - ② 読込・分析: 解析ログ、部材認識（3 状態・リスク行列）、配置する部材を選ぶ
   - ③ 部材を選択: 図面ビュー（認識枠クリック）と検出部材リスト
   - ④ 部材ディテール: 3D アセンブリ（配置／加工／編集／表示／書出し／作業 のメニュー、部材・画層＝プロジェクトブラウザ、日本語の加工指示チャット）、仕様 & 加工指示（プロパティ・確認事項）、部材断面図、整合チェック（干渉・ズレ・接合）、分解図（部品表・バルーン・個別部材化）、積算コスト、カタログ照合
   - ⑤ 概算見積: 見積の作成・A社 → B社 → C社 受け渡し・帳票出力（従来の見積ワークフローをそのまま内包）

   URL パラメータ: `?view=3d`（サインインを省略して 3D 詳細モードへ）、`?view=chat`、`?view=projects`、`?handoff=<token>`（受け渡しリンク）、`?quality=0`（軽量描画）。

## v1 UI の 3 機能（分解確認 / 中央へ / CAD 図面色）
- **分解図**（ホーム → 分解・確認 → 分解図）: 選択部材を部品ごとにバラす（スライダー）。溶接は分解中は非表示。番号バルーンが 3D と部品表に対応し、行クリックでその部品だけ表示。「個別部材化」で組立品を単材・板のインスタンスへ。リボンの分解スライダーは、部材を選択していればその部品を、無ければ部材同士をバラします。
- **中央へ**: 3D 上の部材を**クリック（掴む）**すると、その部材が画面中央に来るようにアニメーションで移動（ダブルクリックはその部材へ寄る）（距離は維持）。`C` で選択部材を中央へ、`F` で全体表示。「✋ 手のひら」（`H`）を押すと左ドラッグで画面を掴んで移動でき、右ドラッグが回転になります。
- **CAD 図面色**（表示スタイル）: 図面ビューと同じ暗背景に、役割ごとのフラットカラー（柱=青 / 梁=緑 / ベースプレート=青緑 / ガセット=紫 / 方杖=黄 / 支持金物=橙 / 配管=水色 / Uボルト=橙 / アンカー=赤 / 溶接=橙）＋明るいエッジで表示し、右上に凡例。3D と CAD 図面の照合用です。

## 3D 品質（追加分）
- **MSAA 4x**（WebGL2 のマルチサンプル レンダーターゲット）＋ SMAA、GTAO、ACES
- **環境光プリセット**（表示 → 環境）: スタジオ / 倉庫（工場）/ 工作機械室 / 屋外（Poly Haven CC0 HDRI、リアル表示では背景にも使用）
- **溶接の熱影響色**: ビードのトゥ側に茶→青の焼け色（頂点色）
- 材質の汚れ・粗さムラ（3D ノイズ）、スパングル亜鉛・ヘアライン SUS・ミルスケール黒皮、面取りボルト・螺旋ねじ、板エッジ面取り
- **外部生成（Astra GPT 等）向け**: `docs/ASTRA_BRIEF.md`（parts JSON 契約・品質要件・API）と `docs/sample_parts_MF-1.json`（門型架台 1 体の実データ）

## カタログ ショールーム（選ぶと 3D に現れる）
ホーム → 配置 → 「ショールーム」（v2 は 配置 ▾ メニュー）。Drive の日栄インテック カタログ（151 製品 / 700 SKU、第1章 吊バンド・第13章 アングル・チャンネルブラケット・第14章 特注加工品）を検索・章で絞り込み、製品をクリックするとその場で 3D に現れて格子状に並びます（SKU はプルダウンで選択）。もう一度クリックで消え、「並べ直す」「すべて消去」も可能。展示した部材は通常のインスタンスなので、そのままコンテキストバーで穴・溶接を足したり、見積に含めたりできます。各行には 3D サムネイル（軽量レンダラで順次生成）が付きます。コンテキストバーの「配管へ取付 ▾」で、吊バンド等を他の部材の配管へ向きを合わせて取り付けられます（管径の近い配管を選び、空いている位置へ 150mm 刻みでずらす）。
Drive フォルダでこのアカウントから読めるのは ch13-14 製品シートと ch01 寸法シートの 2 ファイルのみです（他章のシートはフォルダに存在しないか未共有）。

- サムネイルは専用の軽量レンダラで生成し、**IndexedDB に永続化**（`anglex-thumbs`）。2 回目以降はリロード直後から即表示され、未生成分は空き時間に先回り生成します（ソフトウェア描画など遅い環境では先回りを止め、表示中の行だけ生成）。描画仕様を変えたら `js/ui/thumbs.js` の `VER` を上げると旧キャッシュは無効になります。

## 配管へ取付（両方向・口径合わせ）
- **支持金具 → 配管**: 部材バー「配管へ取付（口径も合わせる）▾」。取付先の配管（他部材の参照配管でも、スリーブ・両フランジ管などの実配管でも可）の呼び径に、自分の `pipes`（呼び径リスト）／`od`（適合外径）／`nominal` を**インスタンス上書き**で合わせてから再生成するので、U ボルトの穴ピッチ・配管位置・向きが同時に揃います（同タイプの他の部材には影響しません）。向き合わせは両方の配管が水平ならヨー回転のみ（架台が傾かない）。配管の長さ内で、他部材と干渉しない位置を 150mm 刻みで探します。
- **配管 → 支持金具**: 配管側の部材バー「支持金具をここへ ▾」で近くの支持金具を選ぶと、その金具の口径をこの配管に合わせてここへ呼び寄せます。

- **取付のプレビュー**: メニューの取付先にホバーすると、結果（位置・向き・口径変更後の形）を青い半透明のゴーストで表示し、ラベルに「MF-1 → HB-1 配管 50A / 配管 125A,32A,20A → 125A, 50A, 20A」のように変更内容を出します。クリックで確定、外すと消えます（モデルは変更しません）。

- **ホットスポット**: 支持金具を選ぶと、近くの配管（他部材の参照配管・スリーブなどの実配管）に青い「◎ 呼び径」が出ます。ホバーでゴースト プレビュー、クリックで取付。配管（スリーブ・両フランジ管）を選ぶと支持金具側に橙の「⇣ 記号」が出て、クリックでその金具を配管へ呼び寄せます（メニューを開かずに 3D 上で完結）。
- **等ピッチ配置**: 部材バー「等ピッチ配置 ▾」→ 配管を選び、サポート間隔 P と個数（0 で配管長から自動）を入力すると、先頭はその部材、残りは複製で配管に沿って等間隔に並びます。口径も揃うので、架台の本数・総質量・見積が一度に出ます。

## 業務フロー（図面 → 確認 → 重量 → 見積 → 共有 → 確定）
ホーム → 集計・見積 → **業務フロー**（v2 はクイックバー）。6 段階のステッパーと段階ごとのカードで、「いまどこか」「数字はいくつか」「次に押すボタン」を 1 画面にまとめています。
1. **3D モデル**: インスタンス／タイプ／接合／要判断（推論）件数。ショールーム・カタログ・図面読込へ
2. **人が確認する箇所**: 未処理の確認事項・ズレ・現場溶接・アンカー。未確認があると受け渡し／確定でゲートが掛かる（上書きは監査ログへ）
3. **重量計算・集計**: 総質量と内訳（鋼材 穴控除後／めっき付着／ボルト類／溶接金属）のバー、表面積・溶接長・穴数、算出根拠の一文。重量計算書 PDF / XLSX / CSV、集計表
4. **見積**: 見積番号・Rev・状態・販売価格計（C社は工場原価計）。モデルから見積を作成（再作成は新 Rev）、見積書 PDF、加工指示書 PDF
5. **他社と共有**: A社（3D・数量・仕様・基準原価）→ B社（利益率・販売価格）→ C社（工場単価・納期・受注可否）の担当表示、受け渡しボタン、共有リンク（`?handoff=トークン`。相手は自社の権限で同じ見積を開く）のコピー、受け渡し履歴、差戻し
6. **確定**: A社が確定（以後編集不可、改訂は新 Rev）。確定見積書 PDF
モデルや見積が変わるとパネルは自動で更新されます。

### B社・C社の役割専用ビュー
受け渡しリンク（`?handoff=…`）で開くと、その会社の権限で業務フロー／見積が開き、**見るべき数字と押すボタンだけ**になります（3 段階のステッパー: 受け取り → 入力 → 返す）。
- B社: A社提示単価・利益率（入力）・販売単価・金額。一括「全行に利益率 n%」。合計は販売価格計・税・粗利。→ A社へ返す／C社へ渡す
- C社: 工場単価（入力・既定は A社基準原価）・納期・受注可否・工場メモ。一括「納期 n 日」「工場単価 = 基準原価 × n%」「全行 受注可」。合計は工場原価計・最長納期。未入力の行数を表示し、未入力のまま渡す時は確認。→ A社へ回答
- 全明細・権限表・監査ログは「詳細」に折りたたみ。C社には販売価格、B社には工場原価が出ません（workflow.js の visibleColumns と同じ境界）

### まとめて確認ウィザード
業務フロー ② の「まとめて確認」／確認リストの「まとめて確認（ウィザード）」。未確認を 溶接 → 穴 → アンカー → Uボルト → 吊ボルト → 図面根拠 → リスク要因 の順にカード送りし、**3D がその箇所へ自動で寄ります**（溶接・穴・アンカーは位置、他は部材）。
- ✓ 確認済（Enter）／溶接指示…／穴あけ指示…／部材を確定（推論 → 確定）／スキップ（→）／戻る（←）
- 「残りの溶接 n 件を確認済に」で同種を一括処理。種類チップで絞り込み。進捗バーと処理件数。Esc で閉じる

### 見積の比較ビュー
業務フロー ④ の「⇄ Rev 比較」、見積ワークフローの「⇄ 比較」、B/C 社ビューの「前 Rev と比較」。
- **Rev 間の差分**: 比較元／比較先の Rev を選び、行ごとに 数量・原価・利益率・納期・受注可否（役割で見える列）と単価・金額の変化を ▲増（赤）／▼減（緑）で表示、追加行・削除行も色分け。右端に「誰が・いつ・何を」（監査ログ）と受け渡しメッセージ
- **会社間の金額**: 同じ行の 工場単価 → A社提示 → 販売単価 を横に並べ、段ごとの上乗せ率と粗利を表示（役割で見える列だけ）

### 受け渡しの通知文・回答期限・確定前チェック・ダッシュボード
- **受け渡し**: メッセージと回答期限（既定 B社 3 日 / C社 7 日）を入力すると、相手へ送る通知文（リンク・お願い事項・合計・期限・未入力行）を自動生成してクリップボードへ。「メールで開く」で mailto 起動。業務フロー／見積ワークフローの「通知文」で再表示。
- **期限**: 業務フロー ⑤ と B/C 社ビューに「回答期限（残り n 日 / 超過 n 日）」「未回答 n 日」を表示。
- **確定前チェック**: 確定時に 受注不可・工場単価未回答・受注可否未回答・利益率未入力・要求納期超過（⑥ の「要求納期」入力）の行を一覧にして停止。承知の上で確定する場合は理由を監査ログへ。
- **ダッシュボード**: ホーム「案件一覧」／プロジェクト タブ／v2 の案件一覧。全案件の見積状態・担当会社・合計・未確認件数・期限を並べ、「自分の番」と期限超過を上位に。行クリックで案件を開き業務フローへ。

## 営業所（拠点）の仕分け — 全営業所と工場で 1 つのシステムを共有
20 営業所が 1 ID ずつ使い、工場は 1 ID で全営業所の案件を扱う前提で、**1 つのサーバー・1 つの DB** を共有し、案件・見積を **営業所（branch）で仕分け**ます。
- 拠点マスタ `js/core/branches.js`（本社・東京・大阪・名古屋・福岡・仙台。追加はこの配列へ）。ユーザーは所属営業所を持ち、工場（C社）・販売（B社）は `scope: 'all'` で全営業所。
- 案件は作成時にユーザーの営業所が付き（トップバーの営業所チップをクリックで変更）、見積番号は `Q-TKY-2026-xxxx` のように営業所コードを含みます。通知文にも営業所が入ります。
- A社ユーザーの「開く」「案件一覧（ダッシュボード）」「v2 の案件一覧」は自営業所が既定で、「全営業所を表示」で切替。工場・販売は全営業所を一覧し、営業所チップ（件数・自分の番）で絞り込めます。
- サーバー `/api/projects` も所属営業所で絞ります（`?all=1` で全件）。マスタ（カタログ・単価表・学習データ）は共通。1 部署 1 サーバーの容量・読込はそのままです。

### 営業所・ユーザーの管理画面
ユーザーメニュー「⚙ 営業所・ユーザーの管理」／プロジェクト タブ「営業所・ユーザー」／v2 案件一覧の「⚙ 営業所・ユーザー」（A社のみ）。
- **営業所**: コード（英大文字 2〜6 文字）・名称・略称の追加・変更・削除（案件が残る営業所は削除不可）。CSV 取込（`code,name,short`、既存コードは上書き）、CSV 書出し、取込テンプレート。マスタはローカル（localStorage）またはサーバー `/api/branches` に保存され、起動時に読み込まれます。
- **ユーザー**: 氏名・メール・会社（A/B/C）・所属営業所（A社のみ。「全営業所（本社管理者）」も選択可）。CSV 取込（`name,email,org,branch`、メール一致で上書き。branch に `*` で全営業所）。サーバーは `/api/users/bulk`（初期パスワード anglex）。v2 のサインインの営業所選択はマスタから生成されます。

## 標準単価マスタ（学習）と案件横断の学習
- C社が回答（A社へ受け渡し／確定）すると、行ごとの **工場単価・¥/kg・納期・受注可否** を 部材種別 × 仕様 × 寸法区分（S/M/L/XL）で蓄積します（ローカル: localStorage、サーバー: `/api/prices`）。
- 次回「モデルから見積を作成」すると、同じ仕様（2 件以上）または同じファミリ×寸法区分の **中央値を基準原価の初期値に適用**（元のモデル原価は保持、監査ログに記録）。見積ワークフロー／業務フロー ④ の「学習単価 n 行」から **単価マスタ** を開き、適用状況・乖離・「単価表に戻す」。
- **見直し候補**: 想定（モデル原価）と回答の乖離が 10% 以上・3 件以上のファミリ×寸法区分を一覧し、単価表の見直しを促します。履歴 CSV 書出し。

## 組立確認（干渉・工具スペース・保温・組立順）
- **工具スペース**: 干渉チェックに、ボルト・アンカー・U ボルト・吊ボルトの頭／ナット側に 2.5M+20 mm × 幅 1.6M の空間が取れるかの判定を追加。不足箇所は橙のリングと一覧（クリックで寄る）。
- **保温厚**: 配管を持つファミリに「保温厚」パラメータ。U ボルト径・穴ピッチ・配管高さが保温外径（od + 2t）で決まり、U ボルト名に「保温 30」が付きます。
- **組立順**: 分解図の部品表に「組立順」列（ベース → 柱 → 梁・腕 → ブレース → 配管・U ボルト → ボルト類 → アンカー）。分解パネルの「組立図 PDF」で、分解図＋工程表＋現場作業（現場溶接・アンカー）の現場向け図を出力。

## ラスター図面（スキャン PDF・画像）と認識の学習ループ
- PNG / JPG / BMP / WebP / TIFF と、文字情報のないスキャン PDF を **ブラウザ内でベクタ化**（二値化 → 行・列のラン抽出 → 直線・矩形）し、既存の認識器に通します。縮尺 1:n と dpi を入力（mm/px を決定）。仕様注記は読めないため、仕様・長さは形状からの推定で「要判断」になります。斜線（方杖など）は軸方向の線を除いた残りの連結成分の主軸から、円（穴）は中空で正方形に近い成分から抽出します。二値化のあとに 3×3 近傍のごま塩ノイズ除去を行い、円（穴）はラン除去の前に生の連結成分から判定します（太い小円の上下の弦が短い直線として拾われるのを防ぐため）。
- **認識率（合成スキャンでの実測、乱数固定）**: `node dev/app-shot.mjs out.png dev/flows/raster_bench.js` がデモ DXF（直線 24・矩形 6・穴 10・仕様注記 5）を 150〜300 dpi 相当に画像化（ぼかし・ごま塩ノイズ付き）して計測します。現状: きれいな画像 200 / 300 dpi は直線・矩形・穴 100%・OCR 仕様注記 5/5、スキャン相当（ノイズ 2%）は直線・矩形 100%・穴 70%（200 dpi）／90%（300 dpi）・OCR 仕様注記 0/5（200 dpi）／3/5（300 dpi）、劣化スキャン 150 dpi（ノイズ 4%）は直線 88%・矩形 83%・穴 60%・OCR 0、円の誤検出 0〜1。日本語注記（5 語彙）はきれいな画像で 4/5、1.5° 傾けた画像はデスキュー後に無回転と同成績。数値は回答書・仕様書に転記しています。
- **限定 OCR**（`js/import/ocr.js`）: ベクタ化で残った文字の画を行単位の領域にまとめ、Tesseract.js（WASM）で **部材仕様・穴注記・長さ** だけを読みます。φ→9/o、`[` の脱落などを正規化し、読めた注記を TEXT として認識器へ。注記の長さと外形が一致する矩形に紐付け、OCR 由来は確信度を下げて「寸法注記(OCR)」と表示。初回のみ worker 初期化に数秒。単一ファイル（オフライン）版には worker・コア・英語データを同梱（`vendor/tesseract/`、`tools/build_single.py` の VENDOR_URLS）。
- **日本語 OCR（限定語彙）**: 英数で仕様・穴・長さが読めなかった領域だけを日本語モデル（`vendor/tesseract/jpn.traineddata.gz`、同梱）で読み、仕上げ（溶融亜鉛めっき / HDZ / 電気亜鉛 / SUS）・溶接（▷n 全周 / 隅肉）・長穴 n×m・Uボルト nA・アンカー Mn の語彙に当たる語だけを採用（`JPN_VOCAB`、`normalizeJpn`）。`ocrRegions(..., { jpn: false })` で無効化。
- **線で描かれた矩形の外形認識**: DXF で部材外形が 4 本の LINE で描かれている場合（CAD では一般的）もポリライン同様に外形候補として復元し、仕様注記・長さ・円（穴）を紐づけます（枠・表題欄レイヤは除外）。
- **打合せの予約（カレンダー連携）**: 業務フローの共有カード「📅 打合せを予約」で、件名・日時・参加者（相手会社のユーザーのメールが初期値）・会議ツールを選ぶと、Google カレンダー（予定内で Meet を追加）／Outlook 予定（Teams 会議を自動で付ける）／Teams 会議の直接作成／.ics のいずれかを開きます。本文に受け渡しリンク・合計・議題が入り、打合せは見積に記録されてタイムラインに「📅 打合せ」として出ます（`js/ui/meeting.js`、`WF.addMeeting`、サーバー `/api/estimates/:id/meeting`）。ログイン連携（OAuth）なしで動く「リンク方式」です。Meet URL の自動発行や相手の空き時間の参照は、サーバー版で各社の Google / Microsoft の OAuth を設定したときに追加します（予定）。
- **片側穴からのボルト提案**: 接触する 2 部材のうち片側にだけ穴がある場合（取付板は穴あり・架台は現場穴あけ）、接触面内の穴を相手側へ写して「○○ に穴あけ」付きでボルト接合を提案します。適用時は穴の無い側だけに穴をあけます（`drill`）。
- **サーバー版の学習共有**: 読込統計は `/api/learnstats` に送られ、「学習の状態」は全営業所の統計を API から表示します（認識の学習・単価と利益率の履歴はもともとサーバー共有）。JSON の出し入れはローカル版や移行用に残します。
- **目標未達の通知**: ダッシュボードの KPI「要判断 目標(n%)未達 様式」（クリックで学習の状態へ）と案件一覧ボタンのバッジに目標未達の様式数を含めます。サーバー版は 7 日に 1 回、営業所ごとに目標を超えた図面様式のまとめを A社ユーザーへ送ります（SMTP or outbox、`ANGLEX_REVIEW_TARGET` 既定 20、`POST /api/weekly/run?force=1`）。
- **提案接合の確認ウィザード連携**: 提案で追加した「推論」の接合は、まとめて確認ウィザードの先頭カード「接合（提案）」に出ます。3D はその穴の中心へ寄り、「✓ 接合を確定」「外す」を 1 クリックで。
- **学習データの出し入れ**: 管理画面「学習の状態」の「⤓ 書き出し／⤒ 読み込み」で、認識の学習・単価と利益率の履歴・読込統計を 1 つの JSON にまとめて出し入れします（重複は自動除外）。拠点間の共有やサーバー版への移行に。
- **要判断率の目標管理**: 「学習の状態」に 図面様式（読込の種別）× 営業所 ごとの要判断率と目標ライン（既定 20%、変更可）。達していない様式ほど上に出るので、検証返送をどの様式から優先するかが分かります。
- **穴からボルト接合を提案**: 接触する 2 部材の既存の穴が接触面上で同じ位置（±4 mm）にある箇所を、ボルト接合候補として挙げます（業務フロー ②「ボルト接合の提案」）。適用するとその穴位置にボルトを立て（穴は新たに作らない、ボルト径は穴径から M10/M12/M16）、状態は「推論」で確認ウィザードへ。`suggestBoltJoints`（`js/bim/joints.js`）、ボルト接合の `points` パラメータ。
- **穴位置の 3D 反映**: 図面に円があれば、その位置をそのまま 3D の穴に使います（単材は `holes` DSL の z/s、板は `extraHoles` DSL に実位置、cols/rows は 0）。円が無く注記の穴数だけのときは等ピッチで仮置きし、確認事項に「穴位置は注記の穴数から等ピッチで仮置き → 位置を確認」を出します（`inst.holePos`: drawing / note）。
- **穴注記・アンカー注記の部材紐づけ**: 鋼材仕様が読めなかった行（穴注記「4-φ15 アンカー M12」など）は日本語パスにも回し、注記は最寄りの部材 1 つ（外形からの距離 < 400 mm）に紐付けます。穴数・径は配置時に 3D の穴（`holes` DSL）になり、アンカー・仕上げ・溶接は確認事項に残ります。
- **デスキュー**: 二値化後に黒画素の行投影分散で傾き（±4°）を推定し、0.3° 以上なら元画像を回して二値化し直します（`estimateSkew`、stats.skew に角度）。
- **図面上で修正**: スキャン画像を薄く重ねた図面ビュー（読込結果の「✎ 図面上で修正」、業務フロー ①、図面ビューのツール）で、矩形（部材）→ 仕様・長さ／部材ではない、円（穴）→ 穴径／穴ではない、文字（OCR）→ 読み直し。修正は即再認識（手入力は確信度 0.98）、「部材ではない」「仕様を直した」は署名ごとに学習されます。↶ 元に戻す対応。
- **実スキャン検証キット**（`out/report.pdf` も出力: 回答書と同じ体裁で、表紙・一覧・図面ごとの検出オーバーレイ・部材表に「ご確認」欄つき。返送いただいた正誤を学習と閾値に反映）: `node dev/raster-real.mjs <フォルダ> [--scale 10] [--dpi 300] [--no-ocr] [--demo]` がフォルダ内の PNG/JPG（スキャン PDF は 1 ページ目を dpi で描画）を順にデスキュー＋ベクタ化＋OCR し、`out/<名前>_overlay.png`（青=直線 緑=矩形 赤=円 紫=斜線 橙=文字領域と OCR）と `out/report.md` / `report.json` を出力します。`--demo` でデモ図面のスキャン画像を生成して動作確認できます。
- **学習ループ**: 読込部材を「確定」（まとめて確認ウィザードの「部材を確定」）すると、認識時の署名（仕様 × 長さ区分 × 穴数 × 特徴 × 図面様式）と直した値（ファミリ・仕様・寸法・仕上げ）を記録。同じ署名の確定が 2 件以上あると、次回の候補は確信度 +0.2 と「学習済 n」チップ、直した値が初期値になります（`js/import/learn.js`、サーバー `/api/learn`）。

## 業務フローの磨き込み（次の一手・タイムライン・催促）
- **次の一手バナー**: 業務フロー最上部に「いま何をすべきか」を 1 行と、そのボタンを 1 つだけ表示（部材なし → 図面を読込、スキャン要判断 → 図面上で修正、確認残 → まとめて確認、見積なし → 作成、未受け渡し → C社へ、相手の回答待ち → 期限と催促文、回答済 → 確定）。期限超過は赤、問題なしは緑。B社・C社ビューにも同じバナー。
- **タイムライン**: 共有カードに 作成 → 受け渡し → 差戻し → 確定 を一列で表示（会社色・日付・期限、いまの位置を強調、回答待ちは点線）。
- **催促文**: 期限超過または未回答 3 日以上で、業務フローとダッシュボードに「催促文」ボタン。期限・経過日数・未入力行数・リンクを含む本文をコピーして送付。
- **期限通知の自動化**: 判定（期限超過／期限 1 日以内／未回答 3 日以上）は `js/core/reminders.js` に一本化。クライアントは起動時と 10 分ごとに数え、ダッシュボード ボタンにバッジ（超過は赤）と起動時トースト、ダッシュボードの「期限超過」KPI から通知一覧（種類・経過日数・サーバーの送信記録）。B社・C社ビューの最上部に期限帯。サーバー版は 1 時間ごとに担当会社のユーザー（所属営業所が一致 or scope=all）へメールを自動送信します（`server/mail.js`: 依存なしの SMTP、`SMTP_HOST` / `SMTP_PORT` / `SMTP_USER` / `SMTP_PASS` / `SMTP_FROM` / `SMTP_SECURE=1`、`ANGLEX_PUBLIC_URL` でリンクのホスト名。同じ見積・種類は 24 時間に 1 通。未設定なら `server/data/reminders.log` に本文を残す。`ANGLEX_REMINDERS=0` で停止、`POST /api/reminders/run?force=1` で手動実行）。
- **C社の「前回回答を流用」**: 一括欄のボタンで、自社の過去回答（単価マスタ履歴: 仕様一致 → ファミリ×寸法区分 の順に 2 件以上）の工場単価・納期の中央値を未入力行に入れます。「全行 受注可」と合わせると、同種案件の回答はほぼワンクリックです。
- **B社の「前回の利益率を流用」**: B社が受け渡すと利益率を 顧客 × ファミリ×寸法区分 ごとに履歴へ記録し、次回は一括欄のボタンで未入力行に中央値（同じ顧客・同じ区分 → 同じ区分 → 全体 の順に 2 件以上）を入れます（`recordMarginsFromEstimate` / `learnedMarginFor`）。
- **学習の状態**（管理画面タブ）: 署名ごとの 確定／修正／却下／返送 ○× の件数と「次回の効果」（却下・修正値を初期値・確信度 +0.2・あと n 件で有効）、読込ごとの 候補・要判断・学習が効いた数、要判断率の前半→後半の推移を表示します（`summarizeLearn`、`recordImportStats`）。
- **検証結果の取込**: 検証キットが出力する `out/feedback_template.csv`（図面・ID・認識した仕様/長さ・正誤・正しい仕様/長さ・署名）に記入して、管理画面「検証結果の取込」に貼り付け／ファイル選択 → 学習に反映。○ は正例、× に正しい値があれば「仕様を直した」、× のみは「部材ではない」として署名ごとに学習されます（`recordFeedback`）。
- **B社・C社の「残り n 行」モード**: 自社の番のとき未入力の行を上に並べ、「未入力だけ表示（n）」で未入力行だけに絞れます（行は黄色で強調）。催促を受けてからの入力を短くします。
- **v1 の図面ビュー**: 「2D」ビュー切替で図面（DXF / PDF / スキャン）を表示するように修正（従来は表示されなかった）。

## サムネイルの同梱（初回から即表示）
GitHub Actions（`.github/workflows/anglex-thumbs.yml`）が、カタログ・ジオメトリ・サムネイル描画のファイルが変わった push と手動実行で `node dev/gen-thumbs.mjs` を走らせ、`js/data/thumbs_pre.js` と dist の単一ファイル版を再生成してコミットします（GPU の無いランナーでは SwiftShader によるソフトウェア描画。ローカル GPU で作る場合は `PLAYWRIGHT_MODULE` でモジュール位置を指定できます）。

`node dev/gen-thumbs.mjs` が全製品（既定 SKU）を headless で描画し `js/data/thumbs_pre.js` に書き出します。`thumbs.js` の `STORE_KEY`（描画仕様 VER ＋ 製品数）と一致するときだけ使われ、単一ファイル版にも同梱されるので、IndexedDB が空の初回起動でもショールームが即表示されます。SKU を切り替えた分はその場で生成して IndexedDB に積みます。

## 3D 操作の不具合修正（v2）
- **3D ペインの高さ**: v2 の 3D ステージが固定 600px だったため、ノート PC（高さ 720px）ではキャンバスの下 1/3 が画面外に出て、そこにある部材は掴めず、移動ギズモも反応しませんでした。高さを `max(380px, 100vh − 320px)` にしてウィンドウに収めました。
- **分解スライダー**: v2 のディテールカードの分解スライダーが選択部材ではなくモデル全体を分解していたのを修正（選択部材だけを部品ごとに分解）。
- **ラベルの上からのドラッグ**: 旗（確認事項）・バルーン・ホットスポットの上でドラッグを始めると画面が動かなかったため、4px 以上動いたらドラッグとして canvas へ転送（クリックは抑止）。`dev/flows/view3d.js` で パン／手のひら／回転／中央へ／分解／ギズモ移動 を v1・v2 で自動確認します。

## v3 シミュレータ（どの部品も押せる・数字が生きている・分解できる・壊せる）
機械を 1 枚の HTML で「部品ごとのボタン・ライブゲージ・分解・壊す」まで作る手法（Claude の machine / anatomy 系スキル）を、ANGLEX の配管サポート BIM に応用したモードです。リボン「シミュレータ」（v1）、ツールストリップ「⚙ シミュレータ」（v2）、業務フロー ① から開きます。
- **部品ボタン**: インスタンスごとに 形鋼／板／ボルト／ナット／座金／Uボルト／溶接／アンカー／吊りボルト／配管 のボタン。押すと 3D でその部品が光って寄り、**役割** と **確認点**（締付トルク・脚長・埋込深さ…）と、その部品の照査結果が出ます。3D 上の部品にカーソルを合わせても同じ情報が出ます。
- **ライブゲージ**: 総質量、配管荷重（鋼管＋満水 × 標準支持間隔）、曲げ応力比、たわみ、ボルトせん断、アンカー引抜、溶接せん断。すべて `js/bim/solver.js` の「小さな正直なモデル」（単純支持はり、P/A と細長比の簡易低減、ボルトは等分、溶接はのど厚 × 有効長）で計算し、「計算方法と仮定」に式と **省略したもの**（動荷重・地震・熱伸び・偏心・接合剛性）を明記します。設計計算書の代わりではありません。
- **荷重倍率と「限界まで」**: 配管荷重を ×0.5〜×8 に変えるとゲージが追従。「限界まで」で最初に許容を超える部品と倍率を探して 3D で光らせます。「応力の色」で部材を照査比で着色。
- **モード**: 分解（選択部材）、X 線（ghost）、ラベル（全部品名）、スロー組立（組立順 assemblySeq に従って部品が順に現れる）。
- **ストーリー再生**: 組立（6 秒）→ 開く（X 線＋ラベル）→ 分解 → 荷重を上げて限界（約 25 秒）。「● 動画」で canvas 録画（WebM）を保存でき、提案・社内説明に使えます。
- **スケールバー**: 画面上の 1 m を表示。

## 3D の基本操作（回す・掴んで中央へ）
- **左ドラッグ＝空間をぐるぐる回す**（既定）。右ドラッグで画面全体を掴んで動かす。
- **部材をクリック（掴む）＝その部材が画面中央へ**寄り（距離は維持、アニメーション）、以後はその部材を中心に回せます。コンテキストバーは中央に出ます。Shift+クリックは複数選択（中央へは寄らない）。選択中の部材の上から左ドラッグすると部材そのものが動きます（直接ドラッグ）。
- **部材をダブルクリック＝その部材へ寄る**（画面の 6 割を占める距離まで、向きは維持）。**空白をダブルクリック＝全体を中央へ**戻る。F で全体表示。
- **掴んだ部材のピル**: 中央へ寄せた部材は 3D の上中央に「◎ MF-2 を中心に回しています」と出続け、回している間も何を中心にしているかが分かる。「全体へ」ボタンか Esc で全体中心に戻す。部材が削除されると自動で消える
- **回転中心の十字**: 回している間だけ、回転の中心（目標点）に小さな十字が出る。部材を掴んだ直後は十字がその部材に乗る
- **見どころ表示（寄ったとき）**: 部材をダブルクリックで寄ると、その部材の穴・溶接・アンカー・確認フラグだけを残して他の部材のラベルとレベル線を一時的に隠し、ピルに「穴 4 / 溶接線 2 / 確認 1」と数を出す（`spotCounts`）。全体へ戻すと元どおり
- **視点の履歴**: 中央へ・寄る・全体へ・ミニマップ移動の直前の視点を積み、Alt+← / Alt+→（ピルの ‹ ›）で戻る／進む（最大 40）
- **自動回り込み**: 寄った状態で 3 秒操作がないと、その部材を中心にゆっくり自転（OrbitControls の autoRotate、約 70 秒で 1 周）。何か触ると止まり、3 秒後に再開。ピルの「⟳ 自動」で入／切（`localStorage` に保存、`prefers-reduced-motion` では無効）
- **切替**: 「✋ 掴む」⇄「⟳ 回す」（v1 リボン・v2 ツールストリップ、H キー）で左ドラッグの役割を入れ替え、設定は保存。Space 長押しで一時的に入替。

## 掴みの慣性と境界・ミニマップ・タッチ
- **慣性と境界**: 掴んで離すと OrbitControls の減衰で少し滑ります。掴んでモデルが画面外に出たとき（中心が視野の 1.05 倍の外）は、操作が止まって 0.5 秒後に自動で画面内へ戻します（`keepInView`。目標点をモデル中心側へ寄せる 360 ms のアニメーション）。
- **ミニマップ**（`js/ui/minimap.js`）: 3D の右下に上から見た部材の外形と、いま見ている範囲（画面 4 隅をモデル中心高さの水平面に落とした足跡）を枠で表示。クリック／ドラッグで目標点を移動（高さは維持）。選択部材は青。「▾ 地図」で畳めます（設定は保存）。2D 表示とシミュレータ中は隠れます。
- **タッチ**: 掴むモードでは 1 本指で掴む、2 本指で回す／ズーム（回すモードでは 1 本指で回す、2 本指で掴む／ズーム）。部材を **長押し（450 ms）** で選んでそのまま掴み、指を動かすと 5 mm 刻みで移動。ダブルタップで中央へ。

## 3D の掴みやすさ（直接ドラッグ・コンパクトモード・操作ガイド）
- **部材を直接ドラッグ**: 選択中の部材を左ボタンで掴んでそのまま水平面上を動かせます（5 mm スナップ、Shift で主軸ロック、複数選択はまとめて移動）。4 px 動くまでは通常のクリック扱い。矢印ギズモ（G）も従来どおり。A社のみ、分解表示中・単部品表示中は無効。
- **コンパクトモード（v2）**: ウィンドウ高 700 px 未満では 3D カードを先頭・全幅にし、他のカードは見出しだけ（クリックで開閉）。3D の高さは `max(340px, 100vh − 220px)`。
- **操作ガイド**: 初回起動時（部材があるとき）と「?」→「操作ガイドを再表示」で、回る／掴んで動かす／中央へ／部材を動かす／分解 を短い CSS アニメーションで案内します（`js/ui/guide.js`、`prefers-reduced-motion` では静止）。

## 操作性（滑らかな UX）
- ホイールは**カーソル位置を中心にズーム**、フィット／アイソメ切替／中央へ はカメラをイージング移動（操作で即中断。`prefers-reduced-motion` では無効）
- 選択部材は**青いエッジのアウトライン**（隠れている側は薄く透過）＋ ホバーで **記号・タイプ名・触れている部品** の吹き出し
- **Esc** は メニュー → ダイアログ → 部材バー → パネル → 手のひら解除 → 選択解除 の順に一段ずつ閉じる。入力欄にフォーカスがあっても効く
- **矢印キー / PageUp・Down** で選択部材を 5mm（Shift で 50mm）移動。**?** でショートカット一覧
- 部材バー・ダイアログ・ショールーム・メニューに出現アニメーション、トーストは同文連打をまとめて最大 4 件まで、ショールーム検索は 1 フレームにまとめて再描画

## 3D 内で触って足す（コンテキストバー）
部材をクリック → 選択。**もう一度クリックで部品（柱・梁・ベース・Uボルト…）を選択**し、その横にコンテキストバーが出ます。
- **＋ 同じ部材を隣に**（同タイプを X 方向に隣接配置）／**＋ 穴**（その部品に穴あけ指示）／**＋ 溶接**（端部溶接・脚長・現場/工場）／**＋ 足す ▾**（ファミリ固有: ベースプレート追加・アンカー +1・配管（Uボルト）追加・ベースをボルト止め・端部溶接・接合定義）
- **寸法**: 触った部品に関係する寸法だけを ±5mm のステッパーで微調整（[T] はタイプ全体、[I] はこの 1 体に反映）
- **移動 X / Y / Z / 自由**: 軸ロック＋5mm 刻みのギズモ。移動後、10mm 以内の隙間は自動で密着（空間を自由に動かしすぎない設計）
- **単独表示 / 中央へ / 分解図 / ズレ n → 補正**
- 材質: ワールド座標ベースの汚れ・粗さムラ（プロシージャル 3D ノイズ）を HDZ / EZ / 黒皮 / 塗装 / ボルトに追加（軽量描画時は無効）
- CAD 図面色: ファミリ側の既定役割（門型架台の柱＝柱 等）を持たせ、分解図 PDF のバルーンは引出線付きで重なりを自動回避。v1⇄v2 切替は選択部材・ステップ・表示スタイルも引き継ぎ

## 追加分（v1/v2 共通エンジン）
- **CAD 図面色の役割上書き**: プロパティ「配置」の「CAD 図面色（役割）」で、自動判定（名称から）を 柱 / 梁 / ベース / ガセット / 方杖 / 支持金物 / 配管 / バンド / 板 / 鋼材 に上書き。インスタンスに保存され、CAD 色スタイルに即時反映。

## 分解図・分解（個別部材化）
部材ディテールの「分解図」カードで、分解スライダー（3D を部品ごとに引き離す）、番号バルーン（3D 上に部品番号、部品表と対応）、部品表（仕様・長さ・質量・加工）を表示します。「分解（個別部材化）」は門型架台などの組立品を、単材・板・管のインスタンスへ変換します（位置・向き・穴・仕上げ・材質を保持。ボルト類と溶接は対象外となるので「接合」で再定義してください。Ctrl+Z で戻せます）。

## 3状態モデル（リスク行列 Case B）
読込・推論した部材は **確定／推論／要判断** を保持します。境界は `js/bim/risk.js` のリスク行列で決まります:
`risk = (1 − 信頼度) × 加工種別コスト（穴2・ピッチ3・溶接4・アンカー4…）× 管径係数（〜50A:1.0 / 〜100A:1.25 / 〜200A:1.6 / 大口径:2.0）`、
risk ≤ 0.6 で確定、≤ 1.8 で推論、それ以上は要判断。読込ウィザードに risk 値と主因を表示します。

## 溶接記号（JIS Z 3021）と現場／工場
溶接 parts は `site`（現場）フラグと記号文字（▷隅肉 / ○全周 / ▶現場 / V突合せ）を持ち、3D ラベル・図面ビュー・溶接集計（工場/現場別）・原価（現場は単価×1.8）に反映されます。指示文「MF-1 と MF-2 を 現場 隅肉溶接 6」、接合ダイアログの「施工」、門型架台の「ベース取付=現場溶接」で指定できます。

## 確認アラート・溶接／穴あけ指示・ズレ補正・作業保存
- **確認事項（人が必ず確認する箇所）**: `js/bim/review.js` が各インスタンスの部品リストから、溶接（脚長・全周/片側・現場/工場）、穴（径・ピッチ・端あき・面）、アンカー、Uボルト、吊ボルト、仕上げ、図面根拠（推論/要判断）、リスク主因をチェックリスト化します。図面から読み込んだ部材（`source='import'`）は全項目が「未確認」で始まり、手で配置した部材は溶接のみ未確認です。
- **3D 旗（⚑）**: 未確認の溶接・穴（面→板ローカル→配置の変換で穴位置に立つ）・アンカー・Uボルト・吊ボルトは位置に、その他は部材上部に件数でまとめて表示。クリックで選択。ステータスバーの「要確認 n」から全体の確認リストを開けます（表示タブの「確認フラグ」で ON/OFF）。
- **溶接指示 / 穴あけ指示**: プロパティの確認事項から実行。単材・鋼板は `welds` DSL（`start:6 site; end:6` = 始端/終端 全周隅肉、site=現場）と `holes` DSL に、組立ファミリは `weldSize`・`baseFix`（現場溶接）・`extraHoles`（`<部品番号>|<面>:z s d [slotNNz]` 行区切り）に書き込まれ、3D・溶接集計・重量・見積に同期します。指示した項目は「指示済」になり、確認後に「確認済」へ。確認状態・メモ・担当はインスタンスの `review` に保存されます。
- **ズレ補正**（ホーム → ズレ補正）: 部材間の隙間（0.5〜60mm）、レベル不一致（±150mm）、穴の板外／5mm 単位外、配管位置の部材外、接触の無い接合を検出し、「補正」で自動修正（寄せて密着 / レベルへスナップ / 端あき 1.5d へクランプ / 5mm へ丸め / 配管位置をクランプ）。Y 方向の隙間はレベルに載っていない側を動かし、両方レベル上なら下側の部材を伸ばして密着（単材 配置軸Y の L、門型架台・ポールの H）。「すべて補正」は同じ部材に影響する補正を 1 回 1 件に制限。
- **受け渡しゲート**: A社が見積を B社へ受け渡す・確定するとき、未確認の確認事項が残っていれば止めます。「確認リストを開く」で処理するか、理由を付けて「承知の上で進める」と、理由が監査ログ（受け渡し／確定の note）に残ります。見積ヘッダには「未確認 n」チップを表示。
- **作業保存**（Ctrl+Shift+S）: 名前とメモ付きでモデル全体のスナップショットをプロジェクトに保存（最大 30 件、ローカル保存／サーバ保存の両方）。「作業履歴」から復元（復元前の状態も自動保存）・削除。通常の自動保存は従来どおり常時働きます。

## 帳票の書出し（CSV / XLSX / PDF）
- 見積: 見積書 PDF（日本語フォント埋込・直接ダウンロード）、XLSX（数式入り: 採用原価・提示単価・販売単価・小計・税）、CSV、加工指示書 PDF（部材ごとの3Dスナップ・穴・溶接・ボルト）
- 重量: 重量計算書 PDF / XLSX（単位質量×長さ、穴控除、めっき付着、合計の数式）/ CSV、集計表 XLSX
- モデル: プロジェクト JSON、glTF/GLB、DXF 加工図（板展開＋穴）、IFC 風 JSON、**SimReady パッケージ**（USDA + USDZ（64byte整列）+ GLB + PBR テクスチャ PNG + 簡略コリジョン（部品 OBB の Cube プロキシ、メッシュは convexHull 近似）+ metadata.json（BOM・質量・重心・bbox・意味クラス）+ サムネイルの ZIP）

## 3D 品質（SimReady 指向）
PBR（アルベド / 法線 / 粗さ / AO）マテリアル、HDRI 環境光（Poly Haven CC0）、GTAO 接触陰影 + SMAA、面取り付き六角ボルト・ナット（30° 円錐面取り）、LOD400 の実螺旋ねじ山、板エッジ・穴の面取り、根元R、溶接ビードの波紋。CDN が使えない環境ではプロシージャル材質と RoomEnvironment にフォールバックします。

## Netlify 運用
リポジトリ直下の `netlify.toml` が `anglex/` を公開します（サーバ不要）。DWG/JWW の自動変換はサーバモード専用のため、Netlify 運用では DXF / IFC / PDF / glTF を直接読み込んでください。
