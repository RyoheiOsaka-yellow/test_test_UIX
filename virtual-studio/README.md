# Virtual Studio — 仮想撮影スタジオ / 撮影指示書ジェネレーター

オンライン上の「仮想撮影スタジオ」で、動画・スチール・屋外/ドローン撮影の
**技法・機材・ライティング・カット割り**を設計し、**撮影指示書 (PDF/画像) と
Seedance 等の AI 動画生成向け詳細プロンプト**を自動生成するプロトタイプです。

ビルド不要・依存ライブラリなし。`index.html` をブラウザで開くだけで動作します。

```bash
# ローカルで開く
open virtual-studio/index.html          # macOS
# または任意の静的サーバー
cd virtual-studio && python3 -m http.server 8080
```

## できること (プロトタイプ v0.2)

### 1. 仮想スタジオ (俯瞰配置図・白基調UI)
- ライト (キー/フィル/バック/リム/トップ/背景/HMI/プラクティカル)、レフ板、
  フラッグ、ディフューザー、ドローン、太陽などを**ドラッグで自由配置**
- **特効機材**: 送風機 / スモーク / レインマシン / スノーマシン /
  紙吹雪キャノン / 爆発ポイント / スパークマシン
- **車両・ロジスティクス**: 機材車 / 発電車 / ロケバス / クレーン車 /
  モニター(ビデオビレッジ) / 音声(ブームポジション)
- グリッドは 1マス = 50cm。各機材に高さ・出力・色温度・モディファイア
  (ソフトボックス、グリッド、パラボリック、ライトテント等25種) を設定可能

### 2. 撮影技法プリセットライブラリ (約50種)
選ぶだけで機材が自動配置され、想定カットが生成されます。

- **人物ライティング (基本)**: 三点照明 / ループ / レンブラント / バタフライ /
  スプリット / ブロード / ショート
- **人物ライティング (応用)**: クラムシェル / 逆光シルエット / ハイキー /
  ローキー(ノワール) / アンダーライト(ホラー) / インタビュー(窓光風)
- **シーン再現 (動画)**: デイ窓光 / ムーンライト / キャンドル / モニター光 /
  尋問トップ単灯 / ステージライブ / ネオンデュオトーン / 回想ハレーション /
  グリーンバック(クロマキー)
- **商品・テーブル動画**: ターンテーブル / 料理真俯瞰 / 手元・開封動画
- **人物スチール**: 白ホリ全身ファッション / カラージェルポートレート /
  ハードライト単灯 / サンドイッチリム
- **商品撮影**: グラデーション / 透過光 / シズル(雫・スプラッシュ) / EC白抜き /
  コスメ / 香水ジェル背景 / ビール / フード半逆光 / フラットレイ / 自動車
- **特殊素材**: ガラスのブライトフィールド/ダークフィールド / ジュエリー /
  金属テント / ガジェットのスペキュラー制御
- **屋外撮影**: ゴールデンアワー / ブルーアワー / 真昼シルク / 日中逆光+HMI /
  曇天 / ナイトネオン / ロケ基地レイアウト(機材車・ベース設営)
- **ドローン基本**: オービット / リビール / 真俯瞰 / 並走 / プルバック / ドローニー
- **ドローン応用**: FPV追跡 / ダイブ / スパイラル上昇 / ローパス / 空撮ドリーズーム
- **特殊効果 (SFX)**: 雨(レインメイキング) / 風(ストームウィンド) / 雪 /
  爆発(パイロ) / 火花(スパークシャワー) / 紙吹雪 / スモーク光条

### 3. 想定カットの自動生成 + かんたん解説
配置したライトの**方位・出力・色温度・モディファイア**を解析し、
カットサイズ・アングルを反映した想定フレームを自動描画します。
併せて**「この配置だとこう写る」を誰でも分かる言葉で自動解説**します
(光の方向 → 影の出方 / 柔らかい・硬い / 輪郭光 / 背景の明るさ / 色味 / カメラの効果)。
「**雫 / 光沢 / 湯気 / ヘイズ / 風 / 雨 / 雪 / 爆発 / 火花 / 紙吹雪 / シルエット**」等の
演出・特効オプションはプレビューと指示書・プロンプトすべてに反映されます。

### 4. カメラリグの詳細設定 (v0.3)
カメラ・レンズ・支持機材を1本単位/1cm単位で微調整できます。

- **ボディ**: シネマカメラ / ミラーレス / ハイスピード / ENG / アクションカム /
  **ウェアラブルPOV(耳掛けCCD)** / FPV / 360° / スマホ / 中判(スチール)
- **レンズ**: 焦点距離スライダー (8〜800mm連続可変) / 絞りF値スライダー /
  フォーカス距離 / ND (段数選択) / フィルター (PL・ブラックミスト・プロミスト・
  クロス・ストリーク・接写) の組み合わせ
- **支持機材 (17種)**: 三脚 / ハイハット / **脚立** / イントレ / スライダー(平行移動レール) /
  ドリー / **クレーン・ジブ** (アーム長可変) / テクノクレーン / **ステディカム(平衡機)** /
  ジンバル / ショルダー / 手持ち / 車載 / ケーブルカム / スノリカム / ウェアラブル / ドローン搭載
  - カメラワークを選ぶと適切な支持機材が自動選択 (手動変更可)
  - 俯瞰図のカメラ下にレール・クレーンアーム・三脚などを可視化
- **ライト詳細**: 照射角スライダー (10〜120°、俯瞰図の光錐に反映) /
  スタンド種別 (Cスタンド・ブームアーム・グリッド吊り等)
- 設定はすべて **指示書 (カメラ・レンズ表 / 支持機材・フィルター表 / 機材表の照射角・スタンド列)**
  と **AIプロンプト** (焦点距離mm・f値・フォーカス距離・フィルター表現・リグの質感) に反映

### 5. 演出・環境・段取りの詳細設定 (v0.4)
- **アスペクト比7種**: 16:9 / 縦9:16(リール・TikTok) / シネスコ2.39:1 / 4:3 / 1:1 /
  3:2 / 縦4:5 — プレビュー・絵コンテが実際にその形に変わる
- **ルック/グレーディング8種**: ナチュラル / ティール&オレンジ / フィルム暖色 /
  ブリーチバイパス / モノクロ / パステル / ビビッド / シネパンク — プレビューに色が乗る
- **カメラワーク精密化**: 移動速度5段階 / 開始→終了カットサイズ (「BSからCUへ寄る」) /
  ドリー・スライダーのレール軌道 (直線・カーブ・円弧) を俯瞰図に描画
- **被写体**: 演技・動き14種 (歩く/走る/振り返る/注ぐ/回転/浮遊/走行 等) +
  自由記述メモ (「20代女性・白ワンピース」等 → プロンプトに反映)
- **環境**: 天候8種 / 時間帯8種 (ゴールデンアワー・ブルーアワー等)
- **収録・段取り**: 音声収録方式5種 / 想定テイク数 / 準備時間 (指示書の香盤に集計)
- **電源プラン自動計算**: 各灯の消費電力(W)から合計電力・100V15A回路数・
  発電機推奨容量(kVA)を指示書に自動記載

### 6. カット割り (ストーリーボード) + トランジション (v0.5)

**カット間トランジション10種** (カット/ディゾルブ/フェード/ホワイトアウト/
マッチカット/ウィップパン/ワイプ/ジャンプカット/モーフ/スピードランプ) を
カットごとに指定でき、ストーリーボード上のカット間チップ・指示書・
プロンプトに反映されます (各トランジションに撮影時の注意付き)。

### 8. 撮影技法mdインポータ (v0.5)

## IntentParser — 自由文からカット自動設計 (v1.0)

スタジオ上部の入力バーにシーンを言葉で書くと、カット一式を自動設計します。

> 例: 「夜の豪雨。主人公が路地を走り、後方で大きな爆発。35mm映画の緊張感。」
> → ベース技法: 爆発バック / 雨+レインマシン自動配置 / 夜 / 人物・走る /
> 35mm / シネマティックルック / Class C 安全警告

- 天候・時間帯・被写体・演技・特効・レンズmm・カメラワーク・アスペクト比 (縦動画等)・
  尺・ムードをルールベースで解釈し、最適なベース技法プリセットに上書き適用
- **すべての推定を「解釈した前提」チップで明示** (根拠の語句付き、CLAUDE.md §8) —
  違う場合はインスペクターでそのまま修正可能
- **「3カットに展開」** で 引き(状況説明 COV-001) → メイン → 寄り(感情 COV-002) の
  カバレッジ構成へワンタップ展開

## 3Dビュー / DMX / 複文設計 (v1.2)

- **3Dテクニカルビュー** (Phase 2): スタジオツールバーの「3D」で切替。
  依存ライブラリなしの自前パースペクティブ投影で、床グリッド・被写体・
  ライトの光錐 (照射角反映)・カメラの視野角フラスタム (焦点距離/アスペクト比反映)・
  **被写界深度の合焦面と前後深度面** (F値/フォーカス距離から自動計算)・ドローン高度を
  立体表示。ドラッグ回転/ホイールズーム。ライト/ダークテーマ連動
- **DMXキューシート** (Phase 4先行): ヘッダーのフェーダーアイコンから印刷/PDF出力。
  全カットの灯体をマージした固定パッチ表 (Universe 1 / 10ch刻み / 汎用8chモード) と、
  カット毎のキュー (Dim/CCT/ジェルRGB近似値、トランジション連動のFade秒) を自動生成
- **IntentParser複文対応**: 「まず引きで…。次にディゾルブで寄り…。最後に…」のような
  順序マーカー付きの文章から**複数カットを一括生成**。天候・時間帯・被写体は全体文から
  継承し、文中のトランジション語 (ディゾルブ等) はカット間の繋ぎに自動設定

## 追加機能の統合・作り込み (v4.5)

v4.1〜v4.4 で足した層 (演出・台本コンテ・ロケ地・写真) を既存の仕組みと
噛み合わせる回。実機監査で見つかった7つの統合漏れを潰しました。

- **台本ページの編集が Undo できるように**: ビート追加・セリフ・ロケ地の変更が
  ⌘Zで戻せるようになりました (連続入力は500ms以内なら1ステップに合体)
- **Escape で前面のページから閉じる**: ロケ地ライブラリ → 台本 → ワークフロー…
  の順に1枚ずつ閉じます。新しいページもフォーカストラップの対象に
- **香盤表がロケ地単位でまとまる**: ロケ地が変わる箇所に**見出し行と移動時間
  (30分)** が入り、座標・当日の日の出/ゴールデンアワー/日の入・撮影許可の注意も
  その行に出ます。撮影スケジュールはロケ地で読むもの、という実務に合わせました
- **ロケ地とスタジオの食い違いを診断**: 屋内スタジオなのに太陽が置かれている /
  指定日時の太陽高度が夜なのに時間帯設定が昼系 (逆も) を指摘
- **ツアーとヘルプが新機能を案内** (9ステップに)、**サンプルプロジェクトが
  ロケ地とビートまで入った状態**に — 初回から台本・ロケ地・太陽計算が見えます

## ロケ地写真からの空気感の取り込み (v4.4)

- **写真の光と色を測ってプロンプトへ**: ロケ地写真を割り当てると、
  ブラウザ内だけで**色温度 (暖色/寒色)・コントラストの硬さ・明るさ・彩度**を測定し、
  日本語タグで確認しつつ `LOCATION LIGHT (from photo):` として英語で渡します
  (例: `warm golden light, moderate contrast, saturated colour palette`)。
  画像はどこにも送信されません
- **時間帯・天候・ルックの推定**: 測定値から推定し、**ボタンを押したときだけ**
  カットに反映 (暖色+高コントラスト→ゴールデンアワー、寒色+柔らかい光→曇天、
  低彩度→モノクロルック)。勝手に上書きはしません
- **プロンプトに使う/使わない**のトグル、指示書に写真サムネイルと測定結果、
  canonical JSON にも `photo_traits` (英語記述と実測値) を記録
- 写真は参照素材として保存されるため、プロジェクト保存・バックアップZIPにも乗ります

## ロケ地 — 地域ライブラリ・座標・太陽計算 (v4.3)

演出の一部として「どこで起きるか」を設計できるようにしました。
**「パリの街」では出力が定まりません。** 場所が場所らしく見えるのは建築・素材・
看板の言語・植生・路面・人の気配の積み重ねなので、その要素を土地ごとに持ちます。

- **ロケ地ライブラリ (23種)**: 日本 / アジア / ヨーロッパ / 北米 / 中南米 /
  中東・アフリカ / オセアニア・極地 / スタジオ の8地域。東京の裏路地・京都の
  町家通り・香港の高密度住宅街・パリのオスマン街路・アメリカ西部の砂漠ハイウェイ・
  モロッコのメディナ・アイスランドの溶岩台地… 各ロケ地が
  **建築 / 素材 / 看板・文字 / 植生 / 路面 / 人の気配 / 空** の英語記述と、
  **光の傾向**・**撮影許可の注意**を持つ
- **プロンプト化**: `LOCATION:` ブロックに要素別で出力し、看板の言語から
  **その土地では出てはいけないもの**を `LOCATION NEGATIVE:` に自動生成
  (例: 東京の裏路地 → `no Latin/English shop signage`)
- **Google Maps 連携**: 地図の埋め込みはしません (このアプリは外部通信ゼロ設計で、
  公開ページ側もCSPで外部ホストを遮断するため)。代わりに**MapsのURLを貼ると
  座標を抽出**し (place の !3d!4d 形式・@lat,lng 形式・生の緯度経度に対応)、
  **地図/ストリートビューを開くリンク**を生成します
- **太陽の計算 (通信不要)**: 座標と撮影日時から**太陽の方位・高度**を計算し、
  カメラ方位と合わせて**逆光/順光/サイド**を判定。**日の出・ゴールデンアワー・
  日の入**も算出 (東京・夏至で日の出04:26/日の入19:02/南中77.8°と実測に一致)。
  白夜・極夜も判定
- **スタジオとの連動**: 「スタジオの太陽に反映」で、計算した方位・高度から
  **俯瞰図の太陽アイテムを自動配置** (高度に応じて色温度2800〜5600Kと出力も設定)
- 撮影指示書に**ロケ地セクション** (座標・地図URL・当日の太陽・光の傾向・許可メモ)、
  canonical JSON にも `location` として記録

## 台本・絵コンテページ — 演出と撮影の分業 (v4.2)

**どう撮るか (カメラ・レンズ・照明・機材) はスタジオ**、
**何が起きるか (演出・動き・セリフ) は台本・コンテ**、と役割を分けました。
動くのは人だけではないため、**登場要素**は人物 / 車両 / 動物 / 群衆 / 商品・物 /
カメラ自身から選べます。

- **台本・コンテページ** (ヘッダーの「台本・コンテ」): 全カットを縦に並べ、
  各カットで **絵コンテ枠 (プレビュー)・カット名・尺・セリフ/テロップ・狙い・
  登場要素・ビート (動き)・動きの質・作り方・診断** をその場で編集。
  カメラ設定は**読み取り専用の要約**として表示され、スタジオ側の変更に追従する
  (台本側からカメラは編集できない = 分業を構造で担保)
- **登場要素ごとのビート**: 「4.0s 車両(赤いセダン): 右から進入して停まる」
  「5.0s 人物: 降りて振り返る」のように、**誰が/何が**動くかを行単位で書ける。
  プロンプトには `cast:` と `BEATS:` として渡る
- **連動**: ビート合計と尺のズレをその場で表示 (「尺に合わせる」で再フィット)、
  カメラワークとカメラ連動の矛盾を診断、絵コンテ枠クリックでスタジオ側の
  選択カットも切り替わる
- **絵コンテ書き出しに動きとセリフ**: 各コマに時間つきのビートと
  「セリフ」が入り、画・動き・セリフが揃った本来のコンテとして印刷できる

## 人の動き (演技演出) レイヤーとプロンプト診断 (v4.1)

カメラ・照明・機材の設計はそのままに、**人の動きを設計する独立レイヤー**を
追加しました。使わなければプロンプトも書き出しも従来どおり (完全に非破壊)、
使うと**既存のカメラ設計と噛み合わせて診断**します。

- **ビート (時間軸の動き)**: 「いつ・何をする・どこを見る・カメラは連動するか」を
  秒単位で並べる。**合計がカットの尺と一致しているか**を常時チェックし、
  ズレたら指摘。「尺に合わせる」で比率を保ったまま再フィット。
  一本撮りの配分 (引き→寄り→展開→収束) など**配分テンプレを尺に比例で流し込み**
- **動きの質**: 「◯◯という名前の動き」ではなく **速さ・雑さ・向き先** と
  演技の温度 (一人でやっている / 見せている / 観察されている) で指定
- **人数と接触**: 接触の強さ (近接→触れる→受け渡し→抱擁) と人数から
  **作り方3通り** (全部AI / 見本を渡す / 先に撮ってから変える) を自動推奨。
  複数人の相互作用は開発元が安定性の課題として挙げている領域なので
  「先に撮る」に倒し、**「先に撮っても解決しない5ケース」**をチェックすると警告
- **カメラとの連動**: ビートごとに「体に連動 / 先回り / 連動しない」を指定でき、
  カメラワークが「フィックス」なのに体連動を指定していれば⛔で指摘
- **プロンプト診断 (右パネル)**: 書いてはいけない5項目を横断チェック —
  ①形容詞の積み上げ ②動きの「名前」 ③身体部位の分解 ④参照画像が持つ情報の重複
  ⑤矛盾する指示 (+ビート合計と尺のズレ、接触カットを寄りで撮る等の噛み合わせ)
- 出力: プロンプトに `PERFORMANCE` / `BEATS` / `PRESERVE / CHANGE` ブロックを付与
  (文章系の方言では1段落に整形)、撮影指示書に**ビート表と診断結果**、
  canonical JSON に `performance` (IN/OUT秒つき) を記録して往復。
  カット割りサムネには「演」バッジ

## モード由来バッジ・容量表記の是正 (v3.4)

## 制作ワークフロー — 1素材→2設計→3生成→4レビュー→1へ (v1.9)

想定フロー「①ChatGPT等で画像+ストーリー作成 → ②本プロダクトでカット設計 →
③Seedance等で生成 → ④レビューして次のストーリーへ」を1画面のループにした。
ヘッダーの「ワークフロー」ボタンから。

- **ステップ1 素材の受け入れ**: ストーリーのテキスト入力と、参照画像
  (キャラクター/シーンイメージ) のドラッグ&ドロップ取り込み (768pxに縮小して
  ブラウザ内保存・外部送信なし・最大12枚)。画像は任意のカットに
  「first frame 参照」として割り当てられる
- **ストーリーからカット設計**: 文/行ごとにIntentParserを通して自動でカット群を
  生成 (既存カットは置き換え/追記を選択)。以降はスタジオ本体で精緻化
- **ステップ3 書き出しセンター**: カット毎にSeedanceプロンプト+パラメータ
  (ratio/duration/1080p/camerafixed)+参照画像サムネイルを一覧表示。
  コピーで「プロンプト済」に自動遷移。連結シーケンス (1プロンプト) も出力
- **API連携 (実験的)**: SeedanceやOpenAIのAPIはブラウザから直接呼べないため
  (CORS/キー保護)、自前の**中継サーバーURL**を設定すると「APIへ送信」で
  プロンプト+パラメータ+first frame画像をJSON POSTできる
- **ステップ4 レビューボード**: カット毎に 設計中→プロンプト済→生成済み→採用 を
  管理 (カット割りサムネにも状態ドット表示)。「このストーリーを完了して次へ」で
  現プロジェクトを保存→新規プロジェクトでステップ1に戻る (ループ)
- ストーリー/参照画像/進行状態はプロジェクト保存・自動保存に含まれる

## EditDecision/EDL・メディアからのDNA抽出 (v1.8)

- **編集セクション (V6 EditDecision本格化)**: インスペクタに「編集」欄を追加。
  採用テイク・素材イン点 (プリロール秒)・音の繋ぎ (ストレート / Jカット /
  Lカット + ズレ秒) をカット毎に指定できる
- **編集リスト出力**: ヘッダーの新ボタンから、採用テイク・素材/レコード
  IN-OUTタイムコード (fps設定準拠 Non-Drop)・繋ぎ・音の編集点をまとめた表と、
  **CMX3600形式EDL** (.edlダウンロード付き) を出力。ディゾルブ系はD+フレーム数、

## CineOS ナレッジ移植 (v0.9)

リポジトリ直下の `cineos/` に **CineOS 開発パッケージ** (開発憲章 CLAUDE.md /
マスターナレッジ / 機材マスター / 推論ルール / スキーマ) を正典として取り込み、
以下を本アプリへ移植済み:

- **機材データベース (131機種シード)** → `js/equipment_db.js`。
  「capability first, SKU second」原則で、配置した機材・カメラ・レンズ・サポートに
  実機材候補 (例: ARRI ALEXA 35 / Aputure 等+同等能力機) をインスペクターと指示書に提示
- **FeasibilityEngine / SafetyFlagger** → `js/engine.js`。
  advanced_rules.json のルールを移植し、リアルタイムで警告
  (例: ハイスピードfpsの必要光量段数 LGT-002 / 雨・雪は逆光必須 SFX-001 /
  黒光沢は写り込み光源の形で設計 LGT-003 / 破壊系はマルチカム COV-003)。
  **特効の安全区分 A/B/C** を表示し、Class C (爆発・火工) は
  「有資格特効技師専任・演出計画のみ」を明示 (危険な構造情報は一切出力しない)
- **プロンプトコンパイラ §10 準拠**: Seedance プロンプトを
  FORMAT → SUBJECT & ACTION → ENVIRONMENT → CAMERA → LENS → MOVE →
  FOCUS → FRAME RATE → LIGHTING → PRACTICAL FX → COLOR → NEGATIVE の
  構造化ブロックで出力

**`js/data.js` がプロダクトの知識の中核**です。プリセットは
「配置座標 + 高さ + 出力 + 色温度 + モディファイア」の構造化データで、
UI・プレビュー・指示書・プロンプトのすべてがここから生成されます。

### ライティング解析の仕組み
カメラ→被写体の軸を基準に各灯の相対方位角を計算し、
- 正面〜斜め前 (|θ| ≤ 115°) → キー/フィルとして陰影の方向・コントラストに反映
- 半逆光〜真後ろ (|θ| > 115°) → リムライトとして輪郭光に反映
- 色温度の加重平均 → 画とプロンプトのカラーパレットに反映

という形で、配置図とカットイメージ・プロンプトが常に同期します。

## 撮影技法 md の取り込みについて

技法ナレッジを md で共有いただく前提で、`docs/knowledge/FORMAT.md` に
取り込み用のフロントマター形式を定義してあります。この形式に沿った md は
`data.js` のプリセットへ機械的に変換できます (サンプル: `docs/knowledge/sample-rembrandt.md`)。
