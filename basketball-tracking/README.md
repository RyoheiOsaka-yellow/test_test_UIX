# 🏀 バスケットボール トラッキング分析 プロトタイプ

試合映像から**全選手とボールをトラッキング**し、戦術の振り返り・次戦への
活用を目的とした詳細データを自動抽出するプロトタイプです。

2本のパイプラインを含みます:

| | 入力 | 検出 | 用途 |
|---|---|---|---|
| `run_pipeline.py` | シミュレータ生成のダミー映像 | 色ベース | パイプライン全体の検証・イベント推定の精度評価(正解データ付き) |
| `run_real_pipeline.py` | **実試合映像** (mp4等) | YOLOv8 + ユニフォーム色分類 | 実映像での選手トラッキング・フィジカル分析 |

さらに `build_cockpit.py` で、トラッキング結果を**プロトタイプ画面
(コックピット UI)** として1枚の自己完結 HTML に固めます:
トラッキング重畳映像と俯瞰コートビュー(選手ドット・軌跡)が再生時刻で同期し、
同じ画面のタブでライブ速度・選手スタッツ・ヒートマップ・サマリーを確認できます。

```bash
python build_cockpit.py --data-dir output_real --video small_annotated.mp4 \
    --ruleset nfhs --label "Hazen vs Lake Region" --out cockpit.html
```

## 実行方法

```bash
pip install -r requirements.txt

# 1) ダミー映像 (シミュレーション) 版: 正解付きでエンドツーエンド検証
python run_pipeline.py --duration 60 --fps 25 --seed 42 --out output

# 2) 実映像版: 試合映像 + コート基準点キャリブレーションを指定
python run_real_pipeline.py \
    --video game.mp4 --calib calib.json \
    --start 0 --duration 90 --imgsz 960 --out output_real
```

### 実映像版のキャリブレーション (calib.json)

映像の基準フレーム上でコートの既知点(センターサークル中心、ハーフライン×サイドライン、
FTサークル中心、レーン角など)を4点以上指定します:

```json
{
  "ref_frame": 0,
  "ruleset": "nfhs",                      // "fiba" (28x15m) or "nfhs" (米国高校 84x50ft)
  "static_masks": [[0, 860, 320, 1080]],  // スコアバグ等の固定オーバーレイ領域
  "points": [
    {"court": [12.80, 0.0],  "img": [783, 387]},
    {"court": [12.80, 7.62], "img": [738, 568]},
    ...
  ]
}
```

カメラがパン・ズームする映像でも、毎フレーム基準フレームへ SIFT 特徴
マッチング(絶対アンカー、ドリフトなし)を行い、失敗フレームのみ LK
オプティカルフローのフレーム間連結でつなぐため、
**1フレーム分のキャリブレーションだけで全編をコート座標に変換**できます。
固定カメラなら `--static-camera` で補償をスキップできます。

出力(`output/`):

| ファイル | 内容 |
|---|---|
| `raw.mp4` | 生成されたダミー試合映像(入力に相当) |
| `annotated.mp4` | トラッキング結果を重畳した映像(ID・軌跡・保持者・ボール) |
| `report.html` | 戦術振り返りレポート(ヒートマップ/パスネットワーク/シュートチャート等) |
| `tracks.csv` | 毎フレームの選手コート座標 [m]・速度(トラックID別) |
| `ball.csv` | 毎フレームのボールコート座標 [m] |
| `player_stats.csv` | 選手別集計(距離・速度ゾーン・スプリント・タッチ・パス・シュート) |
| `events_detected.json` | トラッキングから推定したイベント(パス/TO/シュート/保持区間) |
| `events_ground_truth.json` | シミュレータの正解イベント(精度評価用) |
| `evaluation.json` | 真値との突合による精度指標 |

## パイプライン構成

```
シミュレーション ──► ダミー映像 raw.mp4          ┌ 真値ログ (評価専用)
      │                    │                     │
      ▼                    ▼                     ▼
 [1] 生成          [2] 検出 + トラッキング   [5] 精度評価
                    (色検出 → カルマン+       (RMSE / ID一貫性 /
                     ハンガリアン対応付け)      イベントP/R)
                           │
                    [3] ホモグラフィで
                        コート座標 [m] へ
                           │
                    [4] 分析・イベント推定
                           │
                    [6] レポート / 注釈映像 / CSV
```

- **検出** (`src/bball_tracker/detection.py`) — ダミー映像用の色ベース検出器。
  `Detection` のリストを返すインターフェースに合わせれば YOLOv8 等へ差し替え可能。
- **トラッキング** (`tracking.py`) — SORT系。等速カルマンフィルタ + ハンガリアン法。
  同色選手の重なり(ブロブ結合)は未観測許容で乗り切り、ID を維持する。
- **キャリブレーション** (`calibration.py`) — コート基準点4点からホモモグラフィを推定し
  ピクセル → コート実座標 [m] に変換。実映像ではコート4隅などを指定する。
- **分析** (`analytics.py`) — トラッキング結果のみから算出(真値は不使用):
  - フィジカル: 走行距離、平均/最高速度、速度ゾーン別距離(ウォーク/ジョグ/ラン/スプリント)、
    スプリント回数、加速回数
  - ボール保持: 近接+ヒステリシス+ボール連動性による保持者推定と保持区間
  - イベント: パス、ターンオーバー(シュート起因の攻守交代は除外)、
    シュート(リング接近 + 進行方向 + 速度不連続の3条件)
- **評価** (`evaluate.py`) — シミュレータ真値と突合し、位置RMSE・検出カバレッジ・
  ID一貫性・イベント適合率/再現率を算出してレポートに表示。

## 現状の精度(60秒・2シード)

| 指標 | 値 |
|---|---|
| 選手位置 RMSE | 0.13–0.17 m |
| ID 一貫性 | 93–96 % |
| ボール検出カバレッジ | 100 % |
| パス検出 | 適合率 0.91–1.00 / 再現率 0.50–0.71 |
| シュート検出 | 適合率 0.80–1.00 / 再現率 0.67 |

短時間(0.3秒未満)の保持を挟む速いパス回しの取りこぼしが主な課題。
改善候補: ボール軌跡の折れ点検出によるパス推定、保持判定の学習ベース化。

## 実映像パイプラインの構成 (`run_real_pipeline.py`)

```
実映像 ──► [pass1] YOLO選手検出 + 胴体色抽出 + カメラ運動推定 (LKフロー+RANSAC)
                │
           チーム色クラスタリング (k-means, 審判・観客は除外)
                │
           コート内フィルタ → コート座標トラッキング (カルマン+ハンガリアン)
                │
           フィジカル分析 → report.html / tracks.csv / player_stats.csv
                │
           [pass2] 注釈付き映像 (コートワイヤーフレーム重畳 = キャリブレーション検証)
```

- 接地点 (bbox 下辺中央) をホモグラフィで床平面に投影して実座標化する。
- モジュール: `real_detection.py` (YOLO+チーム分類) / `camera_motion.py` (運動補償) /
  `analytics.py`・`report.py`・`tracking.py` はダミー版と共通。

## 実映像版の現状の制約 (プロトタイプ)

- **ボール検出は未実装**: COCO 学習済みモデルでは小さく動きの速いボールを安定検出
  できないため、パス・シュート・ポゼッション推定は実映像版では省略。
  バスケ専用データセットでファインチューンした検出器を差し込むのが次のステップ
  (ダミー版のイベント推定ロジックがそのまま使える)。
- **トラックIDの分断**: カメラ見切れ・長いオクルージョンで同一選手が複数トラックに
  分かれる。背番号 OCR / 外見 ReID の追加で実名に統合するのが次のステップ。
- 走行距離・速度はホモグラフィ精度に依存(基準点の再投影誤差 ~0.4m 程度)。

## 開発メモ

- ダミー映像にはガウスノイズを付与し、mp4 圧縮を経由して検出するため、
  検出・トラッキングは「きれいな座標」ではなく現実的な観測誤差の下で動作する。
- ダミー版パイプラインは真値を一切参照しない(真値は評価とスコア表示のみに使用)。
- 実映像でのサンプルとして Wikimedia Commons の高校試合映像
  (CC ライセンス) で動作確認済み。
