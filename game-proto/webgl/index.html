仕組み

ロボットは 96×72 の RGB-D センサを持つ。部屋は箱の集合なので、観測はレイキャストで正確に求まる（色・距離・インスタンス ID。ID が SAM マスクの代わり）。一定距離動くと観測をキーフレームとして保存し、まだ地図にない画素から 3D Gaussian を生成する。

最適化は各キーフレームについて全 Gaussian を投影し、次の規則で不透明度と色を更新する。これは CPU 版の色・深度 L1 損失と同じ意味を、勾配ではなく直接の規則にしたもの。

  • 観測面より手前にある Gaussian → その光線は何も無かったはずなので不透明度を下げる（空間を削る）
  • 観測面と一致する Gaussian → 不透明度を上げ、色を観測に寄せる
  • 観測面より奥 → 遮蔽されていて情報がないので触らない

静的マップはすべてのキーフレームを永久に信じる。椅子が動いた後、昔のキーフレームが旧位置の椅子を支え続け、同時に新位置の椅子を「そこは床だった」と削り続ける。結果、旧位置に幽霊が残り、新位置の椅子は薄いままになる。

GaME はキーフレームを足すたびに 2 つの検査を行う。

  1. 追加検出 — 観測が地図より手前に面を見つけたインスタンスを新しい幾何とみなし、その 3D 点を共可視キーフレームに再投影する。昔そこを素通しで見ていた画素にマスクを立て、大きく矛盾するフレームは丸ごと無視する。
  2. 削除検出 — 観測が「空」と言う場所にあり色も合わない Gaussian を候補にし、それだけを描画して 2D で塊になることを確認してから刈り込む。その Gaussian を支持していた昔の画素にもマスクを立てる。

マスクされた画素は上の最適化から外れるので、古い記憶が地図を引き戻さない。これは本家 GaME の detect_additions / detect_removals / occlusion_masks / ignored_frames と同じ構造で、閾値も configs/aria/room0.yaml の値を部屋の大きさに合わせて縮めたもの。描画は WebGL2 で等方 Gaussian を深度順に並べて合成している（CPU 版が等方正則化を掛けているのに合わせた）。
