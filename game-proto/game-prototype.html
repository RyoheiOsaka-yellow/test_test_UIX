何が起きているか

ロボットは視野内の各方向について「どこに何色の面があるか」を観測する（RGB-D の 2 次元版）。一定距離動くたびに観測をキーフレームとして保存し、地図（Gaussian の集まり）を最適化する。最適化では、キーフレームが「面があった」場所の点を強め、「何もなかった」区間の点を弱める。

静的マップは古いキーフレームを正しい制約として使い続ける。椅子が動いた後も、昔のキーフレームが旧位置に椅子を描き直し、新位置の椅子を「そこは空だった」と消しにかかる。結果、旧位置に半透明の幽霊が残り、新位置の椅子は薄くちらつく。

GaMEは新しいキーフレームを追加するたびに 2 つの検査を行う。

  1. 追加検出 — 観測が地図より手前に面を見つけたら新しい幾何とみなし、それを昔のキーフレームに再投影する。昔そこを「空」と見ていた観測にマスクを付け、大きく矛盾するフレームは丸ごと無視する。
  2. 削除検出 — 観測が「空」と言う場所に地図の点があり、色も合わなければ古い記憶として刈り込む。その点を支持していた昔の観測にもマスクを付ける。

マスクされた観測は最適化から外れるので、古い記憶が地図を引き戻さない。右の「キーフレーム」欄でオレンジの区間がそのマスク。これは 本家 GaME の detect_additions / detect_removals / occlusion_masks / ignored_frames の 2 次元版で、閾値の考え方も同じにしてある。

何を作ったか

本家の実装は CUDA ラスタライザ（diff-gaussian-rasterization / FlashSplat）、faiss-gpu、SAM マスク付きの RGB-D データセット（Flat / Aria）を前提にしていて、GPU のない環境では動かない。そこで src/entities/game.py のアルゴリズムを読み取り、次の 3 つを差し替えて同じ制御フローと閾値で回せるようにした。

本家プロトタイプ役割
FlashSplat CUDA ラスタライザgameproto/splat.pyPyTorch CPU の微分可能 3DGS レンダラ。色・深度・alpha・可視性・投影座標を返し、削除検出が使う used_mask（一部の Gaussian だけを描く）に対応
Flat / Aria + SAM マスクgameproto/scene.py床・壁・箱からなる合成ルームをレイキャストして RGB-D を生成。インスタンスマスクが SAM マスクの代わり。物体を run の間で動かせる
src/entities/game.pygameproto/game.py追加検出 → 共可視キーフレームへのオクルージョン伝播、削除検出 → 矛盾 Gaussian の刈り込みと伝播、オクルージョンマスク付き最適化、ignored_frames。change_detection=False で静的マップのベースラインになる

GaME が各キーフレームで行うこと

1. 追加検出
観測深度がレンダリング深度より手前のマスクを「新しい幾何」と判定し、その領域を共可視キーフレームに再投影。古いフレームの該当領域をオクルージョンマスクに入れ、大きく重なるフレームは無視リストへ
2. シードと短い最適化
マップが空・遠すぎる・色が合わない画素から Gaussian を生成し、そのフレームだけで数十反復
3. 削除検出
観測面より手前にあり、かつ色も合わない Gaussian を候補にし、2D で領域を成すか確認。共可視フレームで候補と一致する領域をオクルージョンマスクに加え、候補を刈り込む

最後に、無視されていないキーフレームからランダムに選んで L1（色・深度）+ 等方性正則化で最適化する。オクルージョンマスクの画素は損失から外れるので、古い観測がマップを引き戻さない。

実験設定

  • run 1 — 椅子が左（A）にある部屋を、カメラが左から右へ 7 フレームでスイープ。
  • 変化 — カメラが見ていない間に椅子を右（B）へ移動。
  • run 2 — 同じ軌道でもう一度スイープ。評価は run 2 の 7 視点、正解は変化後の部屋。

解像度 80×60、各キーフレームで 25 反復（単一フレーム）+ 60 反復（サンプリング）。先頭フレームのみ 120 反復。CPU 4 コアで静的マップが約 19 分、GaME が約 9 分。static と game はコードが同一で、違いは変更検出の on/off だけ。run 1 直後の評価は両者とも 32.68 dB / 0.0116 m で完全に一致する。

追加実験: キーフレームを丸ごと捨てない

本家は古い観測を含むキーフレームを ignored_frames で最適化から丸ごと外す。上の観察を受けて、フレームは捨てずにオクルージョンマスクで画素単位に除外するだけの variant（--ignore-policy mask）を追加して比べた。

ブラウザで操作できる GaME Playground（2 次元版）でも同じ 2 ポリシーを切り替えて比較できる。自動シナリオでは一致率が本家どおり 92%、マスクのみ 91% と同等で、マスクのみは 33 フレームを 1 つも捨てなかった（静的マップは 85%、幽霊 14 個）。

観察と本家への示唆

  • マスクの粒度がアルゴリズムの挙動を支配する。本家のいくつかのルールはマスク単位で判断する。SAM が大きな面を細かく過分割することを暗黙に前提にしており、粗いマスクでは除外が過剰になる。実データでも SAM の設定（points per side など）が結果を左右するはず。
  • 古いキーフレームはフレーム単位でかなり積極的に捨てられる。椅子の移動後、run 1 の全キーフレームが ignored_frames に入った。きっかけは 2 つで、旧位置を見ていたフレームは椅子マスクがオクルージョンで 100% 覆われ（occlusion_ignore_threshold = 0.2 に対して）、新位置を床として見ていたフレームは再投影の cover_score が 0.2 を超えた。数値上は困らないが、論文が掲げる「情報を最大限保持する」観点では、フレームごと捨てるのではなくマスク単位で除外し続ける設計に緩める余地がある。
  • 誤検知はごく少ない。run 2 の最終フレームで 4 個の Gaussian が誤って削除され、run 2 のキーフレームにも小さなオクルージョンマスクが付いた。物体の輪郭画素の深度不一致が原因で、本家の 5×5 モルフォロジーが効く解像度なら抑えられる見込み。
両系統は run 1 直後に完全に同じ状態（32.68 dB、旧位置に 229 個）から出発し、run 2 で差が開く。差分は変更検出の有無だけなので、改善はアルゴリズムの効果として切り分けられている。

未移植・簡略化した点

  • 色損失は L1 のみ（DSSIM 項なし）。球面調和は 0 次（RGB 直値）。
  • 最終の refinement（densify / opacity reset）は未移植。増分マッピングのループのみ。
  • 本家のスケール依存定数（再投影の 1.0 m スラック、追加検出の 2.0 m ギャップ、5×5 カーネル）は部屋が 5 m 四方なので縮小して設定。
  • 姿勢は既知（本家も現状は identity tracking）。

次の一手（効果が大きい順）

  1. マスク単位の除外を実データで検証する。合成環境では「フレームを捨てない」variant が同等以上だった（上の追加実験）。Aria / Flat で同じ比較を行えば本家への改善提案の根拠になる。
  2. 実データに接続する。Aria の HF データセットを取得し、本家のローダを CPU 版に流用して 1 シーンだけ低解像度で走らせる。合成環境との挙動差が見える。
  3. ブラウザ版インタラクティブデモ。この Python 実装を土台に、椅子をドラッグしてマップ更新を目で追える WebGL 版を作る。
