# LiDAR × BIM 都市高速 点群シミュレーション

実在の都市高速ジャンクション（OpenStreetMap の実線形）を **LiDAR 風の点群** として合成し、
**BIM / Revit 的な表現**（IFC 分類された構造要素、レベル、通り芯、断面ボックス、4D 施工順序、
Scan-to-BIM 偏差ヒートマップ、Revit 風プロパティ）を重ねて見るブラウザ 3D シミュレーションです。

- 対象地: 首都高速 **箱崎JCT**（6号向島線・7号小松川線・9号深川線・C1）、**大橋JCT**（3号渋谷線・C2）
- 技術: Three.js（WebGL2）＋ 自作 GLSL 点群シェーダ（法線サーフェル）＋ Eye-Dome Lighting、Web Worker で点群合成
- 実測データ: LAS 1.0–1.4 / LAZ（laz-perf）の読み込み、k-NN PCA 法線推定（250 万点超はグリッド PCA）、LAS 書き出し、Scan-to-BIM 自動抽出
- 点数: 標準 約 600 万点（密度 0.4）、最高 約 1,500 万点（密度 1.0）
- ビルド不要。静的ファイルのみ（Three.js は CDN の importmap）

## 起動

```bash
cd pointcloud-highway
python3 -m http.server 8080      # または npx serve .
# http://localhost:8080/ を開く
```

`file://` では Worker / fetch が動かないため、必ず HTTP で配信してください。

## 構成

```
pointcloud-highway/
├── index.html            UI（左: 表示/レイヤー/4D/カメラ、右: Revit 風プロパティ、左下: 凡例）
├── data/
│   ├── hakozaki.json     OSM 由来の道路線形（高さ推定済み）・建物・水面・公園
│   └── ohashi.json
├── tools/
│   ├── sites.json        対象地の中心座標・bbox・レイヤー高さ・走行ルート
│   └── build_data.mjs    OSM XML → data/<site>.json 変換（高さソルバ内蔵）
└── src/
    ├── geom.js           Catmull-Rom 再サンプル、フレーム付きパス、ポリゴン、ラスタマスク
    ├── structure.js      ★ パラメトリック構造モデル（床版・主桁・壁高欄・橋脚・横梁・基礎・照明柱・門型標識柱・建物）
    ├── synth.js          ★ LiDAR 点群合成（反射強度・分類・偏差・要素 ID を各点に付与）
    ├── synth.worker.js   Worker ラッパ
    ├── bim.js            構造モデル → BIM メッシュ（面 + エッジ、要素 ID → 面範囲）
    ├── shaders.js        点群シェーダ（6 着色モード・選択強調・分類マスク・クリッピング）、BIM 面/線シェーダ
    ├── edl.js            Eye-Dome Lighting ポストプロセス
    ├── colormaps.js      viridis / magma / inferno / plasma / turbo / 偏差 / 分類 LUT
    ├── annotations.js    レベル（▽ Deck L2 +11.200）、通り芯バブル（P-012）、断面ボックス
    ├── camera.js         走行ルート連結、ランプ走行 / フライオーバー / ビュー遷移
    ├── measure.js        2 点計測（Revit 風寸法線、mm 表示）
    ├── las.js            LAS/LAZ 読み込み・法線推定（k-NN / グリッド PCA）・LAS 書き出し
    ├── fit.js            RANSAC 平面・円・直線（最小二乗で精密化）
    ├── crs.js            LAS の CRS 読み取り、EPSG 辞書（平面直角座標系・UTM）、横メルカトル順逆変換
    ├── scan2bim.js       点群 → 床版（壁高欄ペア／占有ラスタ）・橋脚・建物の自動抽出、再フィット、偏差計算
    ├── lod.js            セル分割 + 入れ子サブサンプルの LOD 描画
    └── main.js           アプリ本体
```

`structure.js` が **点群と BIM の両方の唯一の真実源** です。点群は各構造要素の表面からサンプリングされ、
各点が要素 ID を持つため、「点群をクリック → BIM 要素を選択」「要素ごとの点数・偏差・被覆率」が成立します。

## データパイプライン（実在線形）

```bash
node tools/build_data.mjs hakozaki            # OSM map API から bbox を取得して変換
node tools/build_data.mjs hakozaki map.xml    # 取得済み XML から変換
```

1. OSM の `highway=motorway|motorway_link|...` を抽出（トンネルは除外）
2. 18 m 以下に細分化し、`layer` / `bridge` タグから目標高さ（layer × 5.6 m）を設定
3. **高さソルバ**: 一般道ノードを 0 m に固定し、縦断勾配 5.5 % 以下の制約を反復投影。
   本線は重く、ランプは軽く動くため、ランプが高低差を吸収して自然なアプローチになる
4. 建物は `height` / `building:levels` があればそれを、無ければ面積に応じた推定高さ

> 高さは OSM の layer からの推定であり実測ではありません。実測点群（LAS/LAZ）や
> 道路台帳・橋梁台帳の縦断データに差し替えれば、そのまま実スキャンの可視化基盤になります。

## サーフェル描画（ソリッドな面）

全点が法線を持ちます（合成時は解析的に、実測データはグリッド PCA で推定）。シェーダは各点を
**公称サンプル間隔を覆う大きさの楕円**として描き、楕円は法線の画面投影方向に |n·view| だけ
縮みます。近づくほど面が閉じ、遠景は細かいまま。法線による陰影（0–100 %）と EDL を重ねて立体感を出します。

## 実測データ（LAS / LAZ）

- 「LAS / LAZ を開く」またはドラッグ＆ドロップ。LAZ は laz-perf（WebAssembly）をブラウザ内で使います
- 読み込み後は点群のみのモード（BIM・4D は非表示）。分類・強度・RGB・標高・偏差の各モードと計測・断面ボックスが使えます
- ASPRS 分類は本ビューアの分類に対応付け（2 地盤, 3–5 植生, 6 建物, 9 水面, 11 路面, 17 橋床版, 7/18 ノイズ）
- 1,600 万点を超えるファイルは等間隔に間引き
- 「LAS で書き出す」: 表示中の点群（合成でも実測でも）を LAS 1.2 / PF2 に。配色 RGB 付きなので CloudCompare や ReCap でそのまま同じ見た目
- 実測点群に BIM を重ねるには、`structure.js` と同じ構造モデル（線形＋断面）を実測座標系で与えれば、選択・偏差・4D がそのまま動きます（次のステップ）

## Scan-to-BIM 自動化（点群だけから構造モデルを作る）

実測データ（または LAS に書き出した合成点群）に対し「点群から構造モデルを自動生成」を押すと、
`src/scan2bim.js` が Worker で次を行います。

1. **壁高欄ペアからの床版抽出**（分類に壁高欄がある場合）: 壁高欄点を 2 m 高さ帯ごとに 1 m ラスタ化 → 細線化 →
   折れ線。4–22 m 離れて平行・同高さの 2 本を**相互に**最良の相手として組にし、間に舗装点があるものだけを床版とする。
   隣接する高架が同じ高さで並ぶ箇所（占有ラスタでは 1 つの塊になる）を分離できる
2. **占有ラスタからの床版抽出**（フォールバック／補完）: 床版候補点を高さ帯ごとにラスタ化 → クロージング → 細線化 →
   折れ線追跡 → 幅の変化で分割 → 方向整合で連結。幅と横位置は横断ヒストグラムの舗装範囲で較正し、
   横断方向の空隙や内側の壁高欄線で分離
3. **中心線の再フィット**: 横位置は**区画線**（外側実線の 90 パーセンタイル）を基準にする（壁高欄の孕みが線形に吸収されない）。
   高さは 10 m ビンごとの RANSAC 平面（車両を除外）で計測し、設計縦断は前後 ±80 m の計測高さに対する
   **ロバスト 2 次フィット**（IRLS、Cauchy 重み 20 mm）。縦断曲線は放物線なので再現され、40 m 程度の局所沈下は
   設計から外れて検出される（`e.settled`）
4. **橋脚**: 鉛直クラスタ → 下部 1/3・上部 1/3 それぞれに RANSAC 円（または面の中央値から矩形中心）を当てはめ、
   位置・半径・天端の傾きを推定。円が下部点の 70 % 以上を RMS 25 mm 以内で説明すれば円形、そうでなければ矩形
5. **対応付けと偏差**: 床版＝設計縦断からの鉛直偏差、壁高欄＝設計位置（区画線基準）からの横偏差（天端・フェンスは中立）、
   主桁＝下面／側面、橋脚＝当てはめ断面からの距離。符号付き mm を点属性に格納

### 答え合わせ（合成点群 470 万点を LAS 経由で再読み込み、Node で実行）

| 項目 | 結果 |
| --- | --- |
| 処理時間 | 約 12 秒（法線推定を除く） |
| 橋脚 位置誤差（中央値） | 40 mm（RANSAC 円が当たったものは 1–4 mm） |
| 橋脚 半径誤差（中央値） | 1 mm |
| 橋脚 傾き検出（真値 68 mm） | 検出 14 / 見逃し 9 / 誤検出 26（矩形断面の面欠損で誤差が出る） |
| 壁高欄の局所孕み（32 mm） | 32 箇所中 26 箇所で平均 \|偏差\| > 15 mm |
| 床版の局所沈下（−42 mm, 44 m） | 12 箇所中 3 箇所（未抽出区間に多い） |
| 床版点の対応付け率 | 45 %（抽出できた床版上では点偏差 ±17 mm） |
| 床版延長 | 11.2 km / 真値 17.8 km |

まだ弱い点: 同じ高さで隣接する複数の床版が壁高欄ペアでも分離できないケース、短い床版（< 50 m）の設計縦断、
面が一部しか見えない矩形橋脚の中心推定。実データでは点密度・遮蔽が異なるため、しきい値は `scan2bim.js` 冒頭の
定数で調整してください。

## 座標系（CRS）

- LAS の VLR（GeoTIFF キー 34735 / WKT 2112）から EPSG を読み取り、平面直角座標系 I–XIX（JGD2011 / JGD2000）、
  UTM 51–54N（JGD2011 / JGD2000 / WGS84）を認識。横メルカトル順逆変換（Krüger 級数）で原点やクリック点の経緯度を表示
- CRS 情報が無いファイルは座標値から候補を提示し、系を手動指定できる
- 合成サイト（箱崎・大橋）は第IX系（EPSG:6677）として扱い、OSM 中心座標から投影した原点を持つ
- LAS 書き出しは GeoKey VLR 付き（CloudCompare / QGIS / ReCap で位置が合う）。X=東距, Y=北距 の格納順を前提

## LOD（大規模点群）

`src/lod.js`: 地上セル（範囲の 1/24、最小 20 m）に分け、各セル内を乱数ランクで 1/64・1/16・1/4・全点の
入れ子部分集合に並べ替え。毎フレーム、視錐台内のセルについて「公称点間隔が画面で約 1 px になる割合」を
求め、描画予算（既定 800 万点）に収まるようスケールして `drawRange` を設定。スプラット径は間引き率に
応じて拡大するので、遠景でも面が抜けません。属性配列は 1 組のまま（セルは `subarray` ビュー）なので
要素 ID・分類・偏差はそのまま使えます。

## 点群合成（LiDAR らしさの作り方）

| 対象 | 再現している特徴 |
| --- | --- |
| 舗装 | 低反射（I≈0.1）、車線の轍で僅かに暗い帯、区画線は高反射（I≈0.9）で破線パターン |
| 壁高欄 | 両面＋天端。天端を高反射にして参考画像の「黄色く光る縁」を再現 |
| 主桁・橋脚・横梁 | 箱桁の側面/下面、円柱/小判形橋脚、横梁。基礎は地中なので **点群なし**（BIM のみ） |
| 建物 | 床スラブ帯・方立（2.6–4.6 m モジュール）・ガラス（疎）・基壇・店舗看板帯・バルコニー（低層住宅系）・屋上パラペット・屋上設備／階段室／高置水槽・内部床スラブの透け |
| 街路 | 歩道・縁石・ガードレール（高反射）・横断歩道・停止線・信号機・街灯、裏通りの電柱＋架空線（カテナリー）＋変圧器・路上駐車・空地の駐車場、植栽帯（生垣・中央分離帯）、歩道橋、バス停（標識・上屋・ベンチ）、道路標識、自動販売機、袖看板・屋上広告 |
| 高架 | 高欄上のフェンス（支柱 2 m ピッチ・笠木）、排水側溝、伸縮装置（40 m）、進行方向矢印（80 m）、床版張出し下面 |
| 車両 | 車線上の箱、窓部は返りが少ない。トラック 18 % |
| 植生 | 公園内の樹木、幹線道路の街路樹（球殻状の点分布） |
| 水面 | 返りがほとんど無い（≈0.03 pt/m²）ため黒く抜ける |
| ノイズ | 測距ノイズ σ≈12 mm、0.25 % の浮遊点（マルチパス・鳥） |
| 偏差 | 一部要素に施工誤差を注入（橋脚の傾き、壁高欄の孕み、桁の沈下）→ Scan-to-BIM モードで赤く出る |

## BIM / Revit 的表現

- **IFC 分類**: IfcSlab / IfcBeam / IfcRailing / IfcColumn / IfcFooting / IfcMember / IfcBuilding
- **Revit 風プロパティ**: 識別情報（要素 ID・マーク・カテゴリ・ファミリ・タイプ）／拘束（レベル・路線・フェーズ）／寸法・体積／材料／点群照合（点数・平均偏差・最大偏差・被覆率・健全度 A–D）
- **レベル** `▽ Deck L1–L5` と **通り芯バブル**（橋脚 P-001…）
- **断面ボックス**（6 面クリッピング、点群と BIM に同時適用）
- **4D**: 基礎 → 橋脚 → 横梁 → 主桁 → 床版 → 高欄 → 付属物 の順に出現（点群も連動）
- **計測**: 点群上 2 点間を mm で表示（水平距離・高低差付き）
- **表示スタイル**: ワイヤーフレーム／半透明シェーディング／カテゴリ色（Revit の「カテゴリで色上書き」）

## 操作

| 操作 | 内容 |
| --- | --- |
| ドラッグ / ホイール / 右ドラッグ | 回転 / ズーム / パン |
| クリック | 点群または BIM 要素を選択（右パネルにプロパティ） |
| 計測ボタン → 2 点クリック | 距離計測。Esc で解除 |
| ランプ走行 | 首都高本線を連結した約 2.5 km を車載視点で走行 |
| 凡例の分類をクリック | 分類ごとの表示／非表示 |
