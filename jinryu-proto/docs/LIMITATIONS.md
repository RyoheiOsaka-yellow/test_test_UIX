# 既知の限界と v0.2 ロードマップ

## 既知の限界（v0.1）

### データ
- **期間ずれ**: 人流オープンデータは 2019–2021 年、実測（岡山市 AI カメラ）は 2024 年〜、建物は 2022 年調査。較正は「空間分布は安定」という仮定に依存する。
- **時間帯の粗さ**: 人流オープンデータは 昼(11–14時台)/深夜(1–4時台)/終日 のみ。仕様の 8 区分（朝・昼・夕・夜）は商用データ導入まで出せない。
- **来街者構成は市区町村単位**: 区画ごとの居住地構成は出せない（UI では市の構成比を参考表示）。
- **実測地点が少ない**: 較正に使えた街路地点は 9 箇所。Spearman の信頼区間は広く、1 地点の入れ替えで ±0.1 動く。隔年の「商店街等通行量調査」（時間帯別・多地点）の取り込みが最優先。
- **PLATEAU 属性の欠損**: 階数不明（9999）が 32%、延床が異常値（建築面積×階数の 0.3〜3 倍外）で 41% は推定に置換。用途「その他」が 25%。
- **OSM 依存**: 歩行者ネットワークの品質（アーケードと車道の分離、横断歩道の接続）が結果に直結する。奉還町 3 丁目（S09）は並行街路に流れが取られ、通行量 0 のまま。

### モデル
- 経路配分は最短経路 all-or-nothing。並行街路の分担が極端になる（アーケード選好係数 0.75 とスクリーンライン合算で緩和）。コスト摂動による簡易確率的配分は試したが Spearman を下げたため無効化（config で再有効化可）。
- 重力モデルの距離抵抗は半減距離 300m が最良。「駅 → 表町（1.2km）」のような長い徒歩トリップは過小になる（路面電車・バスの中間手段を扱っていない）。
- 駅の出口配分（東口 72%／西口 28%）は手置き。
- 発生・集中の係数 α は手置き（学習していない）。POI 密度の追加集中（1 件 = 100 人/日相当）も手置き。
- 外部ゾーン（bbox 外周 1km のメッシュ人口を境界ノードに載せる）の流入割合 0.35 は手置き。
- 秘匿は「10 未満は表示しない」だけで、少数値の丸めや複数値からの逆算対策はしていない。

### システム
- 認証・課金・マルチテナントなし。API は無防備（ローカルデモ専用）。
- UI は単一 HTML（ビルド無し）。PDF 出力はブラウザ印刷相当。
- 建物 GeoJSON（3 万棟）を毎回配信するため初回表示が数秒かかる（MVT 化していない）。

## v0.2 ロードマップ（優先順）

1. **実測点の拡充**: 岡山市 商店街等通行量調査（時間帯別）の手入力 CSV → 時間帯別較正。xBUILD 自社センシング点の追加（source 列で管理）。
2. **商用人流アダプタ**: Agoop 等の 500m/1 時間帯データで `adapters/` を実装し、同じ較正で精度比較（H3 の検証）。
3. **確率的経路配分**: k-shortest / ロジット配分。歩行環境（歩道幅、アーケード、信号）をコストに反映。
4. **係数 α の学習**: 実測点を教師に α・距離抵抗・POI 重みを同時推定（ベイズ最適化 or 非負最小二乗）。
5. **施策シナリオ**: リンクの通行止め／歩行者天国化／新規建物の追加を UI から指定して再配分（「もしも」比較）。
6. **2 エリア目（札幌）**と area.yaml の切替だけで動く一般化、MVT 配信、Vite + TypeScript 化。
7. **法務**: OSM ODbL の派生 DB 扱い、商用データの再配分可否、秘匿基準の整理。
