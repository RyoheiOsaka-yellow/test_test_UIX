# 既知の限界と v0.2 ロードマップ

## 既知の限界（v0.1）

### データ
- **期間ずれ**: 人流オープンデータは 2019–2021 年、実測（岡山市 AI カメラ）は 2024 年〜、建物は 2022 年調査。較正は「空間分布は安定」という仮定に依存する。
- **時間帯の粗さ**: 人流オープンデータは 昼(11–14時台)/深夜(1–4時台)/終日 のみ。仕様の 8 区分（朝・昼・夕・夜）は商用データ導入まで出せない。
- **来街者構成は市区町村単位**: 区画ごとの居住地構成は出せない（UI では市の構成比を参考表示）。
- **実測地点が少ない**: 較正に使えた街路地点は 9 箇所。Spearman の信頼区間は広く、1 地点の入れ替えで ±0.1 動く。隔年の「商店街等通行量調査」（時間帯別・多地点）の取り込みが最優先。
- **PLATEAU 属性の欠損**: 階数不明（9999）が 32%、延床が異常値（建築面積×階数の 0.3〜3 倍外）で 41% は推定に置換。用途「その他」が 25%。
- **OSM 依存**: 歩行者ネットワークの品質（アーケードと車道の分離、横断歩道の接続）が結果に直結する。奉還町 3 丁目（S09）は並行街路に流れが取られ、通行量 0 のまま。

### モデル
- 経路配分は最短経路 all-or-nothing。並行街路の分担が極端になる（アーケード選好係数 0.75 とスクリーンライン合算で緩和）。コスト摂動による簡易確率的配分は試したが Spearman を下げたため無効化（config で再有効化可）。
- 重力モデルの距離抵抗は半減距離 300m が最良。「駅 → 表町（1.2km）」のような長い徒歩トリップは過小になる（路面電車・バスの中間手段を扱っていない）。
- 駅の出口配分（東口 72%／西口 28%）は手置き。
- 発生・集中の係数 α は手置き（学習していない）。POI 密度の追加集中（1 件 = 100 人/日相当）も手置き。
- 外部ゾーン（bbox 外周 1km のメッシュ人口を境界ノードに載せる）の流入割合 0.35 は手置き。
- 秘匿は「10 未満は表示しない」だけで、少数値の丸めや複数値からの逆算対策はしていない。

### システム
- 認証・課金・マルチテナントなし。API は無防備（ローカルデモ専用）。
- UI は単一 HTML（ビルド無し）。PDF 出力はブラウザ印刷相当。
- 建物 GeoJSON（3 万棟）を毎回配信するため初回表示が数秒かかる（MVT 化していない）。

## v0.2 ロードマップ（優先順）

1. **実測点の拡充**: 岡山市 商店街等通行量調査（時間帯別）の手入力 CSV → 時間帯別較正。xBUILD 自社センシング点の追加（source 列で管理）。
2. **商用人流アダプタ**: Agoop 等の 500m/1 時間帯データで `adapters/` を実装し、同じ較正で精度比較（H3 の検証）。
3. **確率的経路配分**: k-shortest / ロジット配分。歩行環境（歩道幅、アーケード、信号）をコストに反映。
4. **係数 α の学習**: 実測点を教師に α・距離抵抗・POI 重みを同時推定（ベイズ最適化 or 非負最小二乗）。
5. **施策シナリオ**: リンクの通行止め／歩行者天国化／新規建物の追加を UI から指定して再配分（「もしも」比較）。
6. **2 エリア目（札幌）**と area.yaml の切替だけで動く一般化、MVT 配信、Vite + TypeScript 化。
7. **法務**: OSM ODbL の派生 DB 扱い、商用データの再配分可否、秘匿基準の整理。

## v0.4 で分かった精度の上限（重要）

福岡で実測 436 観測に対して較正した結果、街路単位の順位相関は **空間ブロック CV で 0.44** だった。
岡山の 0.69 は 9 地点による値で、地点数を増やすと実力は 0.4 台であることが分かった。

原因は構造的で、係数の調整では埋まらない。

- **人流データが 1km メッシュ**。天神・博多のような中心部は数メッシュしか無く、サブ km スケールの
  空間的な情報は事実上ゼロ。街路ごとの差は建物の延床面積・用途と POI 密度からの推定でしか作れない。
  係数推定が「延床面積より POI 密度」と言ったのは、1km メッシュに情報が無いことの裏返しでもある。
- **地下歩行空間が未モデル化**。天神地下街は 1 地点で 44,272 人と地上の主要地点を超える。地上だけの
  ネットワークに全トリップを載せているため、駅周辺の地上街路を系統的に過大評価する。
- **経路配分が最短経路ベース**。コスト摂動による確率的配分で推定 0 の街路は 11%→4% に減ったが、
  並行街路の分担は依然として粗い。

これは仕様の H3（商用データで精度が上がるか）に対する実証的な答えでもある。**100〜500m メッシュの
商用人流データを入れたときに 0.44 がどこまで上がるかが、有償データ導入の意思決定材料になる。**
現状の水準は「順位の粗い把握」には使えるが、「人/日の絶対値」を根拠に投資判断をする水準ではない。

## v0.5 追記: 地下を入れて分かったこと

地下歩行空間をモデルに入れると、学習に使っていない地区での順位相関が 0.299 → 0.352 に上がった。
一方で、これまで平面でスクリーンラインを判定していたため、地下街の真上の地上地点が地下の流量を
合算しており、v0.4 までの数値（0.472/0.439）はその分だけ過大だった。修正後は 0.427/0.404。

残る構造的な限界は変わらない。

- **人流データが 1km メッシュ**であること。これが絶対値の精度を縛る最大の要因。
- **地下の調査地点 80 箇所を使えていない**。PDF の地下図には縮尺バーが文字として無く、座標を
  付与できなかった。地上図との重ね合わせで座標を起こせば、地下の較正もできる。
- **地下鉄の駅間移動を扱っていない**。地下街は歩行ネットワークとして入ったが、地下鉄そのものは
  発生・集中点（駅）としてしか扱っていない。

## 製品としての位置づけ（v0.5 で確定）

**提供するのはエリア内の相対順位**であり、人/日の絶対値は目安として扱う。UI は順位を主役に据え、
絶対値は「参考値」と明示し、利回りは幅で示す。順位の一致度は実測で検証し、その数値を画面に
常時表示する。絶対値を根拠に投資判断をする水準に上げるには、100〜500m メッシュの商用人流データが
必要で、その検証が次の意思決定ポイントになる。


## v0.6 追記: 数値が揺れていた原因と、確定した精度

ジオリファレンスで縮尺を自由変数にしていたため、実行のたびに 1% 程度ずれ、地図の端の地点が
隣の街路に乗り移って **Spearman が 0.427 と 0.383 の間で揺れていた**。縮尺バーのある図では
縮尺と回転を固定する方式に変え、再現するようにした。確定値は以下。

| エリア | 較正観測 | Spearman (in) | 空間ブロック CV |
|---|---|---|---|
| 岡山市中心部 | 18 | 0.631 | 0.685 |
| 福岡市中心部 | 436 | 0.365 | 0.365 |

### 係数推定は一意に決まらない
12 個の係数を 217 地点で推定すると、実行ごとに大きく違う解が同程度の当てはまりで得られる
（例: 商業の集中係数が 0.25 の解と 5.5 の解が同じスコア）。**個別の係数値を「業務用途は集中が
低い」といった知見として読むのは誤り**で、安定して言えるのは次の 3 つだけ。

- POI（店舗・飲食）密度の重みは常に上限に張り付く。延床面積より店舗密度が効く
- 住宅からの発生率は常に下限に張り付く。中心部では住宅発地はほとんど効かない
- 距離抵抗の半減距離は 180〜245m に収束する。手置きの 450m よりかなり局所的

係数を減らすか、複数都市の実測をまとめて推定するのが次の手になる。

**v0.7 でも解決していない。** 到着端を入れて精度が上がったあとも、70/30 分割ごとに
`dest_retail` は 2.682 / 0.049 / 0.110、`underground_weight` は 2.3 / 92.1 / 0.1 とばらつく。
安定しているのは `poi_weight` が上限付近（1204-1462）に張り付くことだけで、「延床面積より
店舗密度が効く」という所見は頑健。それ以外の個別の係数値を知見として読んではいけない。

## v0.7 追記: 精度の主因は係数ではなく「到着端の欠落」だった

v0.6 までは係数の調整で精度を上げようとしていたが、効果は ±0.03 に留まっていた。
実測 217 地点に素朴な指標を当てて比べたところ、**パラメータを 1 つも持たない
「半径 100m の POI 数」が順位相関 0.558 を出し、積み上げたモデル（0.365）を上回っていた**。

原因は構造的な取りこぼしだった。最短経路配分はゾーン代表ノード（150m グリッド）で打ち切られる。
つまり**目的地に着いてからの最後の数十メートル — まさに商店街で通行量が立つ区間 — が
どのリンクにも乗らない**。モデルが数えていたのは通り抜け交通だけで、その街路自体が目的地で
ある場合の歩行が丸ごと抜けていた。実際、到着端を入れると通行量が付くリンクが 8,662 → 13,495 本に増え、
合成値が 0 だった較正地点が 22 → 0 になった。

### 到着端の重みは「店舗密度」でなければならない

最初に入れた重み `(1+沿道POI) × 長さ/100` は順位相関 0.06 しかなく、効果が出なかった。
リンク長そのものが -0.17 と負相関（長いリンクは郊外の幹線、短いリンクは繁華街の街区）で、
長さ項が重みを支配していたため。断面の通行量は区間に居る総人数ではなく単位長さあたりの
立ち寄り先の多さに対応するので、長さで割った密度を使う。

| 重みの作り方 | 順位相関 |
|---|---|
| 沿道 POI 密度（100m あたり、半径 50m） | 0.534 |
| 沿道 POI 数のみ（半径 30m） | 0.478 |
| (1+沿道POI) × 長さ/100 | 0.060 |
| リンク長のみ | -0.169 |

**新しい項を入れるときは、その項の重み自体を単独で実測に当てて確かめる**。これをしなかったため、
正しい仮説を一度は誤って捨てかけた。

### 到着端係数は学習させず、格子探索で決める

他の係数と一緒に最適化に渡すと、学習地区に特化して転移しなくなる。学習量と転移性能は
きれいな逆相関になった（天神↔博多の相互 holdout、2 方向平均）。

| 手法 | 学習する係数の数 | 別地区での順位相関 |
|---|---|---|
| 到着端を固定し、他も手置き | 0 | **0.345** |
| 到着端を固定し、他 12 個を学習 | 12 | 0.31 |
| 到着端も含め 13 個を学習 | 13 | 0.269 |
| 従来（到着端なし 12 個を学習） | 12 | 0.257 |

そこで到着端係数は `calibrate` の格子探索（half_distance と同時）で全観測に対して 1 つ決める。
最適値はエリアで異なり、福岡は 300 付近、岡山は 100 が最良だった（岡山には地下街も
大規模な駅前商業集積もなく、到着端の寄与が小さい）。

### 用途によって推奨が変わる

**同じ市内の未観測地点**を推定する（実運用）なら、係数を学習したうえで到着端を足すのが最良。
地点を 70/30 に分けた検証を 3 回行った結果（本番と同じ構成。到着端 100・距離抵抗 450m は
全観測から決めた値に固定し、残り 12 個だけを学習データ内で学習）:

| 分割 | 学習内 | 検証 |
|---|---|---|
| 0 | 0.559 | 0.566 |
| 1 | 0.591 | 0.456 |
| 2 | 0.583 | 0.555 |
| **平均** | 0.578 | **0.526** |

同じ分割・同じ手順で到着端を外すと 0.526 → **0.314**（0.272-0.366）になる。3 分割すべてで
改善し、到着端ありの最小値 0.446 が従来の最大値 0.366 を上回る。

UI に出している 0.528（calibrate のブロック別スケール CV）と、独立に測ったこの 0.526 は
ほぼ完全に一致する。測っているものは違う（前者はスケールだけを再推定、後者は係数を分割内で
学習し直す）のに同じ値に落ち着いたので、表示値は過大でも過小でもない。分割間のばらつきは
0.46〜0.57。測っているものは違う（前者はスケールだけを再推定、後者は係数を分割内で
学習し直す）のに同じ値に落ち着いたので、表示値は過大でも過小でもない。分割間のばらつきは
0.45〜0.55 で、66 地点での検証としては自然な幅。

**実測が無い別の街**へ持ち出した場合は、本番構成（到着端と距離抵抗は固定し、残り 12 個を
一方の地区で学習）で測ると 0.347（0.26-0.40）。到着端なしの 0.257 から +0.09。

| 学習 → 検証 | 平均 | 最小 | 最大 |
|---|---|---|---|
| 博多（駅前型）→ 天神 | **0.382** | 0.373 | 0.396 |
| 天神（商業集積型）→ 博多 | 0.312 | 0.258 | 0.342 |

方向で性質が違う。駅前型で学習した係数は商業集積型へ持ち出せてばらつきも小さいが、逆は
不安定。博多は駅という支配的な要因があるぶん係数が定まりやすく、天神は店舗密度が主因で
解が一意に決まらないためと考えられる。**新しい都市では駅前型の地区から実測を取るのがよい。**
新しい都市に展開するときは、現地の実測を取るまで精度を約束しないという運用は変わらない。

### 残る限界

- 天神と博多は物理的に別の係数を要求する。博多は駅が支配的（駅重み 0.8、住宅発生ほぼ 0）、
  天神は店舗が支配的（POI 重みが上限に張り付き、駅重みは 1/10）。1 組の係数で両方を説明できない。
- 人流データが 1km メッシュであることは変わらない。到着端が効いたのは、1km メッシュには無い
  サブ km スケールの情報を、沿道の店舗密度という別の観測から補ったため。
- half_distance は学習が一貫して 240〜300m に収束する。v0.6 の 179m は短すぎた。
