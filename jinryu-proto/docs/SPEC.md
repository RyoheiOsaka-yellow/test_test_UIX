## 1. 目的とコンセプト

### 1.1 一言で

**メッシュ単位の広域人流データを、建物・道路リンクという「意思決定の単位」に再配分し、不動産・自治体が使える言葉（通行量・来街者構成・施策効果）で返すエンジン。**

### 1.2 参考にした構造（syte）

| syte の要素 | 本プロトタイプでの対応 |
|---|---|
| 分断データを1物件単位のデジタルツインに統合 | 人流メッシュ＋PLATEAU建物＋道路網＋統計を建物ID/リンクIDで統合 |
| 地番を「経済単位」へ束ねる独自アルゴリズム | メッシュ人口を建物・道路リンクへ再配分（ダウンスケーリング） |
| 合成データで学習し実測で検証 | OD生成＋経路配分で合成歩行者流を作り、公開の通行量調査で較正 |
| 法規ロジックを学習した特化モデル | 用途地域・建物用途に基づく配分係数（v0.1はルールベース） |
| API／ホワイトラベルで業務フローに組込み | 区画スコアAPI＋地図UI |

### 1.3 プロトタイプで検証したい仮説

- H1：1kmメッシュ程度の粗い人流データでも、建物・道路リンク単位に再配分すれば、実測通行量との順位相関（Spearman）が 0.6 以上出る
- H2：不動産向けには「区画単位の通行ポテンシャル＋来街者構成」、自治体向けには「施策前後の差分」が、それぞれ購買理由になる
- H3：オープンデータのみでデモ可能な精度が出れば、商用データ（有償）はアダプタ差し替えで精度向上オプションにできる

## 2. スコープ

### 2.1 v0.1 でやること

- 対象エリア1か所（市区町村1つ、または駅圏2〜3km四方）
- オープンデータでのパイプライン一式
- 建物単位の滞在人口推定、道路リンク単位の通行量推定
- 実測通行量データでの較正と精度評価
- 区画（建物 or 任意ポリゴン）を指定するとスコアを返す API
- 地図 UI（ヒートマップ、区画クリックでレポート表示、期間比較）

### 2.2 v0.1 でやらないこと

- 全国展開、リアルタイム更新
- 売上の確定的な予測（「仮定を入れた試算」までに留める）
- 商用人流データの本契約（アダプタの口だけ用意）
- 認証・課金・マルチテナント

## 3. 想定ユーザーとユースケース

### 3.1 不動産（デベロッパー、仲介、AM、金融機関の審査部門）

- UC-R1：候補区画を指定 → 前面道路の推定通行量（平日/休日・時間帯）、周辺比較での順位、来街者の居住地構成
- UC-R2：エリア内で「通行ポテンシャルは高いが空き・低利用」の建物を抽出（syte の区画検索に相当）
- UC-R3：業態別の簡易売上試算（通行量 × 入店率 × 客単価。係数はユーザー入力、既定値は仮置きと明示）

### 3.2 自治体（まちづくり、商工、交通、防災）

- UC-G1：施策（歩行者天国、再開発、イベント、社会実験）の前後期間を指定 → 対象街路の人流差分と周辺への波及
- UC-G2：エリアの時間帯別・曜日別の人流構造の把握（中心市街地活性化計画などの基礎資料）
- UC-G3：PLATEAU との重ね合わせによる説明資料の出力

## 4. データソース

> 利用規約・ライセンス・更新状況は着手時に必ず一次ソースで再確認すること（本表は候補リスト）。

### 4.1 オープンデータ（v0.1 の主軸）

| 区分 | データ | 用途 | 備考 |
|---|---|---|---|
| 人流 | 国交省「全国の人流オープンデータ」（G空間情報センター） | 1kmメッシュ滞在人口の基礎値 | 期間・粒度・区分は要確認 |
| 建物 | PLATEAU 3D都市モデル（建物：用途、階数、高さ、延床相当） | 配分係数、建物ID | 対象都市のLOD・属性充足度を事前確認 |
| 道路 | OpenStreetMap（歩行者網）／国土地理院 基盤地図情報 | 経路配分用ネットワーク | v0.1 は OSM を優先 |
| 駅 | 国土数値情報「駅別乗降客数」 | OD生成の発生点・重み | |
| 用途地域 | 国土数値情報「用途地域」 | 配分係数 | |
| 地価 | 国土数値情報「地価公示」 | レポート付加情報 | |
| 人口 | e-Stat 国勢調査 地域メッシュ統計 | 夜間人口の補正 | |
| 事業所 | e-Stat 経済センサス メッシュ | 昼間人口・商業集積の重み | |
| POI | OSM の店舗・施設 | 商業集積度 | |
| **検証用** | 自治体公開の歩行者・自転車通行量調査 | 較正と精度評価 | 対象エリア選定の最重要条件 |

### 4.2 商用データ（アダプタのみ用意、本契約は v0.2 以降）

- Agoop 流動人口データ、KDDI Location Analyzer、ドコモ・インサイトマーケティング モバイル空間統計 など
- 粒度（100m〜500mメッシュ、時間帯、属性）がオープンデータより細かいものを想定
- `adapters/` に共通インタフェースを定義し、ソース差し替えでパイプラインが動くようにする

### 4.3 対象エリア選定基準

1. 直近数年分の**歩行者通行量調査が地点・時間帯付きで公開**されている（必須）
2. PLATEAU の建物用途・階数属性が整備されている
3. 駅を含み、商業地と住宅地が混在している
4. 将来の営業先になり得る（自治体案件化の可能性）

候補を3つ挙げ、1〜3の充足状況を表にしてから決定する（フェーズ0のタスク）。

## 5. アルゴリズム

### 5.1 全体フロー

```
[人流メッシュ] ──┐
[建物(PLATEAU)] ─┼─▶ ① 建物単位 滞在人口推定（ダスメトリック配分）
[用途地域/統計] ─┘            │
                               ▼
[駅乗降客数] ─────▶ ② OD生成（駅・建物を発生/集中点に）
                               │
[道路ネットワーク] ─▶ ③ 経路配分 → 道路リンク通行量（合成）
                               │
[通行量調査] ─────▶ ④ 較正（係数フィッティング）＋精度評価
                               │
                               ▼
                    ⑤ スコアリング／レポート／API
```

### 5.2 ① 建物単位 滞在人口推定

メッシュ m の滞在人口 P_m を、メッシュ内建物 b に配分する。

```
w_b = GFA_b × α(用途_b, 時間帯) × β(用途地域_b)
P_b = P_m × w_b / Σ_{b∈m} w_b
```

- GFA_b：延床面積（建築面積 × 階数で近似。PLATEAU属性から算出）
- α：建物用途×時間帯の在館係数（例：業務は平日昼が高い、住宅は夜が高い）。v0.1 は `config/coefficients.yaml` に手置き
- β：用途地域補正（v0.1 は 1.0 固定でも可、フラグで切替）
- メッシュ境界をまたぐ建物は重心で帰属

### 5.3 ② OD 生成

- 発生点：駅（乗降客数で重み付け）、住宅系建物（夜間人口）
- 集中点：商業・業務・公共系建物（① の P_b で重み付け）
- 重力モデル：`T_ij = k × O_i × D_j × f(d_ij)`、f は距離抵抗（指数型、徒歩圏を想定し半減距離はパラメータ）
- 時間帯別に OD 行列を作る（v0.1 は平日/休日 × 朝・昼・夕・夜の8区分）

### 5.4 ③ 経路配分

- OSM 歩行者ネットワークで最短経路配分（all-or-nothing）
- v0.1 は最短経路で十分。v0.2 で確率的配分や混雑考慮を検討
- 出力：リンク ID × 時間帯区分 × 推定通行量（合成値・相対値）

### 5.5 ④ 較正と評価

- 通行量調査地点を最寄りリンクにマッチング（距離閾値付き）
- 合成通行量 → 実測通行量へのスケール係数と、α・距離抵抗パラメータをフィッティング
- 評価指標：Spearman 順位相関、MAPE、上位20%地点の一致率
- **学習用と検証用に地点を分割**（空間的に分けるブロッククロスバリデーション）して過学習を避ける
- 目標：Spearman ≥ 0.6（H1）

### 5.6 ⑤ スコアリング

| 指標 | 定義 | 対象 |
|---|---|---|
| 通行ポテンシャル | 前面リンクの推定通行量（時間帯別）とエリア内パーセンタイル | 不動産 |
| 来街者構成 | 滞在人口の居住地区分（市区町村内/外等、データが持つ区分に依存） | 不動産・自治体 |
| 低利用ギャップ | 通行ポテンシャル上位 × 建物滞在人口下位 | 不動産（UC-R2） |
| 簡易売上試算 | 通行量 × 入店率 × 客単価 × 営業日数（係数はユーザー入力） | 不動産（UC-R3） |
| 施策差分 | 期間A/B のリンク通行量差・変化率、周辺リンクへの波及 | 自治体（UC-G1） |

すべての推定値に「推定」「根拠データの期間」「信頼度（較正地点からの距離などで簡易算出）」を付与する。

## 6. システム構成

### 6.1 技術スタック

- 言語：Python 3.11+、パッケージ管理は uv
- データ処理：DuckDB（spatial 拡張）、GeoPandas、Shapely、PyProj
- ネットワーク：OSMnx、NetworkX（重くなれば pandana / igraph に切替）
- CityGML 処理：PLATEAU の配布形式に応じて選択（GeoPackage/Shapefile 等の変換済み形式があればそれを優先）
- API：FastAPI
- フロント：Vite + TypeScript + MapLibre GL JS + deck.gl
- 座標系：保存は EPSG:4326、距離・面積計算は平面直角座標系（対象エリアの系）

### 6.2 ディレクトリ構成

```
jinryu-proto/
├── docs/
│   └── SPEC.md                # 本ファイル
├── config/
│   ├── area.yaml              # 対象エリア（bbox、市区町村コード、平面直角系）
│   ├── coefficients.yaml      # α, β, 距離抵抗などのパラメータ
│   └── sources.yaml           # データソースのURL・ライセンス・取得日
├── data/
│   ├── raw/                   # 取得したままのデータ（git管理外）
│   ├── interim/
│   └── processed/             # parquet / duckdb
├── src/jinryu/
│   ├── adapters/              # 人流ソース共通IF（open_mlit.py, commercial_stub.py）
│   ├── ingest/                # 各データの取得・正規化
│   ├── units/                 # 建物・リンクの意思決定単位テーブル生成
│   ├── downscale.py           # ① 建物配分
│   ├── od.py                  # ② OD生成
│   ├── assign.py              # ③ 経路配分
│   ├── calibrate.py           # ④ 較正・評価
│   ├── score.py               # ⑤ スコア
│   └── api/main.py            # FastAPI
├── web/                       # MapLibre + deck.gl
├── notebooks/                 # 検証・可視化用
├── tests/
└── Makefile                   # make ingest / build / calibrate / serve
```

### 6.3 主要テーブル

```
mesh_flow(mesh_code, period, day_type, time_band, population, origin_class, source)
building(building_id, geom, usage, floors, height, gfa, zoning, mesh_code)
building_pop(building_id, period, day_type, time_band, pop_est, confidence)
road_link(link_id, geom, u, v, length_m, highway_type)
link_flow(link_id, period, day_type, time_band, flow_synth, flow_calibrated, confidence)
count_site(site_id, geom, year, day_type, time_band, count, link_id)
parcel_score(parcel_id, period, metric, value, percentile, confidence)
```

`period` は YYYY-MM を基本とし、データの粒度に合わせる。

## 7. API 仕様（v0.1）

| メソッド | パス | 概要 |
|---|---|---|
| GET | `/areas/current` | 対象エリア情報、利用可能期間 |
| GET | `/links/flow?period=&day_type=&time_band=` | リンク通行量（GeoJSON／MVT） |
| GET | `/buildings/pop?period=&...` | 建物滞在人口 |
| POST | `/parcels/score` | ポリゴン or building_id を受けてスコア一式を返す |
| POST | `/compare` | 期間A/B とポリゴンで差分を返す（UC-G1） |
| POST | `/search/gap` | 低利用ギャップ建物の抽出（UC-R2） |
| GET | `/meta/sources` | 使用データの出典・期間・ライセンス表記 |

レスポンスには必ず `sources` と `disclaimer`（推定値である旨）を含める。

## 9. 法務・プライバシー・表示

- 使用するのは**統計化・秘匿処理済みの集計データのみ**。個票・個人単位の軌跡は扱わない
- 各データの利用規約（商用利用可否、再配布、クレジット表記）を `config/sources.yaml` に記録し、UI と API に出典を表示
- 少数値の秘匿：配分後に小さな値が出る区画は、閾値以下を「—」表示または丸める（閾値は config 化）
- 推定値であることを常に明示し、売上試算は「ユーザー入力の仮定に基づく試算」と表示
- 商用データ導入時は、提供元の利用条件（再配分・派生データ提供の可否）を契約前に確認
