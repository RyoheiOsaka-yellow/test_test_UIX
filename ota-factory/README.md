# YELLOW フュージョン・ファクトリー 大田区 — 開発一体型工場 3D構想モデル v0.4

ソフトウェア開発と大型機械開発をひとつの屋根の下に重ねる「開発一体型工場」を、大田区の想定敷地上に
Three.js で精緻に組み上げた単一 HTML モデルです。共有いただいた加須工場モデル（FLOW·LAB 3D）の
「敷地 → 建屋 → 設備・動線」の作り方を踏襲し、構想イメージ 9 枚（折板屋根・木天井・ガラス・黄色クレーン）を
形にしています。

## 開く

`ota-factory/index.html` をブラウザで開くだけで動きます（three.js を CDN から読むためインターネット接続が必要）。
Chrome / Edge / Safari の最新版を推奨。

| 操作 | 内容 |
|---|---|
| 左ドラッグ / 右ドラッグ / ホイール | 回転 / 平行移動 / ズーム |
| 上部ナビ 外観・1F・2F・3F | 上階と屋根を外す「ドールハウス」表示（キー 1〜4） |
| 断面 | 水平・南北・東西のクリップ断面（スライダー） |
| 歩行 | 作業者の目線で WASD 移動、QE で上下、Esc で終了 |
| 設備クリック / 設備台帳 | 仕様カードを表示し、その設備へ寄る |
| 昼・夕・夜 / ⏸ 稼働 | 時間帯の切替、クレーン・ロボット・AGV・人・トラックの稼働再生 |
| レイヤー | 架構・外皮・設備・什器・MEP・床ライン・人・ラベル・植栽・周辺 の表示切替 |

## v0.2 の追加：レーン自動生成・生産性 KPI・Factory OS・天井工具

**レーン（生産ライン）はデータから自動生成されます。** `src/10_data.js` の `LANE_RECIPES` に
「こういうレーンには こういう機械」をレシピとして定義し、`LANES` で区画・シフト・無人運転時間を与えると、
`56_lanes.js` が機械を蛇行配置し、床の流れ帯・工程マーカー・天井工具を生成し、KPI を算出します。

| レーン | レシピ（工程順） | 天井工具 | 主な KPI |
|---|---|---|---|
| L1 精密部品 加工 | 素材投入→旋盤×2→5軸MC×3→横型MC×2→洗浄→計測→ストア（＋ロボット段取セル） | 天井ガントリーローダ、ツールレール、カメラ/UWB | 個/日・タクト・OEE・自動化率・無人運転 |
| L2 大型構造物 加工 | 素材投入→門型MC→研削→EDM→計測 | ジブクレーン、エネルギーブーム | 個/日 |
| L3 大型機 組立 | 機械組立→配線→ソフト結合→試運転→出荷 | 10t クレーン（精緻版）、ツールレール、ブーム、レーザー投影、カメラ | 台/月・リードタイム |
| L4 制御盤・電子 組立 | 盤組立×2→配線×2→通電試験 | ツールレール、ブーム | 面/日 |
| L5 ソフトウェア デリバリー | コミット→ビルド→HIL→実機試験（試験セル）→OTA | — | リリース/週 |

左下パネル「レーン・生産性」で **構成を変える**（レシピ・主要機械台数・シフト・無人運転・区画）と、
その場で再生成されて KPI が更新されます。「＋ レーン追加」で受入置場や北側庇下などの区画に新しいレーンを置けます。
区画をはみ出す場合は警告を出します。

**Factory OS** タブは YELLOW のソフトウェア層（Edge Runtime / Fleet 協調 / Scheduler / MES / Quality AI / Digital Twin / 予知保全 / CI/CD・HIL / OTA）と
各レーンの対応を示し、モジュールをクリックすると使用レーンと Edge DC（2F サーバー室）へのデータの流れを 3D に表示します。

KPI の式（`computeLaneKPI`）：タクト＝max(工程時間/並列数)、OEE＝稼働率×性能×品質、
日産＝（有人時間＋ボトルネック工程が無人運転可なら無人時間）×OEE÷タクト。組立は月産、ソフトは週次リリース数。

## v0.3 の追加：根拠値の編集・工場全体ライン・レシピ拡充・外観

1. **根拠値を編集できる**: レーンカードの「構成を変える」に工程表（標準時間・並列数・自動化・要員）と OEE の
   3 要素が並びます。実機のサイクルタイムを入れて「生成」すると配置と KPI が即座に更新されます。
   「保存 / 読込」でレーン定義と目標需要を JSON にして持ち回れます。
2. **工場全体ライン（「工場全体」タブ）**: 目標「大型機 2 台/月」から BOM（1 台あたり精密部品 120 個、
   大型構造部品 6 個、板金 40 個、塗装 40 個、制御盤 3 面、ソフトリリース 2 件）で必要量を出し、各供給レーンの
   月産能力と比べて稼働率バーと工場全体の制約（最も能力の低い工程）を表示します。「3D に供給リンクを表示」で
   供給レーンの完成品ストアから組立ベイへの流線（色＝稼働率）が描かれます。社内レーンが無い品目は「外注前提」と表示します。
3. **レシピ拡充**: 板金・溶接（レーザー→プレスブレーキ→溶接ロボット×2→仕上げ→ストア）、塗装（前処理→ブース→乾燥炉）、
   顧客デモ・立会い（準備→ステージ実演→会議室で検収）、試験（試験セル×2＋HIL 判定）を追加。
   「＋ 追加」から区画（受入置場・北側庇下・ホール内の各区画）を選んで置けます。
4. **外観**: 南西の木質エントランス・ポータルと看板、3F 床と軒のスパンドレル、テラス先端の白い帯、
   屋上太陽光（棟の南斜面）と空調屋外機、前庭のボラード照明、雲、樹冠の色バリエーション、夜景では
   オフィス天井とホール天井が発光しガラスが透けます。

## v0.4 の追加：社内化 vs 外注・組立 what-if・屋根リブ

- **社内化 vs 外注**（「工場全体」タブ）: 外注前提の品目ごとに、社内レーンを置いた場合の能力・稼働率・リードタイム・
  年間費用（要員は稼働率換算で他レーンと共有、面積賃料、保守 5%）・設備投資・回収年数を外注の年間費用と並べます。
  「需要 X 台/月以上で 7 年以内に回収」の損益分岐も出します。「社内化する」でその場にレーンを追加できます。
  単価・設備費・賃料は `COST` / `capex` / `outsource` の想定値です。
- **組立 what-if**: 現状 / 組立ベイ 2 並列 / 試験を試験レーンへ外出し / 両方 の 4 案を、3D を作らずに評価して
  組立能力・工場能力・リードタイム・要員・追加投資を比較し、「適用」で 3D とレーン定義を置き換えます。
  モデル上、組立はベイ A（機械組立）→ベイ B（配線・ソフト）の 2 ステージ流れ作業として扱い、タクトは最長ステージです。
- **外観**: 折板屋根のリブ（0.5 m ピッチ）、視点「西面 夕景」「夜景」、周辺街区が敷地に食い込まないよう修正。

## 構成

```
ota-factory/
  index.html        ← 配布用（build.sh で生成。これだけで動く）
  build.sh          ← src/ を連結して index.html を作る
  src/
    00_head.html    CSS・パネル DOM・importmap
    10_data.js      ★計画データ（敷地・建屋寸法・ゾーン・設備台帳・人員・ツアー）
    20_core.js      レンダラ・空・太陽・手続きテクスチャ・材質・カメラ（軌道/歩行）
    30_site.js      敷地・前面道路・電柱・隣接街区・駐車場（ソーラーカーポート）・前庭
    40_building.js  鉄骨架構・トラス・クレーンランウェイ・折板屋根・鋸歯トップライト・カーテンウォール・床・コア
    50_interior.js  工作機械・ロボットセル・組立中の大型機・試験セル・計測室・ラボ・オフィス什器・MEP・レーン用ステーション
    55_overhead.js  天井設備：精緻版クレーン・ジブクレーン・ツールバランサーレール・エネルギーブーム・ガントリーローダ・レーザー投影・カメラ
    56_lanes.js     レーン自動生成（蛇行配置）・床の流れ表示・KPI 計算・Factory OS データフロー
    60_movers.js    クレーン・AGV・作業者・トラック・フォークリフトの稼働アニメ
    70_ui.js        UI・階層表示・断面・設備台帳・計画概要・ツアー・メインループ
  img/              構想イメージ（圧縮済）
  preview/          ヘッドレス描画で取得した確認用スクリーンショット
```

数値を変えたいときは `src/10_data.js` を編集して `bash build.sh` を実行してください。
敷地（`SITE`）と建屋外形（`BLD`）の値を差し替えると、柱・屋根・床・外皮・ラベル・計画概要がすべて追従します。

## 次の議論・提案（v0.2 に向けて）

1. **敷地の確定**: 現在は 120×80 m の仮想敷地。京浜島・城南島のような臨海部（大型トレーラー動線が楽、運河側に試験ヤードを取れる）と、
   糀谷・下丸子のような内陸部（街に開いたファサード、通勤利便）のどちらを目指すかで外構と階数が変わります。
2. **ホール幅 32 m vs 40 m**: 大型機 2 台を並行して組む場合、クレーンスパン 30 m・ベイ幅 16 m は最小限。
   40 m にすると建蔽率 50% で収まり、中央に試験セルを置けますが、屋根の折れが大きくなります。
3. **ソフト階の位置**: 現案は「機械の真上（南側ストリップ）」。中庭を挟んで別棟にする案（イメージ 04）は音・振動に有利ですが、
   実機とログの距離が離れます。両案を同じデータで切り替えられるようにするのが次の実装候補です。
4. **夜間・無人運転**: ロボットセル 2 基のみ自動化。門型 MC へのパレット供給を AGV ループに乗せると、夜間稼働率の試算ができます。
5. **精緻化の次段階**: 配管系統（圧空・クーラント・電源）の干渉チェック、動線の距離・交差の自動集計、
   設備ごとの電力・基礎荷重の集計表、といった加須モデルにあった「評価機能」を同じ台帳データから生成できます。
6. **KPI の根拠値**: 工程時間・OEE・要員は想定値です。実機のサイクルタイムや現工場の実績に差し替えると、
   レーン再構成の比較（例：5軸MC 3台→5台、2直→3直＋無人8h）がそのまま投資判断の材料になります。
