# XANTALOS（ザンタロス）大田区 — 開発一体型工場 3D 構想モデル v0.9

ソフトウェア開発と大型機械開発をひとつの屋根の下に重ねる「開発一体型工場」XANTALOS を、
大田区の想定敷地の上に Three.js で組み上げた単一 HTML モデルです。
加須工場モデル（FLOW·LAB 3D）の「敷地 → 建屋 → 設備・動線」の作り方を踏襲し、
構想イメージ 9 枚（折板屋根・木天井・ガラス・黄色クレーン）を形にしています。

---

## 1. 開き方

| ファイル | 用途 |
|---|---|
| `xantalos-ota-factory-standalone.html` | **配布用の単体版**。構想イメージとロゴを埋め込み済み。ダブルクリックで開けます |
| `index.html` | 開発用。`img/` フォルダと同じ場所に置いて開きます |

- three.js を CDN から読むため、インターネット接続が必要です。
- Chrome / Edge / Safari の最新版を推奨します。

## 4. 主な機能

### レーン自動生成と生産性 KPI（左下「レーン」）

- `src/10_data.js` の `LANE_RECIPES` に「こういうレーンにはこういう機械」をレシピとして定義し、
  `LANES` で区画・シフト・無人運転時間を与えると、機械配置・床の流れ帯・工程マーカー・天井工具・KPI が自動生成されます。
- 「構成を変える」では、レシピ・主要機械台数・シフト・無人運転・区画に加え、工程ごとの標準時間・並列数・自動化・要員と OEE を編集でき、その場で再生成されます。
- 「＋ 追加」で新しいレーンを置けます。「保存／読込」でレーン定義を JSON にして持ち回れます。
- レシピは 9 種です：精密部品、大型構造物、大型機組立、制御盤、ソフトウェア、板金・溶接、塗装、顧客デモ、試験。
- KPI の式：タクト＝max（工程時間÷並列数）、OEE＝稼働率×性能×品質、日産＝（有人時間＋無人運転時間）×OEE÷タクト。
  無人運転時間はボトルネック工程が無人運転可のときだけ加算します。

### 工場全体ライン（左下「工場全体」）

- 目標台数（スライダー）と 1 台あたりの BOM（精密部品 120 個、大型構造部品 6 個、板金 40 個、塗装 40 個、制御盤 3 面、ソフトリリース 2 件）から必要量を出し、各レーンの能力と比べて稼働率と工場全体の制約を表示します。
- 「3D に供給リンクを表示」で、供給レーンから組立ベイへの物量の流れを稼働率の色で描きます。
- 社内化と外注の比較（能力・リードタイム・年間費用・投資・回収年数・損益分岐の需要）を表示します。
- 組立の what-if（配線ベイ 2 並列／機械組立 +1／試験外出し／併用）を 3D を作らずに評価し、「適用」で置き換えられます。

### Factory OS（左下「Factory OS」）

XANTALOS のソフトウェア層 9 モジュールを 4 層で示します。
Edge Runtime、Fleet 協調、Scheduler、MES、Quality AI、Digital Twin、予知保全、CI/CD・HIL、OTA です。
モジュールをクリックすると、使用レーンと 2F サーバー室へのデータの流れを 3D に表示します。

### BIM・MEP（上部バー「BIM・MEP」）

- 8 系統を自動ルーティングします：給気ダクト、排気・集塵ダクト、圧縮空気、クーラント、消火、電源ケーブルラック、LAN、冷温水。
- 幹線と枝のサイズは、設備ごとの設計負荷を集計し、需要率 0.7 で算定して形状に反映しています。
- 系統ごとの表示切替、延長・器具数・負荷の集計、数量 CSV、X 線表示、幹線高さの調整ができます。
- 干渉チェックは、配管と柱・トラス・クレーン走行範囲・設備の交差を検出します。
- 保守スペースチェックは、設備ごとの前後・左右の開放寸法を黄枠で表示し、他設備や配管の立下りの侵入を一覧します。

### 建屋と内外装

- **外観**：折板屋根とリブ、鋸歯トップライト、木天井の軒、3F 南面の木製ルーバー、2F テラス（木デッキ・足元灯・パーゴラ）、木質エントランス、東面の避難階段、北面の目地・ガラリ・竪樋・排気筒、屋上太陽光と点検歩廊。
- **外構**：前庭プラザとシンボルツリー、ソーラーカーポート駐車場、EV 充電、守衛所とゲート、駐輪場、ごみ置場、北側の庇下ヤード、周辺街区と電柱。
- **天井設備**：10 t クレーン（フェストゥーン・巻上ドラム・フックブロック）、ジブクレーン、ツールバランサーレール、エネルギーブーム、5 軸 MC 列のガントリーローダ、レーザー投影、天井カメラ。
- **内観**：レーンごとのアンドン表示板とバナー、機械まわりの切粉箱・工具カート、通路のゼブラと AGV 停止線、ゾーンごとの床仕上げ、各室の什器とドアプレート、ロビーと HIL ラボのデジタルツイン壁面。
- **稼働アニメ**：クレーン、ロボット、AGV、ガントリーローダ、作業者、トラック、フォークリフト。

### 実物 3D モデル（NVIDIA SimReady）

フォークリフト・ハンドパレット・パレット・木箱・パレットラック・踏台・ドック安全ゲート・消火器・救急箱・洗眼器・ロッカー・
溶接機・ツールキャビネット・工具カート・リフトテーブル・部品洗浄機・空気圧縮機・エアドライヤ・ドラム缶・IBC タンク・塗装ブース・
ローラーコンベヤ・移動式協働ロボット・工場扇・ごみ箱・来客ソファ・コーヒーステーション・複合機・3D プリンタ・オシロスコープ・
オフィスチェアなど約 40 種・130 点を、NVIDIA SimReady の実物モデル（glTF）で配置しています。

- 出典：[nvidia/simready-assets](https://huggingface.co/datasets/nvidia/simready-assets) を Web 向けに圧縮した
  [codepawl/simready-glb](https://huggingface.co/datasets/codepawl/simready-glb)。ライセンスは CC BY 4.0（著作者：NVIDIA）。
- 読込は開いたときにネットワークから行い、届くまでは手続きモデルを表示し、届いた順に差し替えます。オフラインでも手続きモデルで成立します。
- レイヤーの「実物モデル（SimReady GLB）」で ON/OFF、「実物モデルの品質」で 軽量（LOD2）／標準（LOD1）／最高（原型）を選べます。
  原型で 30 万三角形を超える重いモデルは、選んだ品質より 1 段軽い LOD を使います。URL に `?assets=lod2`、`?assets=off` も指定できます。
- レーンを再構成すると、工程の種類に応じた小物（旋盤の工具カート、溶接セルの溶接機、前処理のドラム缶など）も自動で付きます。
- クリックすると出典とアセット名、ホバーで名称を表示します。

## 5. ファイル構成と編集方法

```
ota-factory/
  xantalos-ota-factory-standalone.html  ← 配布用の単体版（build.sh で生成）
  index.html                            ← 開発用（build.sh で生成）
  build.sh                              ← src/ を連結して 2 つの HTML を作る
  src/
    00_head.html    CSS・パネル DOM・importmap
    05_logo.js      XANTALOS ロゴ（base64）
    10_data.js      ★計画データ：敷地・建屋寸法・ゾーン・設備台帳・人員・ツアー・レシピ・レーン・BOM・費用
    20_core.js      レンダラ・空・太陽・テクスチャ・材質・カメラ・ロゴ板
    30_site.js      敷地・道路・電柱・周辺街区・駐車場・前庭・北側ヤード
    40_building.js  鉄骨架構・トラス・折板屋根・トップライト・カーテンウォール・床・コア・テラス・屋上
    50_interior.js  工作機械・ロボットセル・組立機・試験セル・ラボ・オフィス什器・レーン用ステーション
    55_overhead.js  天井設備（クレーン・ジブ・ツールレール・ブーム・ガントリーローダ・レーザー・カメラ）
    56_lanes.js     レーン自動生成・KPI・工場全体ライン・社内化比較・what-if
    57_mep.js       MEP 8 系統の自動ルーティング・サイジング・干渉と保守スペースのチェック
    58_detail.js    外観・内観ディテール（ルーバー・避難階段・外構・アンドン・デジタルツイン壁面）
    59_floors.js    各階の部屋ごとの作り込み
    60_movers.js    稼働アニメ
    65_assets.js    NVIDIA SimReady GLB の読込・配置（レーン連動、LOD、fallback）
    70_ui.js        UI・ツアー・ホバー表示・メインループ
  img/              構想イメージとロゴ
  preview/          確認用スクリーンショット
```

数値を変えるときは `src/10_data.js` を編集してから、次のコマンドで再生成します。

```bash
bash ota-factory/build.sh
```

敷地（`SITE`）と建屋外形（`BLD`）を差し替えると、柱・屋根・床・外皮・計画概要が追従します。
工程時間・OEE・設備費・外注単価・設計負荷はすべて想定値で、`STATION_TYPES`、`LANES`、`COST`、`BOM`、`LOADS` にまとまっています。

## 7. 未決事項と次の候補

**決めていただきたいこと**

1. **ブランドカラー**：UI の差し色は黄（#f2c744）のままです。ロゴのモノトーンに合わせるか、差し色を 1 色決めるかを決めたいです。
2. **敷地の性格**：臨海部（京浜島・城南島）なら大型トレーラー動線と屋外試験ヤードが取りやすく、内陸部（糀谷・下丸子）なら街に開いたファサードが活きます。
3. **想定値の差し替え**：実機のサイクルタイム、設備見積り、外注単価、人件費が入ると、KPI と比較表がそのまま投資判断の数字になります。

**次の実装候補**

1. MEP の負荷集計から、コンプレッサ・集塵機・受変電の機器容量を選定し、北側設備ヤードの機器サイズに反映する。
2. 保守スペースをレーン生成の制約に組み込み、台数を増やしたときに区画内に収まるよう自動で行を増やす。
3. 歩行モードに、ドアの自動開閉、階段・EV での階移動、来客動線のプリセット巡回を付ける。
4. 製造要員の集計：レーン要員の合計（約 45 名）が人員計画の製造 38 名を超えているので、人員内訳をレーンから自動集計する形にする。
