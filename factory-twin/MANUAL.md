# ATOMIX 加須工場 デジタルツイン 利用マニュアル

最終更新: 2026-11-25（第8回）。機能を変えるたびに、このマニュアルも同時に更新します。
変更の経緯は `README.md`、データの作り方は `pipeline/build_analytics.py` を参照してください。

---

## 1. これは何か

加須工場の設備移設（ワニス・調色を第二工場へ移し、生産人員を2名減らす計画）を検討するための道具です。
3Dビューアと分析基盤が連動しており、「工場全体 → 建屋の内部 → 設備1台」の順に掘り下げて見られます。

## 2. 開き方

`dist/index.html` をブラウザ（Chrome / Edge 推奨）で開きます。3D描画ライブラリをインターネットから読むため、ネット接続が必要です。
読み込みに数秒かかります。20秒たっても表示されない場合は、接続を確認して再読み込みしてください。

## 3. 画面の構成

| 場所 | 内容 |
|---|---|
| 中央 | 3Dビュー（敷地全景、または建屋内部） |
| 右 | **分析基盤パネル**。いま見ている対象に合わせて内容が変わる。上部の「分析基盤」ボタンで開閉 |
| 左 | 設備ワークスペース（外観・空間・接続と動線・設備台帳・設備詳細・配置検証） |
| 上 | 視点（俯瞰／斜め）、移動モード、混雑表示、BIM表示、図面モード、影、ガイドツアー、画像保存 |
| 下中央 | 「▶ 稼働再生」（人とリフトの動き） |

分析基盤パネルを閉じると、右側に従来の評価指標（搬送距離など）とミニマップが出ます。

## 4. 基本操作

| やりたいこと | 操作 |
|---|---|
| 視点を回す／寄る | ドラッグ／ホイール |
| 建屋の内部に入る | 建屋をダブルクリック。または分析基盤の「ライン別」の行をクリック |
| 敷地に戻る | 上部の「← 敷地へ戻る」 |
| 人とリフトを動かす | 「▶ 稼働再生」 |
| 設備の情報を見る | 設備をクリック（分析基盤が設備の表示に切り替わる）。戻るときは「建屋の分析へ戻る」 |
| 設備を動かす | 「移動モード」を押してから設備をドラッグ。動線の距離がその場で再計算される |
| 作業者の目線で歩く | 下の「作業者視点」。WASDで移動、Escで戻る |
| 配置を保存／読込 | 分析基盤を閉じ、右下の「配置を書出」「読込」 |

### 第二ペイント工場だけの操作（分析基盤 →「内部の配置」）

| 切替 | 内容 |
|---|---|
| 初期イメージ（仮配置） | 既定。検討用の仮の配置。設備番号との連動なし |
| 図面 現状（260925） | 図面どおりの設備位置。設備番号で台帳・生産実績と連動 |
| 図面 変更案（260925・未確定） | 変更レイアウト図面どおり。ワニス生産エリア・調色エリアを含む |
| 写真調の質感 | 緑の床・明るい照明・写真に寄せた設備形状に切替（チェックを外すと元の表示） |
| 差分を3Dに重ねる | 図面配置のときだけ。変更案で追加される設備＝緑、消える設備＝橙 |

### ほかの画面

分析基盤の一番下にボタンがあります。

- **実測再生（位置トラッキング）**: 2026/7〜8 の位置実測を時刻ごとに再生。改善案タブで移設先をドラッグして移動時間を試算できる。右上の「仮設備を編集」で3Dへ戻る。
- **実測動線ダッシュボード**: 実測のエリア間移動、移設比較、人員計画の一覧。右上の「従来3Dを開く」で3Dへ戻る。

## 5. 分析できること

「確度」は、実データだけで出しているか、仮定が入っているかの目安です。

| 知りたいこと | 見る場所 | 元データ | 確度 |
|---|---|---|---|
| 月ごとの生産・出荷・在庫の計画と実績 | 全景 → 月次 計画と実績 | 生産出荷在庫トン数 | 高（実績そのまま） |
| ラインごとの生産性（バッチ/日、出来高、kg/人時、収率） | 全景 → ライン別 | 生産データ、日報 | 高 |
| 記録されている作業時間が就業時間の何割か | 全景 → ライン別「記録直接工数/就業」 | 生産データ、日報 | 中（記録の入力率に依存） |
| 部門ごとの出勤・残業・応援の出入り | 全景 → 部門別の人員 | 日報 | 高 |
| **2名削減がどの条件なら成り立つか** | 全景 → 2名削減の原資（試算） | 日報×生産データ（日別） | 中（記録外作業が比例すると仮定。調色は未算入） |
| **ワニス・調色を第二工場へ移すと移動時間がどう変わるか** | 全景 → 建屋間の移動と移設の影響 | 位置トラッキング×人員 | 中（計測は工程ごと4〜7人日。距離は建屋代表点間） |
| 調色の資材置場を移した場合の効果 | 全景 → 調色⇄研究棟を減らせた場合 | 同上 | 中 |
| 調色の補正回数と作業時間の関係 | 全景 → 調色 色補正 | 色補正回数（7日分） | 中（期間が短い） |
| ラインごとの月次推移、充填の標準時間に対する実績 | 建屋内部 → 月次推移 | 生産データ | 高（2Bは標準時間の記録なし） |
| どの設備がよく使われているか | 建屋内部 → 稼働の多い設備 | 生産データ | 高 |
| 設備1台の仕様・導入年・使用バッチ数・主な製品 | 図面配置で設備をクリック | 設備台帳、生産データ | 高（台帳未照合の設備が約3割） |
| 設備間を人が1日に何m歩くか（現状と変更案） | 第二ペイント内部 → 図面 現状と変更案の比較 | 図面、生産データ | 中（設備位置は図面、回数は実績。平面1層で評価） |
| 設備を動かしたら距離がどう変わるか | 移動モードで設備をドラッグ | 同上 | 中 |
| 変更案で行き先が分からない工程 | 第二ペイント内部 → 経路化できないフロー | 図面、生産データ | 高（図面に無い設備を使う実績を列挙） |
| 実測の人の動きを時刻で追う | 実測再生 | 位置トラッキング | 高（通信断・座標飛びは非表示） |

### いま分かっている主な結論

- 移設だけでは移動時間は減らない（1,494分/日 → 1,770分/日）。調色が研究棟へ資材を取りに行く往復が遠くなるため。資材置場も一緒に移せば1,438分/日まで下がる。
- 第二ペイント内の設備の並べ方を変えても、歩く距離はほとんど変わらない（約337m/日 → 約332m/日）。
- 2名削減の原資は、日ごとの仕事量のばらつきにある。工程ごとに1名減らすと忙しい日に足りないが、工程をまたいで融通できれば成り立つ（4工程を兼務できれば、2名減でも不足する日は4%）。
- 2Bとワニスは忙しい日が重ならないので、第二工場への集約には人のやりくりの面で意味がある。

## 6. 足りないデータ

優先度は「移設と2名削減の判断にどれだけ効くか」で付けています。

| 足りないデータ | 無いために出来ていないこと | あれば出来ること | 優先 |
|---|---|---|---|
| 人員の正しい内訳（日報の在籍は計22名、共有コメントは24名で充填10名・調色3名） | 削減の起点が定まらない。充填10名の負荷を正しく見られない | 工程別の余力を正しい人数で出す | 高 |
| 誰がどの工程を担当できるか（スキル表） | 兼務で成り立つという試算が、実際に組めるか確認できない | 兼務の現実的な範囲で不足日を再計算 | 高 |
| 調色の日別の作業記録（生産データに調色のシートが無い。色補正は7日分の経過時間のみ） | 調色を人員試算に入れられない。調色エリアの人の動きは巡回表示のみ | 調色を含めた6工程で試算。調色設備の稼働連動 | 高 |
| 調色が研究棟から取る資材の中身・量・保管条件 | 資材置場を移せるか判断できない | 移設後の移動時間の現実的な見積もり | 高 |
| D-108／T-101〜104 の移設後の行き先（未定） | 2Bで最も多い69バッチ分の動線が変更案で引けない | 行き先の候補を3Dで並べて比較 | 高 |
| 変更レイアウト図面が確定版かどうか | 変更案の評価が暫定 | 確定案として評価 | 中 |
| 第一ペイント・ワニス・調色・倉庫の図面（未入手） | これらの内部は仮配置。設備番号での連動は第二ペイントだけ | 全建屋で設備単位の分析と動線評価 | 中 |
| フォークリフトの荷役記録・入出荷伝票（無いとの回答） | リフトの便数・行き先・順番は仮定。リフト2名の負荷を評価できない | リフト動線と必要台数・人数の検証 | 中 |
| フォークリフト自体の位置実測 | 同上 | リフト経路の実態把握、人との交錯箇所の特定 | 中 |
| 第二ペイントの搬入口・搬出口・原料置場・製品置場の位置 | 荷役点と周辺物は仮置き | リフトと人の動線を実際の位置で評価 | 中 |
| 設備の高さ・架台の高さ・外形寸法 | 立体の見た目は仮定。干渉確認は参考程度 | 高さ方向の干渉確認、2層（架台上下）の動線 | 低 |
| 同じ期間の生産データと位置実測（生産・日報は2025/9〜2026/3、位置実測は2026/7〜8） | 「この日にこの製品を作ったからこう動いた」という日単位の突き合わせができない | 製品・バッチ別の動線分析 | 中 |
| より長い位置実測（現在は工程ごと4〜7人日） | 建屋間移動の回数に個人差・日による差が残る | 移動時間の見積もりの安定化 | 中 |
| 記録外の時間の内訳（段取り・搬送・待ち・洗浄。記録は就業の31〜76%） | 余力の中身が分からない。細目の入力率は10〜37% | どの作業を減らせば何分浮くかの特定 | 中 |
| 2Bの充填の標準時間（記録なし） | 2Bの充填効率を評価できない | 1Bと同じ基準で比較 | 低 |
| 設備の停止・故障・洗浄切替の記録 | 設備稼働率、切替ロスを出せない | ボトルネック設備の特定 | 低 |
| 人件費・移設費用 | 効果を金額で示せない | 投資回収の試算 | 低 |

## 7. 数値を読むときの注意

- **仮定が入っているもの**: リフトの巡回先・便数、第二ペイントの荷役点と周辺物（原料・製品・空缶・ラック・配管）、設備の高さ、図面のない建屋の内部。画面左下の表示と分析基盤の注記に、仮定の範囲を書いています。
- **人とリフトの動き**は、人数（工程人員）と工程の順番は実データですが、個々の経路とタイミングは説明用です。実測の動きは「実測再生」で見てください。
- **不足日**は、各工程の「繁忙日ペース」（1人あたり直接工数の上位10%の日）を基準にした割合です。基準を変えると数字は動きます。
- **期間**が資料ごとに違います（生産・日報 2025/9〜2026/3、位置実測 2026/7〜8、色補正 2026/10）。
- **氏名**は取り込んでいません。担当者は「作業者01」形式の番号です。

## 8. データを更新するとき

1. 元のExcelを `data/raw/` に置く（ファイル名は `pipeline/build_analytics.py` の冒頭を参照）。
2. `python3 pipeline/build_analytics.py` を実行。`data/processed/*.csv` と `src/data/analytics.json` が作り直される。
3. `python3 tools/build.py` を実行。`dist/index.html` ができる。

`data/raw/` は氏名を含むためGitに入れていません。

## 9. 既知の制約

- 人どうし、人とリフトのすれ違いは考慮していません（重なって通ることがあります）。
- リフトは常に前進で、バックでの出し入れはしません。
- 第二ペイントの動線は平面1層で評価しており、架台の上り下りは距離に入っていません。
- 第二ペイントの図面配置では、設備の密集部で4〜5本の経路が「到達不可」になります（通路幅の判定によるもの）。
- 実測再生の「直接工数」合計は、調色が未入力のため表示されません。工程別の負荷は出ます。
