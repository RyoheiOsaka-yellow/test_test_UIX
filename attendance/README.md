# GO！ALL！GOAL！プロジェクト（アスルクラロ沼津）

`index.html` 1枚で完結するページです。ビルド不要、そのままブラウザで開けます。

プロジェクト名は `PROJECT` で一括設定しています。
ここを変えると、見出し・タイトル・シェア本文・フッターがまとめて変わります。

```js
const PROJECT = {
  name:   "GO！ALL！GOAL！プロジェクト",
  short:  "GO！ALL！GOAL！",   // シェア本文のハッシュタグに使われます
  season: "2026 SEASON"
};
```

## このページの考え方

**来場 → 勝ち点 → 優勝** を1本の線でつないでいます。
「たくさん来てほしい」ではなく「あと何人来れば優勝に届くのか」を
数字で見せることで、来場の理由をつくるのが狙いです。

## 数字の更新

`index.html` 内の `const SEASON = { ... }` だけを書き換えてください。

- `league` … 優勝ラインの勝ち点と、アウェイ戦の成績
- `matches` … 全ホームゲームの配列。`attendance` と `result` を入れる
  - `result` は `"W"`（勝ち3点）/ `"D"`（分け1点）/ `"L"`（負け0点）
- `goals` … 来場者数の目標ライン（3万 / 4.5万 / 5万）

### `league` について

```js
league: {
  goalName:      "優勝",  // 「昇格」などに変えると、ページ全体の表記が変わります
  goalPoints:    48,      // 優勝ラインの想定勝ち点 ← 必ず実際の想定値に
  awayPlayed:    10,      // 消化したアウェイ戦数
  awayPoints:    13,      // アウェイで積んだ勝ち点
  awayRemaining: 5        // 残りのアウェイ戦数
}
```

ホームの勝ち点は `matches` の `result` から自動計算し、
`awayPoints` を足したものが通算勝ち点になります。

**`goalPoints` は必ず見直してください。** 現在の 48 はダミーデータで
「届きそうで届かない」状態をつくるための値です。実際に達成不可能な値
（残り全勝でも足りない値）を入れると、ページが「—」表示になります。

## 来場と勝ち点の結びつけ方

2か所で計算しています。どちらも `matches` の実データから出しています。

1. **帯別の平均勝ち点** … ホームゲームを来場者数の中央値で2つに分け、
   それぞれの1試合あたり平均勝ち点を比べます
2. **シミュレーター** … 来場者数と勝ち点の関係を最小二乗法で直線にあてはめ、
   残りホームの平均来場者数から最終勝ち点の目安を出します

### 数字の扱いについて（重要）

- **これは相関であって、因果ではありません。** ページにも
  「来場者数だけで結果が決まるわけではありません」と明記しています。
  ここは消さないでください
- 実データで関係が見られなかった場合（傾きがマイナス、または差がほぼ無い場合）は、
  **自動的に文言が変わり**、「まだ結びつきは見えていません」と正直に表示します。
  都合のいい断定は出ません
- 見積もりは、**実際にあった来場者数の範囲の外へは伸ばしません**。
  伸ばすと「◯人入れば全勝できる」に近い話になり、根拠が無くなるためです

### シーズン中の更新のしかた

**これから開催する試合は `attendance: null, result: null` にしておいてください。**
試合が終わるたびに、その2つを書き込むだけで済みます。

```js
// 終わった試合
{ round: 21, date: "8/9", vs: "K FC", attendance: 3180, result: "W" },
// まだの試合
{ round: 23, date: "8/23", vs: "L FC", attendance: null, result: null },
```

`null` が1つでもあると、消化した試合数を**自動で判定**します
（`PLAYED` を手で直す必要はありません）。累計来場者数・勝ち点・順位表への距離・
次のホームゲーム・シミュレーターまで、すべて連動して更新されます。

`DEMO_PRESETS` と、ページ下部の「【デモ用】」ブロックは公開時に削除してください。
いまはダミーデータが全試合ぶん埋まっているため、デモ表示（10試合終了）になっています。

### 対戦相手のロゴ

`matches` に `logo` を足すとロゴが表示されます（省略可）。

```js
{ round: 1, date: "3/8", vs: "A FC", attendance: 3412, result: "W",
  logo: "assets/opponents/a-fc.svg" }
```

- 表・次のホームゲーム・グラフのツールチップに出ます
- **書かない試合はチーム名の頭文字バッジ**になります。全チーム分そろっていなくても崩れません
- 画像が見つからなかった場合も、自動で頭文字バッジに切り替わります
- 詳しくは `assets/opponents/README.md` を参照してください

## 公開前に必ず埋めるところ

### 1. リンク先（`LINKS`）

```js
const LINKS = { ticket:"", access:"", official:"" };
```

空のままだと、ボタンが「チケットを買う（URL未設定）」という
押せない灰色の表示になります（気づかず公開してしまわないための状態です）。

### 2. SNSカード（OGP）

`<head>` の `REPLACE-WITH-YOUR-DOMAIN` を公開ドメインに差し替えてください。
**`og:image` と `og:url` は絶対URLでないと X／Facebook が画像を取得できません。**
クローラーは JavaScript を実行しないので、ここだけは静的に書く必要があります。

カード画像は `assets/og.png`（1200×630）です。
**あえて来場者数を入れていません。** 数字を焼き込むと、更新のたびに
画像を作り直さないと古い数字が出回ってしまうためです。
節目のタイミングで「3万人突破」版に差し替える運用は問題ありません。

### 3. ハッシュタグ（`SHARE.tags`）

```js
const SHARE = { url:"", tags:["アスルクラロ沼津"] };
```

キャンペーンタグが決まったら 2つ目に足してください。
`url` は空ならページ自身のURLを使います。

## シェアの動き

投稿先ごとにボタンを分けています（X／LINE／Facebook／コピー）。
PCのブラウザには OS の共有シートが無いことが多く、それ頼みだと
「押しても何も起きない」状態になるためです。

| ボタン | 挙動 | 公開URL |
|---|---|---|
| Xに投稿 | 投稿画面が開き、本文とURLが入った状態になる | 無くても可 |
| LINEで送る | 送信先を選ぶ画面が開く | **必須** |
| Facebook | シェア画面が開く。文言はOGPから拾われる | **必須** |
| 文章をコピー | 本文をクリップボードへ（Instagram など貼り付け用） | 無くても可 |
| 他のアプリで共有 | OS の共有シート。**対応端末でのみ表示** | 無くても可 |

LINE と Facebook は仕様上URLが無いと成立しないため、
公開URLが未設定のうちはグレー表示（押しても案内が出るだけ）になります。
`file://` で直接開いた場合も同じ扱いです。**サーバーに置くと自動で有効**になります。

X は URL パラメータで画像を添付できません。
投稿に出る画像は、リンクが展開されたときの **OGPカードが担当**します。
そのため 2. の絶対URL設定を済ませないと、投稿が味気ない見た目になります。

なお各社ともロゴの使い方にガイドラインがあります。対外的に出す前に、
ボタンの意匠が各サービスの規定に沿っているかご確認ください。

## 「あなたが埋めたマス」

行った試合を選ぶと、その試合で埋まったマスがグリッド上で光り、
「合計何人の場にいたか／全体の何%か」が出ます。シェア文にも反映されます。

選択内容は `localStorage`（キー `acn26_mine`）にのみ保存され、
サーバーには送信しません。バックエンド不要で動きます。

## ロゴ・マスコット

いただいた Illustrator データからパスを起こして SVG 化しています。
`index.html` にはインラインで収録済み（外部画像の読み込みなし）なので、
HTML 1枚だけで完結します。

| ID | 内容 | 掲出箇所 |
|---|---|---|
| `#ac-emblem` | エンブレム（盾マーク） | 左上のクラブバー / 盤面の左上 / フッター |
| `#ac-wordmark` | ロゴタイプ「azul claro」 | 左上のクラブバー |
| `#ac-mascot` | アスルくん（正面） | 盤面の背景 / ひとことエリア / フッターの背景 |

別ファイルとしても `assets/` に置いてあります（他媒体での再利用用）。

```html
<svg><use href="#ac-emblem"/></svg>
```

### 元データについて

いただいた 2つの `.ai` は「PDF 互換ファイルを作成」を外して保存されていたため、
PDF として開くと Illustrator の注意書きしか表示されません。
実データは以下のとおり `.ai` 内部の非公開ストリームに入っていたので、
そこから展開してパス化しました。

- `_130222_azul_claro_logo.ai` … `%AI12_CompressedData`（zlib 圧縮）
- `azul_last_black.ai` … `%AI24_ZStandard_Data`（zstd 圧縮）

ロゴの `.ai` はガイドライン台紙（4C 版 / BK 版 / 色指定 / 版ごとの見本）だったため、
そのうち 4C のエンブレムとロゴタイプだけを切り出しています。
マスコットの `.ai` は正面・背面の 2 図だったため、正面のみを使用しています。

色は CMYK 指定だったので、ジャパンカラー相当のインキ原色を使った
減法混色で sRGB に変換しています（例: DIC 179s → `#00A0E9`、DIC 222s → `#001886`）。
BK 版のエンブレム・ロゴタイプが必要になった場合は、元データから同様に切り出せます。

## 動作について

- 盤面の下に「来場 → ホームの勝ち点 → 優勝まで」の連動表示があります
- グラフの濃い部分は、試合結果（勝ち／分け／負け）で色分けしています
- カウンター・マス・グラフは、それぞれ**画面に入った時点で**動き出します
  （先に全部動かすと、スクロールして着いた頃には終わっているため）
- 目標ラインを越えた瞬間、アスルくんが跳ねます
- グラフは棒にカーソルを乗せる／フォーカスすると内訳が出ます（キーボード操作可）
- `prefers-reduced-motion: reduce` の環境ではアニメーションを止めます
- 来場者数は**パタパタとめくれる**表示です。桁が変わるたびに1枚ずつめくれ、
  上半分に影が落ちます。数字は常に整数位置に置いているので、
  動いている途中でも中途半端な位置には止まりません
- 桁の位置は CSS 変数 `--dh` を基準にしているため、画面幅が変わっても自動で追従します
- 数字の桁は、動き終わったあと必ず実数とぴったり一致する位置で止まります
- 読み上げは、カウントアップ中ではなく確定値だけを1回読みます

## まだ手を付けていない案

- **来場者の声の投稿**：バックエンドか外部フォームが要ります
- **節目の自動お知らせ**：3万人突破時に自動投稿するなら、更新の仕組みとセットで
- **数字入りOGP画像**：更新のたびに画像生成が必要なので、動的生成の仕組みが前提

Chromium で デスクトップ（1280px）／モバイル（390px）× 通常／`reduced-motion`
の4通り。JSエラーなし、横スクロールなし、カウンター表示が実数と一致することを確認。
