# ちれきくん

指定調査機関向けの、地歴調査報告書の作成支援。資料（登記簿謄本・公図・住宅地図・空中写真・聴取記録・過去の報告書）を共有すると、エコ・テック様の報告書と同じ章立てで下書きを組み、根拠ページと公式出典を付けて出力します。

`index.html` を開くだけで動きます（1ファイル。ビルド済み）。

## デモ

入力せずに一連の流れを見せるための仕組みが2つあります。

- **デモを再生する**（ログイン画面、案件一覧）：ログイン → 新しい調査 → 対象地・目的・資料の入力 → 作成 → レポート → 確認・判断・出典 までを、字幕つきで自動で進めます。約70秒。途中で「停止」できます。`index.html#demo` で開くと最初から再生します。
- **入力例を入れる**（新しい調査の画面）：対象地・要望・資料9点をまとめて入れます。あとは「レポートを作成する」を押すだけです。

デモ用の資料は、川崎市川崎区貝塚一丁目の既往報告書を資料の種類ごと（登記簿、法人登記、公図、地図、空中写真、聴取記録、踏査写真、行政回答、調査メモ）に分けたものです。AIの読み取り結果に当たる部分だけ記録済みのデータを使い、結合・判定・所見・描画は本番と同じ処理を通します（`src/demo.js`）。

### デモ②：資料のない土地（既往の報告書が無い場合）

ログイン画面・案件一覧の「デモ② 資料なし」（または `index.html#demo2`）。名古屋市熱田区の土地を、資料を1点も入れずに作成します。記録済みのデータは使いません。

- その場で取得するもの（公開データ）：位置図（地理院地図）、治水地形分類図、標高からの地下水流向の推定、年代別の空中写真8年代（国土地理院 地理院タイル。整備の無い年代はその旨を表示）、適用する法令・条例と条項の判定、行政の照会窓口
- 取得できないもの：本文に色分けした枠で出し、取得先と、共有すると報告書のどこが埋まるかを添えます。表の中の未確認・未取得・判読前も同じ色です
  - 青＝有料の資料：登記簿謄本（地目・所有者を含む）、公図、住宅地図
  - 緑＝APIで取得できる：地形・地質の記述、指定区域の有無（未対応の自治体）、自然由来・埋立の情報、年次表の「判読前」
  - 赤＝人の作業：ヒアリング、現地踏査、特定施設の届出（行政への照会）、調査期間の記入、台帳で拾った指定区域の位置関係の確認、AI判読案の採用
  - 灰色：その年代の地形図・写真が存在しない
- 表紙に「下書き　未取得 N件」と色ごとの件数・凡例の札、紙面の上に未取得の一覧（押すと該当箇所へ）。色つきの枠は確認用のPDFにも出ます
- 登記簿と住宅地図・地形図がどちらも無いときは、所見を「保留」にします（根拠なしに「低い」と書かない）
- 資料を「資料」タブに入れると、該当する枠が消えて表と所見が組み上がります

### 保存・プレビュー・共有・印刷

- 保存：編集のたびに自動保存します。右上の「保存」を押すと、その時点の内容を版として残し、「資料」タブの「保存した版」から直前5版まで戻せます。「この案件をファイルに保存」で案件を1つのファイルに書き出し、案件一覧の「ファイルから開く」で読み込めます（別の端末への受け渡し、バックアップ用）。保存先はこの端末のブラウザです
- プレビュー：「プレビュー」で、紙面だけの閲覧用の画面になります（編集不可）。確認用／提出用を切り替えて見られます
- 共有：プレビューの「共有リンクをコピー」で、案件の内容を圧縮して入れたURLを作ります。開いた人には、まずログイン画面が出て、ログイン後にプレビューを見て印刷できます。内容はURLの「#」以降に入っており、サーバーには送られません（サーバー側の保存は不要）。リンクを知っている人は誰でも開けるので、登記名義人などを含む案件では送り先に注意してください。`index.html` をWebに置いた状態で使います（端末のファイルとして開いていると、他の人の端末では開けません）。リンクは数KB〜数十KBになります
- 印刷：編集画面の「PDFで出力」、プレビューの「PDFとして印刷」で、ブラウザの印刷画面が開きます。送信先に「PDFに保存」を選ぶと、画面と同じページ割りのPDFになります
- 確認：`node tests/share.js index.html <出力先>`

### 出典の等級

出典を4段階に分け、付録の出典一覧に表示します。

1. 公式：法令、自治体の公表、国土地理院、登記簿、行政回答
2. 公的資料の転載：旧版地形図の閲覧サイトなど（原本は公的資料）
3. 民間・Web
4. AIの推定：地形図・写真の判読案、文章の下書き

所見の根拠に使うのは、等級1・2と、担当者が採用した等級3です。等級4は、担当者が採用するまで利用履歴・所見に使いません。

### 旧版地形図（今昔マップ on the web）

位置が決まると、対象地が「今昔マップ on the web」（埼玉大学教育学部 谷謙二・人文地理学研究室。国土地理院発行の旧版地形図を複製したタイル）の収録範囲に入るかを確かめ、入る場合は明治・大正からの各時期の地形図を、空中写真と合わせて年代順に 2.3 の表と図に載せます（等級2）。AIが接続されていれば、空中写真と同じ要領で用途を下読みします。

- 収録は首都圏・中京圏・京阪神圏など15地域を登録（`src/engine.js` の `KJ_SETS`。時期は同サイトの公開一覧による）。範囲外の土地は空中写真だけになります
- 同サイトの利用条件に従い、図の脚注・表・出典一覧に「今昔マップ on the web」と表示しています。一般公開する場合は、同サイトの案内に沿って連絡してください

### 出力の種類（確認用／提出用）

案件画面の右上で切り替えます。PDF・Wordの両方に効きます。

- 確認用：色つきの枠（未取得の注記）、表紙の下書きの札、付録を付けて出力
- 提出用：色つきの枠・下書きの札・仮の文言・付録を外して出力。色つきの「未確認」は黒字に戻します。未取得の項目が残っている場合は、切り替え時に件数を知らせます

### 空中写真のAI下読み

住宅地図・地形図が無い案件で、国土地理院の年代別空中写真（対象地を中心にした一辺約500mの画像）をAIが読み、対象地と周辺の用途の「判読案」を 2.3 の表に入れます。AIが接続されていれば作成時に自動で走り、紙面の「AIで下読みする」からも実行できます。

- 判読案には「AI判読案」の札と確からしさ（高・中・低）が付きます。業種は写真から断定しない指示にしています
- 「判読案を利用履歴表に採用する」を押すと、通常の年次表になり、文言を直せます。採用するまで、利用履歴・懸念の抽出には使いません
- 空中写真だけでは所見を出しません（登記簿か住宅地図・地形図が入るまで「保留」）
- 確認：`node tests/photo-ai.js index.html <出力先>` は模擬応答での動作確認。`--live` を付けると環境変数 `ANTHROPIC_API_KEY` で実際に送信します（実送信での確認は未実施）

### 指定区域の公表台帳との自動照合（東京都・名古屋市）

自治体が公表している区域の一覧を公式ページから取得し、対象地と照合します。

- 取得：`pip install openpyxl pdfplumber` のうえ `python3 tools/fetch_zones.py`。`registry/zones.json` ができ、`python3 build.py` で台帳を埋め込んだ `index.local.html` が別に作られます（`index.html` には入りません）。Webで配信する場合は、`index.html` と同じ場所に `registry/zones.json` を置くと起動時に読み込みます。一覧のファイル名は更新のたびに変わるので、毎回、公式ページのリンクから読み取ります
  - 東京都環境局「東京都が指定する要措置区域等一覧」（Excel）：要措置区域、形質変更時要届出区域
  - 名古屋市環境局「土壌汚染に係る区域一覧」（PDF）：法の区域と条例の区域。取り消し線の付いた変更前の記載とふりがなを除き、解除区域・除去済み特例区域は外して読みます
- 照合：対象地と同じ町丁目の区域、および町丁目の代表点どうしで1.5km以内の区域を拾います（1.0km圏の判定に、町丁目の広がり分の余裕を加えた範囲）。該当が無ければ 1.1 と 2.4.3 に「なし」、あれば「要確認（同じ町丁目に2件）」のように入れ、2.4.3 に該当区域の表（種類・町丁目・指定番号・指定年月日）と照合方法の注記を出します。人や行政回答が入れた値は上書きしません
- 「確認」タブに、提出前に公表ページで最新を確認する旨（該当ありの場合は台帳の図面で区域との位置関係を確認する旨）を出します
- 限界：照合は町丁目単位です（東京都の一覧には地番がありません。名古屋市の地番は区域指定時のもので「◯番の一部」が大半）。対象地が区域に含まれるかは、台帳の図面で人が確認します。東京都の一覧に八王子市・町田市は含まれず、解除済みの区域は載りません。名古屋市の条例附則によるみなし区域は一覧に載っていません。東京都条例第118条の2の台帳一覧は未対応です
- 取り扱い：両自治体ともサイト掲載情報の複製・二次利用に条件があるため、`registry/zones.json` と取得ファイルはリポジトリに含めていません（`.gitignore`）。保持するのは区域の種類・町丁目・指定番号・指定年月日のみです。本番で使う前に、各自治体の担当課に利用条件を確認してください
- 確認：`node tests/zones.js index.html <出力先>`

## 操作マニュアル

`manual.html` が利用者向けの操作マニュアルです（画面の写真つき、1ファイル。ブラウザの印刷でPDFにできます）。アプリの上の帯の「マニュアル」と、ログイン画面のリンクから開きます。`index.html` と同じ場所に置いてください。

- 原稿は `manual/manual.src.html`。`node tools/make_manual.js` で、実際の画面を撮影して埋め込み、`manual.html` を作り直します。画面を変えたら作り直してください

## 画面

| 画面 | 役割 |
|---|---|
| ログイン | メールアドレスとパスワード。試作版は認証サーバー未接続で、「デモ用アカウントで入る」でも入れます |
| 案件 | 案件ごとに、自治体・照合する条例・所見・確認が必要な件数を一覧 |
| 新しい調査を始める | ①対象地（所在・地番・面積、地図でピンを動かして番地に合わせる）②目的と条件（自由記入）③資料を共有 → 「レポートを作成する」 |
| レポート | 左＝目次、中央＝紙面（直接編集可）、右＝確認／判断／出典／資料。PDF出力・Word保存 |
| 法令・条例 | 国の法令と地域の条例の登録内容。条文の原文引用・出典URL・確認日つき |

## レポートの中身

章立てと紙面の体裁は、既往報告書8通（Drive「エコテック地歴調査報告書」）に合わせています。

- 表紙、目次（点線とページ番号、【添付資料】の表）
- 1 調査概要（1.1〜1.7）
- 2 履歴調査（2.1 地形・地質・地下水／2.2 登記簿：土地・地番の変遷図・建物・法人／2.3 地図・空中写真／2.4 ヒアリング・現地踏査・公的機関の環境情報）
- 3 結果まとめ（所見）
- 所見が「否定できない」のとき：4 試料採取等対象物質の選定（表4 指定基準つき）／5 汚染のおそれの由来に応じた区分／6 土壌汚染のおそれの区分の分類
- 付録（原本にない、本システムの部分）：適用条項の判定（法3条・4条・5条・14条・6/11条と、地域の条例の各条が該当するか）／対象物質の選定根拠／出典一覧
- 添付資料の扉

紙面の体裁（原本の実測に合わせたもの）

- A4のページ単位。余白は上17mm・左30mm・右20mm、本文はゴシック10.5pt、表は8pt。右下にページ番号、ページ下に脚注（「添付資料(一般)A「登記簿謄本」を参照。」の書き方）
- 見出しは太字にせず字下げで階層を示す。1.1 の表、筆の一覧（合計欄の斜線）、登記簿の表（地積の結合、分筆行の横結合、現状地番の切り替え）、2.3 の年次表、所見の枠、表4（調査対象物質の○、含有量基準なしの斜線）を原本の罫線で組む
- 1ページに収まらない内容は、表や段落の切れ目で次のページへ送り、ページ番号と目次を振り直す（`paginate`）。「PDFで出力」は画面と同じページ割りで出る
- 書体は BIZ UDゴシック（Webフォント）を先頭に、MS ゴシックを次に指定。Word保存は MS ゴシック指定

見出しや脚注の横に「原本 p.7」「p.22–85」のような小さな札が付きます（画面のみ。印刷・Wordには出ません）。原本PDFを「資料」タブに入れると、札を押してそのページを表示できます。

## 人が見るのは「確認」だけ

右の「確認」には、次のものだけを出します。

- 判読が不明瞭な名義人、筆によって食い違う日付
- 資料どうしの矛盾（例：ヒアリングと地図・登記が合わない）
- 原本との差（誤記と判断して直した箇所、古い法令の引用）
- 未記入の項目（行政照会、条例の台帳確認、ヒアリング）
- 公式資料・社内実績の登録がなく、物質を自動で選べなかった業種

「判断」では、懸念として扱う利用履歴・対象物質・筆ごとの区分・条例の確認結果を切り替えると、所見と4〜6章を組み直します。

## 出典の扱い

- 法令・条例は **公式サイトで条文を確認できたものだけ**「公式出典で確認」と表示します（e-Gov法令検索、環境省、自治体の例規集・公式ページ）。確認できていない条項は判定表に「出典未確認」と出ます。
- 調査結果の原本は `registry/research/*.json`（URL・ページ題名・確認日・原文引用つき）。`tools/make_registry.py` がアプリ用の `registry/{laws,ordinances,industry}.json` に変換し、`build.py` が `index.html` に埋め込みます。
- 業種→特定有害物質は2種類の根拠を区別します：**社内実績**（既往報告書での選定）と **環境省の公表統計**（「土壌汚染対策法の施行状況及び土壌汚染調査・対策事例等に関する調査結果」表3-3・表3-13）。どちらも無い業種は自動選定しません。

## 資料の読み取り（AI）

資料1点ごとに Claude API を呼び、「案件データの部分」を同じJSON形で返させて結合します（`src/ai.js`）。各行にページ番号を付けさせ、判読に自信がない名義人は `unclear` で返させます。

接続は2通りです。

1. **サーバー経由**（本番向け）：`netlify/functions/claude.mjs` が中継。APIキーは Netlify の環境変数 `ANTHROPIC_API_KEY`。利用者の画面にキーは出ません。
2. **設定画面でキーを登録**（試用向け）：ブラウザから直接呼びます。

未接続でも、サンプル4件の表示、章立ての作成、法令・条例の判定、地下水流向の推定（標高）は動きます。

## 開発

```
python3 tools/make_registry.py   # registry/research → registry/*.json
python3 build.py                 # src/ + registry/ → index.html
```

- `src/data.js` 26物質と指定基準、業種→物質、目的
- `src/samples.js` サンプル4件（葛飾区金町・川崎市貝塚・東住吉区駒川・渋谷区西原）
- `src/engine.js` 適用条項の判定、懸念の抽出、所見、確認項目、出典一覧
- `src/report.js` 紙面の描画
- `src/ai.js` 読み取り・結合・地下水流向の推定
- `src/demo.js` デモの台本と入力例
- `src/ui.js` 画面
- `tools/fetch_zones.py` 指定区域の公表台帳の取得（東京都・名古屋市）
- `tests/share.js` 保存・プレビュー・共有リンク・印刷の確認
- `tests/` 再現テスト（`node tests/demo.js index.html`、`node tests/demo2.js index.html <出力先>`、`node tests/review-regression.js index.html`）、紙面の確認（`node tests/paper.js index.html s-kanamachi <出力先>`：各ページの画像と印刷用PDFを出し、はみ出しとページ数を表示）
- `screening.html` 以前の地図・年代別空中写真・CSV取込の試作（単体で動作）

## 未対応・制約

- AI読み取りは、この環境にAPIキーが無く実PDFでは未実走です。結合〜所見の組み立ては模擬データで確認済み。
- 地下水流向は標高からの方向推定のみ。到達距離の計算（物質・地層・透水係数）は、計算ツールの資料を受領後に組み込みます。
- 地番図（図1.7-2）と区分図（図6.3.x）は公図が元のため差し込み枠のみ。位置図は地理院地図（原本はゼンリン地図）、図2.1 は治水地形分類図のみで凡例は付けていません。表紙のロゴは未掲載。
- 行の結合がある表（登記簿）が1ページを超える場合は、表の途中では分けず、そのページが長くなります。
- Netlify Functions は要求本文6MBまで。大きなスキャンPDFは、Files API を使うサーバー構成に変える必要があります。
- 認証・案件の保存はブラウザ内のみ（基幹システム連携は案件JSONの入出力を足場にする想定）。
