| 略語 | 正式名称 | 意味 |

## 1. 目的とスコープ

### 1.1 目的

歯科医院のチェアサイドで、**術者が入力した所見（う蝕・欠損・修復物・歯周状態）を 3D 口腔モデル上に可視化し、患者へ説明する**ためのツール。

参照画像（顎模型 / typodont）が示すとおり、従来は物理模型＋手書き歯式で説明していた工程を、患者個別データを反映した 3D で置き換える。

### 1.2 スコープ内（V1）

- 上下顎 32 歯 + 歯肉 + 歯根 + 歯槽骨（半透明）の 3D 表示
- 歯単位 / **歯面単位（5面）** のピッキングと色分け
- 術者手入力による所見データの読み込み・保存（JSON / DB）
- う蝕深度（C0〜C4）、修復物、欠損、インプラントの可視化
- 歯周ポケット 6点法チャートの 3D 重畳
- 治療前 / 治療後（プラン）のビフォーアフター切替
- 患者説明モード（用語を平易化、UI を簡素化）

### 1.3 スコープ外（V1では実装しない）

- **画像からの自動う蝕検出・自動診断**（→ §2 の理由により意図的に除外）
- CBCT / DICOM の 3D 再構成
- 矯正シミュレーション、補綴 CAD 設計
- レセプト・電子カルテ本体機能（既存システムとの連携に留める）

## 2. 法規上の位置づけ（設計制約）

> ⚠ 以下は設計方針であり法的助言ではない。上市前に薬事の専門家・所轄部門の確認を必須とする。

- 本ツールは **「術者が確定した所見を可視化・説明するための表示ツール」** として設計する。診断そのものを行わない。
- **自動でう蝕を検出・重症度を判定する機能を入れた瞬間に、プログラム医療機器（SaMD）該当性の議論が発生する。** V1 では入力を「術者の手入力」に限定し、AI 判定は将来の別トラック（薬事対応込み）とする。
- UI に「本表示は説明用であり、診断結果を代替するものではありません」の常設表記を置く。
- 患者情報は個人情報保護法および厚労省「医療情報システムの安全管理に関するガイドライン」に準拠。**HTML 単体ファイルに患者データを埋め込んで配布しない**（§8.3 参照）。

## 3. 歯式・歯面のデータモデル

### 3.1 歯番（FDI を内部正とする）

内部表現は **FDI 2桁 (integer)** に統一。表示は設定で Palmer / Universal に切替可能。

```
上顎右          上顎左
18 17 16 15 14 13 12 11 | 21 22 23 24 25 26 27 28
48 47 46 45 44 43 42 41 | 31 32 33 34 35 36 37 38
下顎右          下顎左
```

乳歯: 55–51 / 61–65 / 85–81 / 71–75（小児対応時に有効化）

象限: 1=上右, 2=上左, 3=下左, 4=下右（永久歯） / 5,6,7,8（乳歯）

### 3.2 歯面（5面 + 歯頸部）

う蝕記録の最小単位は **歯面**。1歯あたり 5面を定義する。

| コード | 名称 | 英名 | 適用 |
|---|---|---|---|
| `M` | 近心面 | Mesial | 全歯 |
| `D` | 遠心面 | Distal | 全歯 |
| `B` | 頬側面 / 唇側面 | Buccal / Facial | 全歯 |
| `L` | 舌側面 / 口蓋側面 | Lingual / Palatal | 全歯 |
| `O` | 咬合面 | Occlusal | 臼歯・小臼歯 |
| `I` | 切縁 | Incisal | 前歯（`O` の別名として扱う） |
| `C` | 歯頸部 | Cervical | 修飾子（B/L/M/D と併用） |

歯面集合は文字列で表現（例: `"MOD"`, `"BO"`）。DB では正規化して1行1面。

### 3.3 う蝕分類

2系統を併記できる構造にする。

**日本の慣用（主表示）**

| コード | 内容 | 標準色 |
|---|---|---|
| `SOUND` | 健全 | `#F2EDE4` |
| `CO` | 要観察歯 | `#FFF3B0` |
| `C1` | エナメル質う蝕 | `#FFD166` |
| `C2` | 象牙質う蝕 | `#F3722C` |
| `C3` | 歯髄に到達 | `#D62828` |
| `C4` | 残根状態 | `#6A040F` |

**ICDAS II（副表示・研究用）**: `0`–`6` を `icdas` フィールドに保持。

**窩洞分類（Black）**: `I`–`VI` を `cavity_class` に保持（修復設計の説明用）。

### 3.4 歯の状態（tooth-level status）

`SOUND` / `CARIES` / `RESTORED` / `CROWN` / `BRIDGE_PONTIC` / `BRIDGE_ABUTMENT` / `ROOT_CANAL_TREATED` / `IMPLANT` / `MISSING` / `UNERUPTED` / `IMPACTED` / `RETAINED_ROOT`

### 3.5 修復物・補綴物の材質

`CR`（コンポジットレジン）/ `IN_METAL`（メタルインレー）/ `IN_CERAMIC` / `FMC` / `PFM`（陶材焼付） / `FULL_ZIRCONIA` / `HJC`（硬質レジン前装冠）/ `DENTURE_CLASP` 等。

### 3.6 歯周データ（6点法）

1歯あたり計測点 6（頬側 MB/B/DB、舌側 ML/L/DL）。

| フィールド | 型 | 説明 |
|---|---|---|
| `pd` | int (1–12) | プロービング深さ mm |
| `gm` | int (-5–10) | 歯肉辺縁位置（CEJ基準）mm |
| `cal` | int | `pd + gm`（導出値） |
| `bop` | bool | 出血 |
| `pus` | bool | 排膿 |
| `plaque` | bool | プラーク付着 |

歯単位: `mobility`（Miller 0–3）、`furcation`（Lindhe 0–3、臼歯のみ）。

## 4. 3Dアセット仕様

### 4.1 座標系（**最重要・ここを間違えると全部ズレる**）

- 単位: **mm**
- 右手系、**Y-up**（Three.js 標準）
- 原点: 正中矢状面 × 咬合平面 × 上顎中切歯唇面接線 の交点
- `+X` = 患者の左方向 / `+Y` = 頭頂方向 / `+Z` = 顔面前方（患者の正面）
- 正面ビューのカメラは `+Z` 側から `-Z` 方向を見る

> ⚠ **落とし穴**: IOS（口腔内スキャナ）の STL は Z-up かつ原点がバラバラで出力される。取り込み時に必ず正規化パス（§6.3）を通すこと。既存の PLATEAU 系ワークフローと同じく「外部データの軸順は必ず疑う」。

### 4.2 メッシュ構成

```
root (Scene)
├─ maxilla                 上顎グループ
│  ├─ tooth_11 … tooth_18
│  ├─ tooth_21 … tooth_28
│  ├─ gingiva_upper
│  └─ bone_upper           （半透明、既定 OFF）
├─ mandible                下顎グループ（開口アニメーションはここを回転）
│  ├─ tooth_31 … tooth_48
│  ├─ gingiva_lower
│  └─ bone_lower
└─ overlays                所見・注記レイヤ（動的生成）
```

**1歯 = 1メッシュ**（`tooth_<FDI>`）。歯冠と歯根を1メッシュに含め、頂点属性で区別する。

### 4.3 ノード命名規則

| 対象 | 名前 |
|---|---|
| 歯 | `tooth_11` … `tooth_48`（乳歯 `tooth_51` …） |
| 歯肉 | `gingiva_upper` / `gingiva_lower` |
| 歯槽骨 | `bone_upper` / `bone_lower` |
| 所見オーバーレイ | `finding_<FDI>_<SURFACE>_<idx>` |

### 4.4 ポリゴン予算

| 対象 | 目標 tri 数 |
|---|---|
| 歯 1本（歯冠+歯根） | 4,000 – 8,000 |
| 歯 32本 合計 | 130k – 250k |
| 歯肉（上下） | 30k |
| 歯槽骨（上下） | 40k |
| **合計** | **≤ 320k tri** |

Draco 圧縮（`glTF-Pipeline`）で GLB 化。目標ファイルサイズ **≤ 12MB**。

> ⚠ **落とし穴**: Draco デコード後は頂点が重複する。トポロジ操作（法線再計算、歯面セグメンテーション）を行う場合は必ず weld（マージ）を先に実行する。

### 4.5 glTF 拡張メタデータ

各 `tooth_*` ノードの `extras` に以下を格納。**歯面判定に必須**。

```json
{
  "fdi": 16,
  "type": "U6",
  "jaw": "U",
  "quadrant": 1,
  "roots": 3,
  "axis_occlusal": [-0.102932, -0.994522, 0.018199],
  "axis_buccal":   [-0.979332,  0.104528, 0.173154],
  "axis_mesial":   [ 0.174108,  0.0,      0.984727],
  "centroid":      [-25.714, 10.243, -1.882],
  "cej_h": 3.05,
  "crown_top_h": 10.55,
  "apex_h": -9.95,
  "cej_y": 7.75,
  "crown_h": 7.5, "root_l": 13.0,
  "md_width": 10.0, "bl_width": 11.0,
  "bone_level_mm": 2.0
}
```

- 3軸は**正規直交化して3本とも明示的に格納する**。
  `mesial = occlusal × buccal` で導出しない — **左右の歯は互いに鏡像であり、基底の
  行列式の符号が左右で反転する**ため、外積による導出は片側で向きが逆になる。
- `cej_h` / `crown_top_h` / `apex_h` は **centroid から `axis_occlusal` 方向に測った符号付き距離**。
  歯面判定（§5.1）が直接使うのはこの3値。`cej_y` はワールド Y 座標（参考値）。
- `bone_level_mm` は CEJ から根尖方向への歯槽骨頂の距離。骨吸収の可視化に使う（§4.8）。
- 生成は Blender スクリプト（購入モデル）または `dental_arch_gen.py`（暫定モデル）で自動化。

| 案 | 内容 | コスト | 精度 | ライセンス |

### 4.7 暫定ジオメトリ戦略（購入前に開発を止めない）

購入モデルの選定・レビューには時間がかかるため、**同じ契約（命名規約 + `extras` メタデータ）を満たすプロシージャル生成の暫定歯列**を先に作り、ビューア開発を並走させる。

- 生成方法: 歯種ごとのパラメトリック形状（切歯=箆状、犬歯=尖頭、小臼歯=2咬頭、大臼歯=4咬頭）＋歯根（単根/2根/3根）を lathe + loft で生成
- 歯列弓は Beta 関数近似のアーチカーブ上に配置、各歯の傾斜角（近遠心・頬舌側）をテーブルで指定
- **精度は求めない。** 目的は「歯番・軸・CEJ・歯面判定・配色・UI が正しく動くこと」の検証
- 購入モデル到着後は GLB を差し替えるだけで動く状態にしておく（ビューアはジオメトリの中身に依存しない）

**実装: `dental_arch_gen.py`（numpy のみ、GLB を自前で書き出す）**

```
$ python3 dental_arch_gen.py      # → dental_template.glb
$ python3 verify_glb.py           # → 構造検証 + オルソ投影プレビュー4枚
```

出力実績: ノード38 / メッシュ36 / 64,376 tri / 32,324 vtx / 1.51 MB（Draco 未適用）

**暫定モデルの既知の限界（購入モデルで解消する前提）**

| 項目 | 現状 |
|---|---|
| 咬合面形態 | 咬頭数のみ再現。裂溝・辺縁隆線・咬合小面なし |
| 隣接面接触 | 弧長で機械的に配置。実際の接触点は再現していない |
| 口蓋・口腔底 | 未生成（上顎咬合面観で中央が空洞に見える） |
| 歯根形態 | テーパ円錐の近似。彎曲・断面の扁平さなし |
| 咬合彎曲 | Spee 彎曲・Wilson 彎曲なし（咬合平面はフラット） |
| 乳歯 | 未対応（Q7 の通り V2） |

### 4.8 歯根・歯槽骨の仕様【Q2: 含める（確定）】

| 対象 | 仕様 |
|---|---|
| 歯根 | 歯冠と同一メッシュ。歯種別の根数（前歯・小臼歯=1、上顎第一小臼歯=2、下顎大臼歯=2、上顎大臼歯=3）を再現 |
| 根管 | V1 では形状として持たない。根管治療済みの表現は歯根内部に半透明シリンダーを動的生成 |
| 歯肉 | 歯頸線に沿ったメッシュ。`opacity` を 1.0 ⇄ 0.25 でアニメーション遷移させ、歯根を「透かして見せる」 |
| 歯槽骨 | 上下顎の歯槽突起のみ（下顎枝・上顎洞は不要）。`opacity` 0.35 |
| 骨吸収表現 | 歯槽骨頂の高さを歯単位で可変にする。`bone_level_mm`（CEJ からの距離）を頂点シェイプキー or 頂点変位で反映。歯周病の説明で最も効く表現 |

**表示の段階（患者説明の主要導線）**

```
① 通常     歯肉 不透明 / 骨 非表示      → 「見えている状態」
② 歯根表示  歯肉 半透明 / 骨 非表示      → 「歯ぐきの中はこうなっています」
③ 骨表示   歯肉 半透明 / 骨 半透明      → 「骨がここまで下がっています」
```

この 3 段階を **1つのスライダー or 3ボタン** で行き来できることを V1 の必須要件とする。

## 5. インタラクション仕様

### 5.1 歯面判定アルゴリズム（コア）

レイキャストのヒット点から所属歯面を決定する。

```
入力: hit.point (world), hit.face.normal (world), tooth の extras
手順:
  1. p_local = hit.point - centroid
  2. h = dot(p_local, axis_occlusal)              // 咬合軸方向の高さ
  3. h_ratio = (h - cej_h) / (crown_top_h - cej_h)  // 0=CEJ, 1=咬頭頂

  4. if dot(n, axis_occlusal) > cos(40°) and h_ratio > 0.55:
         surface = O  (前歯なら I)
     else:
         // 側面4方向のうち最大内積
         cand = { B: +axis_buccal, L: -axis_buccal,
                  M: +axis_mesial, D: -axis_mesial }
         surface = argmax_k dot(n, cand[k])

  5. if h_ratio < 0.20: cervical_flag = true
```

**閾値定数**は `CONFIG.SURFACE_PICK` に外出しし、チューニング可能にする。

### 5.2 ホバー / 選択

- ホバー: 該当歯面をアウトライン + ツールチップ（歯番・面・現所見）
- クリック: 歯を選択 → サイドパネルに詳細、カメラが該当歯をフレーミング（`lerp` 0.12/frame）
- ダブルクリック: 単歯ズーム（周囲の歯を半透明化）
- 右クリック / 長押し: 所見入力コンテキストメニュー（術者モードのみ）

### 5.3 表示レイヤ（トグル）

| レイヤ | 既定 | 内容 |
|---|---|---|
| `caries` | ON | う蝕の歯面色分け |
| `restoration` | ON | 修復物・補綴物 |
| `perio` | OFF | 歯周ポケット深さの帯表示 + BOP マーカー |
| `root` | OFF | 歯根表示（歯肉を半透明化） |
| `bone` | OFF | 歯槽骨（骨吸収レベル可視化） |
| `plan` | OFF | 治療計画（提案される処置のプレビュー） |
| `xray` | OFF | 該当部位のX線画像を板ポリで空間配置 |

### 5.4 カメラプリセット

`正面` / `上顎咬合面` / `下顎咬合面` / `右側方` / `左側方` / `単歯ズーム`

開口アニメーション【B-3.2 で模型式に変更 2026-08-16】:
物理の顎模型（typodont）と同じ**本のような両開き**とする。スライダー 0–60°。

- ヒンジは**臼歯直後の仮想ヒンジ [0,-10,-48]** を使う（解剖学的な顆頭 z=-75 だと
  回転半径が大きく、開口時の上下の隙間が過大になる。GLB の `hinge_point` は
  解剖学的開口を実装する場合のために保持）
- `mandible` をこのヒンジ（X軸回り）で **+θ（前方が下がる）** 回転
- `maxilla` を同じヒンジで **−0.8θ（前方が上がる）** 回転
- これにより開口時に**上下両方の咬合面が視線側を向き、俯瞰で観察できる**
  （下顎のみの解剖学的開口では、1つのカメラから両顎の咬合面を同時に見ることは
  幾何学的に不可能。患者説明ツールとしては模型式を優先する）

【方向の定義】ヒンジより前方の点 (z_rel > 0) に対し `y' = y·cosθ − z_rel·sinθ`。
下顎は**正**の回転角（`mandible.rotation.x > 0`）、上顎は**負**（`maxilla.rotation.x < 0`）。
符号を誤ると逆に閉じ込む。検証はこの2つのアサーション + 正面スクリーンショット目視。

【開口時のフレーミング】全体ビュー（歯を選択していないとき）に限りレンダリング時に:
- 注視点を 開口角 × 0.15mm 下方へ（下顎の振れ幅の方が僅かに大きい）
- 距離を 開口角 × 1.8% 増加
- 仰角を 開口角 × 0.007 rad 上へ（見下ろす＝俯瞰。スクリーンショットで調整済み）
補正する。単歯フォーカス中は補正しない（注視点は回転後のワールド座標で追従）。

【スムーズ化】開口角はスライダー値へ時間基準 lerp で追従（下記参照）。

【スムーズ化 2026-08-16】以下は即時切替ではなく毎フレーム lerp で遷移させる:
- 開口角（スライダー値 → 表示角、係数 0.15/frame）
- 歯肉・歯槽骨の不透明度（表示段階①②③の切替、係数 0.10/frame。§4.8 の
  「opacity をアニメーション遷移」の実装）
- カメラの方位角 θ は **最短経路**で補間する（±π 正規化。何周も回した後の
  プリセット復帰で長回りしない）

### 5.5 患者説明モード

- 専門用語 → 平易表現（「C2」→「歯の内側まで進んだ虫歯」）
- 操作を回転・ズーム・レイヤ2種に限定
- 大きい文字、タブレット前提のタッチ操作
- ビフォー / アフター スライダー

### 5.6 UI/UX 原則【Q6: 一般歯科・分かりやすさ最優先（確定）】

**利用状況の前提**

| 項目 | 前提 |
|---|---|
| 場所 | 診療チェアサイド。患者は仰臥位または半座位 |
| 端末 | タブレット（横持ち）またはチェアサイドモニタ |
| 操作者 | 歯科医師 / 歯科衛生士。**グローブ着用** |
| 説明時間 | **3〜5分**。それ以上は患者の集中が切れる |
| 操作者のIT習熟度 | 低〜中と想定する。マニュアルは読まれない |

**設計原則（優先順に）**

1. **3タップルール** — 起動から「この患者のこの歯の状態」を患者に見せるまで **3タップ以内**。
2. **グローブ前提のタッチ設計** — タップ対象は最小 **60×60px**。ホバー依存の UI と右クリックを**使わない**（§5.2 の右クリックメニューは長押しに一本化）。
3. **左右の明示** — 3D 上の左右は必ず取り違えが起きる。画面の左右端に **「患者さんの右 / 患者さんの左」** を常時表示する。歯番ラベルにも象限を併記。**これは省略不可。**
4. **同時に見せる情報を絞る** — 初期表示は「う蝕」レイヤのみ。歯周・骨・治療計画は明示的に切り替える。全部同時に色が付いた画面は患者に何も伝わらない。
5. **階層は1段まで** — ネストしたメニュー、タブの中のタブを作らない。すべての機能は画面上の1操作で到達する。
6. **常時表示の凡例** — 色の意味を隠さない。凡例は畳まない。
7. **元に戻せる** — 誤タップは必ず起きる。Undo を常設し、破壊的操作には確認を出す。
8. **文字サイズ** — 患者向け表示は最小 18px、術者向けは最小 14px。細字は使わない。
9. **説明の"型"を用意する** — 自由に触れる UI だけでは現場で使われない。**ワンタップで説明シーケンスが流れるプリセット**（下記）を用意する。

**説明プリセット（ワンタップで実行）**

| プリセット | 動作 |
|---|---|
| `虫歯の説明` | 該当歯へカメラ移動 → う蝕面をハイライト → 深度を段階表示 |
| `歯周病の説明` | 歯肉半透明 → 骨表示 → 骨吸収部位をハイライト |
| `治療の流れ` | ビフォー → 処置 → アフター を順に再生 |
| `全体サマリー` | 上下顎の要処置歯を一望、本数と概算を表示 |

【B-3 実装 2026-08-16】タイマーシーケンス（1.6〜2.4s/ステップ）として実装。
各ステップで画面上部のナレーションバナーに平易な説明文を表示する。
3D ビューへのタッチ・別プリセットの開始・リセットで**即時中断**する
（自動再生が操作を奪い続けない）。対象歯はすべて所見データから動的に選ぶ
（`虫歯` = う蝕重症度最大の歯、`歯周病` = PD 最大の歯、`治療の流れ` = plan の priority 順）。

**モード切替**

`術者モード` ⇄ `患者モード` は画面右上の**1つの大きなトグル**。モード間で視点・選択歯は維持する（切り替えたら見ていた場所が変わる、が最悪の体験）。

**出力**

説明後に **患者への渡し物**（PDF 1枚）を1タップで生成できること。現場では「持ち帰れる紙」が同意率に直結する。

### 5.7 所見入力 UI【Q8: 2Dチャート入力 + 3D表示専用（確定）】

**入力は 2D 歯式チャート、3D は表示専用。** 3D 上のクリックで所見を登録する方式は採用しない。

理由:
- 3D 上のクリックは回転操作と誤爆しやすく、誤登録がカルテ品質を直接損なう
- 既存の紙歯式・電子カルテの入力フローと形が同じで、移行障壁が最小
- 衛生士がチェア横で素早く入力し、医師が 3D で説明する、という現場の役割分担に合う

**構成（画面上下 2 ペイン、または左右分割）**

```
┌─────────────────────────────────────┐
│  3D ビュー（表示専用・大きく）           │
│  ← 患者さんの右      患者さんの左 →     │
├─────────────────────────────────────┤
│  2D 歯式チャート（入力）                │
│  18 17 16 15 14 13 12 11|21 …        │
│  48 47 46 45 44 43 42 41|31 …        │
└─────────────────────────────────────┘
```

**双方向連動（必須）**
- 2D で歯をタップ → 3D のカメラが該当歯へ移動、ハイライト
- 3D で歯をタップ → 2D の該当歯がハイライト（**登録はしない**）
- 2D で所見を変更 → 3D の色が即時反映

**2D チャートの1歯セル**
- 歯を 5 分割した「田の字＋中央」の伝統的表現（M / D / B / L / 中央=O）
- 面をタップ → その面の所見をポップオーバーで選択（健全 / CO / C1〜C4 / 修復物）
- セル全体を長押し → 歯単位の状態（欠損・インプラント・未萌出 等）
- 歯周は別タブ（6点法の入力グリッド）

**3D 側の歯面判定アルゴリズム（§5.1）の役割**
入力用ではなく、**ハイライトと説明表示のため**に使う。3D で歯面をタップすると、その面の現在の所見をツールチップ表示する（読み取り専用）。

### 5.7.1 2D チャート入力の実装方式【B-3 実装 2026-08-16】

§5.6 の「タップ対象 60×60px」制約により、**田の字セルの面を直接タップさせる方式は採用しない**
（1面あたりの当たり判定が 20px 程度になりグローブ操作で誤爆する）。実装は次の 2 段階：

1. チャートのセル（1歯 = 1セル、幅 ≥60px）をタップ → 歯を選択、3D カメラが該当歯へ移動、
   **入力ポップオーバー**が開く
2. ポップオーバー内で「面の選択（M/D/B/L/O の大ボタン）」→「所見の選択（健全/CO/C1〜C4/修復物）」。
   所見ボタンのタップで即時反映（ポップオーバーは開いたまま連続入力できる）。
   同ポップオーバー内に「歯全体の状態」（欠損/インプラント/埋伏/未萌出/根治済/クラウン/健全）の
   1 行を併設する。**階層は 1 段のみ**（§5.6-5 を満たす）

- セルの田の字は**表示専用**（面ごとの所見色を反映）。切歯・犬歯も同一の 5 分割表現とする
- M/D の左右はチャート上の歯の位置で決める（正中に近い側 = M）。上顎行は B が上、下顎行は B が下
- 全入力操作は Undo スタック（深いコピー、最大 50 件）に積み、Undo ボタンを常設（§5.6-7）
- 「所見JSONを保存」ボタンで現在の所見（入力結果を含む）をローカルダウンロード。外部送信なし
- 3D 側の歯タップは 2D セルのハイライトのみ行い、**ポップオーバーは開かない**（誤登録防止、§5.7）

### 5.9 治療後シミュレーション（Before / After）【B-3 実装 2026-08-16】

治療計画（`plan[]`）から「治療後の想定状態」を**導出値として**生成し、現在の状態と切替表示する。
所見データ（現在の状態）は一切書き換えない（非破壊）。

**処置 → 治療後状態のマッピング（`PROC_EFFECT`）**

| procedure | 歯面所見への効果 | 歯状態への効果 |
|---|---|---|
| `CR_FILLING` | 対象面のう蝕 → `RESTORED`(CR) | う蝕面が残らなければ `RESTORED` |
| `INLAY` | 対象面のう蝕 → `RESTORED`(IN_METAL) | 同上 |
| `RCT` | う蝕面すべて → `RESTORED`(CR) | `ROOT_CANAL_TREATED` |
| `CROWN` | 全面 → クラウン表現 | `CROWN` |
| `EXTRACTION` | — | `MISSING` |
| `BRIDGE` | — | 欠損歯 → `BRIDGE_PONTIC`（人工歯をセラミック色で表示） |
| `SRP` / `OBSERVE` | 変化なし（歯周計測値は**実測値のため書き換えない**） | 変化なし |

- シミュレーション表示中は画面上部に
  **「治療後シミュレーション表示中（実際の治療結果とは異なります）」** のバナーを常設する。
  SIMULATED ≠ ACTUAL の区別は消せない（研究資料 §11/§29 準拠）
- ヘッダの KPI サマリーは常に**現在の状態**から計算する（シミュレーションに引きずられない）

### 5.10 歯周ポケットの 3D 重畳【B-3 実装 2026-08-16】

- レイヤ `perio`（既定 OFF）。ON で各歯の歯頸部に 6 点法の計測点マーカー（球）を表示
- マーカー位置は `extras` から導出:
  `centroid + axis_occlusal×cej_h + (±axis_buccal)×(bl_width/2+マージン) + (±axis_mesial)×(md_width×0.3)`
- 色は §9.3 の PD 3 段階。BOP は咬合側に小さい赤ドットを併置
- 欠損歯・非表示顎のマーカーは表示しない。マーカーはピッキング対象外
- 計測値は実測データのみ。シミュレーション表示中も書き換えない

### 5.11 2D 表示モード【B-3.2 実装 2026-08-16】

3D と並ぶ表示形態として **2D モード**を用意する（従来の紙歯式に近い見え方。
3D に不慣れなスタッフや、一覧性を優先したい場面向け）。

- ヘッダの「2D表示 ⇄ 3D表示」ボタンで切替。**選択歯・所見・モードは維持**する
- 2D モードでは 3D ビューを隠し、歯式チャートを主役として拡大表示
  （セル最大 110px、面の色分け・欠損×・選択ハイライトは 3D と同一ロジック）
- 右パネルの詳細・レイヤ・シミュレーション・プリセットはそのまま機能する
  （プリセットのカメラ移動は無効になるが、選択とナレーションは動く）
- 3D 専用のコントロール（視点プリセット・表示の段階・開口）は 2D 中は非表示
- 患者説明モードでも 2D チャートを表示する（通常の術者チャートと同じ内容）

### 5.12 凡例の配置【B-3.2 変更 2026-08-16】

### 5.13 所見JSONの読み込みUI【B-3.2 一時変更 2026-08-16】

ローカル読み込み方針自体は変更しない。保存ボタンは存続）。リセットはヘッダへ移動。

### 5.8 患者渡し物 PDF【Q9: PDF 1枚（確定）】

A4 縦 1 枚。1タップ生成 → プレビュー → 印刷 or 保存。

| 領域 | 内容 |
|---|---|

### 6.2 Blender エクスポートスクリプト要件

1. 各歯オブジェクトを FDI 名にリネーム（命名規約チェック → 不一致は fail）
2. 主成分分析 or 手動指定で `axis_occlusal` / `axis_buccal` を算出
3. CEJ ループ（頂点グループ `cej`）から `cej_y` を算出
4. `extras` を JSON で埋め込み
5. GLB エクスポート → Draco 圧縮
6. **検証**: 32歯すべてが存在するか、軸が正規直交か、bbox が想定範囲内かをアサート

### 6.3 IOS STL 正規化（Phase 2）

```
STL (Z-up, 任意原点)
 → 単位確認（mm か否か。inch/m で来るケースあり）
 → 咬合平面フィッティング（PCA + RANSAC）で回転行列を算出
 → 正中面推定（左右対称性最大化）
 → 原点移動
 → 歯牙セグメンテーション（Phase 3: 学習モデル / Phase 2: 手動）
 → FDI ラベル付与
 → テンプレメッシュとの非剛体位置合わせ（所見マッピング用）
```

### 7.2 DB スキーマ（PostgreSQL）

GPT 側で作成中の DB は以下の形に揃える。**歯面所見は必ず正規化して1行1面**（`"MOD"` のような文字列を1カラムに詰めると集計もdiffも不可能になる）。

```sql
-- 患者
CREATE TABLE patients (
  patient_id   UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  chart_no     TEXT UNIQUE NOT NULL,       -- 院内カルテ番号
  birth_date   DATE,
  sex          CHAR(1) CHECK (sex IN ('M','F','O')),
  created_at   TIMESTAMPTZ DEFAULT now()
);

-- 検査（来院1回 = 1レコード）
CREATE TABLE examinations (
  exam_id      UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  patient_id   UUID NOT NULL REFERENCES patients(patient_id) ON DELETE CASCADE,
  exam_date    DATE NOT NULL,
  examiner_id  TEXT,
  exam_type    TEXT CHECK (exam_type IN ('INITIAL','RECALL','TREATMENT','POST_OP')),
  note         TEXT,
  created_at   TIMESTAMPTZ DEFAULT now()
);
CREATE INDEX ON examinations (patient_id, exam_date DESC);

-- 歯単位の状態
CREATE TABLE tooth_status (
  exam_id      UUID NOT NULL REFERENCES examinations(exam_id) ON DELETE CASCADE,
  fdi          SMALLINT NOT NULL CHECK (
                 (fdi BETWEEN 11 AND 48) OR (fdi BETWEEN 51 AND 85)),
  status       TEXT NOT NULL,             -- SOUND / CARIES / MISSING / IMPLANT ...
  mobility     SMALLINT CHECK (mobility BETWEEN 0 AND 3),
  furcation    SMALLINT CHECK (furcation BETWEEN 0 AND 3),
  note         TEXT,
  PRIMARY KEY (exam_id, fdi)
);

-- 歯面単位の所見（コア）
CREATE TABLE surface_findings (
  finding_id   BIGSERIAL PRIMARY KEY,
  exam_id      UUID NOT NULL REFERENCES examinations(exam_id) ON DELETE CASCADE,
  fdi          SMALLINT NOT NULL,
  surface      CHAR(1) NOT NULL CHECK (surface IN ('M','D','B','L','O','I')),
  cervical     BOOLEAN NOT NULL DEFAULT FALSE,
  finding_type TEXT NOT NULL,             -- CARIES / RESTORATION / FRACTURE / WEAR / EROSION
  caries_grade TEXT CHECK (caries_grade IN ('CO','C1','C2','C3','C4')),
  icdas        SMALLINT CHECK (icdas BETWEEN 0 AND 6),
  cavity_class TEXT CHECK (cavity_class IN ('I','II','III','IV','V','VI')),
  material     TEXT,                       -- CR / IN_METAL / FMC / PFM ...
  placed_on    DATE,
  note         TEXT,
  UNIQUE (exam_id, fdi, surface, finding_type)
);
CREATE INDEX ON surface_findings (exam_id, fdi);

-- 歯周6点法
CREATE TABLE perio_measurements (
  exam_id      UUID NOT NULL REFERENCES examinations(exam_id) ON DELETE CASCADE,
  fdi          SMALLINT NOT NULL,
  site         TEXT NOT NULL CHECK (site IN ('MB','B','DB','ML','L','DL')),
  pd           SMALLINT CHECK (pd BETWEEN 0 AND 15),
  gm           SMALLINT CHECK (gm BETWEEN -5 AND 15),
  cal          SMALLINT GENERATED ALWAYS AS (pd + gm) STORED,
  bop          BOOLEAN DEFAULT FALSE,
  pus          BOOLEAN DEFAULT FALSE,
  plaque       BOOLEAN DEFAULT FALSE,
  PRIMARY KEY (exam_id, fdi, site)
);

-- 治療計画
CREATE TABLE treatment_plans (
  plan_id      BIGSERIAL PRIMARY KEY,
  exam_id      UUID NOT NULL REFERENCES examinations(exam_id) ON DELETE CASCADE,
  fdi          SMALLINT NOT NULL,
  surfaces     TEXT,                       -- 'MOD' 等（表示用。判定はJOIN先で）
  procedure    TEXT NOT NULL,              -- CR_FILLING / INLAY / CROWN / EXTRACTION / RCT / SRP
  priority     SMALLINT DEFAULT 3,
  est_visits   SMALLINT,
  est_fee_yen  INTEGER,
  status       TEXT DEFAULT 'PLANNED'
                 CHECK (status IN ('PLANNED','AGREED','IN_PROGRESS','DONE','CANCELLED')),
  note         TEXT
);

-- 添付メディア（X線・口腔内写真・IOSスキャン）
CREATE TABLE media_assets (
  media_id     UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  exam_id      UUID NOT NULL REFERENCES examinations(exam_id) ON DELETE CASCADE,
  media_type   TEXT CHECK (media_type IN ('XRAY_PA','XRAY_BW','PANO','CBCT','PHOTO','IOS_MESH')),
  fdi_refs     SMALLINT[],                 -- 関連歯
  storage_uri  TEXT NOT NULL,              -- 実体はDB外
  captured_at  TIMESTAMPTZ,
  meta         JSONB
);
```

**設計原則**
- 「現在の状態」テーブルを持たない。**常に `examinations` の時系列で表現し、最新を導出する**（VIEW で `latest_tooth_status` を提供）。これで経過比較とビフォーアフターが自然に実装できる。
- `fdi` に FK は張らず CHECK 制約のみ（マスタテーブル `teeth_master` を作るなら FK 化してよい）。
- 患者氏名は本スキーマに置かない。既存の電子カルテ側 ID (`chart_no`) で突合する。

## 8. 実装仕様（ビューア）

### 8.1 技術スタック

| 項目 | 選択 | 理由 |
|---|---|---|
| 3Dエンジン | **Three.js r128**（インライン） | 社内標準・CDN依存排除 |
| 形式 | 単一 HTML ファイル | 社内標準の納品形態 |
| ローダ | GLTFLoader + DRACOLoader | Draco 圧縮 GLB 対応 |
| カメラ操作 | **自前 orbit 実装** | r128 は CDN 版 OrbitControls が使えない（既知） |
| UI | 素の DOM + CSS（フレームワークなし） | 単一ファイル要件 |

### 8.2 既知の落とし穴（社内 CLAUDE.md より継承）

- `THREE.ColorManagement.enabled = false` を明示（手調整パレットのため）
- 加算合成（AdditiveBlending）は明背景では使わない → 所見ハイライトは `MeshStandardMaterial` の `emissive` で
- `LineDashedMaterial` は視認性が悪い → 歯周ポケット線はチューブ or 帯ポリゴンで
- カメラ lerp 0.12/frame は SwiftShader 下で収束が遅い → Playwright 検証時は 12–16s の `wait_for_timeout`
- スクリーンショット >800KB はインライン表示不可 → JPEG q68–80 / 長辺 ≤640px

### 8.3 データの取り扱い

- **患者データは HTML に埋め込まない。** 起動時に `fetch` で `findings.json` を読む、または `<input type=file>` でローカル読み込み。
- 院内クローズドネットワークでの動作を前提（外部 CDN・外部 API へのリクエストゼロ）。
- ローカルストレージへの患者データ保存は禁止（ブラウザ共有端末を想定）。

### 8.4 パフォーマンス目標

| 指標 | 目標 |
|---|---|
| 初回ロード（ローカル） | ≤ 3s |
| FPS（iPad Pro / M1） | ≥ 50 |
| FPS（診療室の一般 Windows PC / 内蔵GPU） | ≥ 30 |
| ピッキング応答 | ≤ 16ms |
