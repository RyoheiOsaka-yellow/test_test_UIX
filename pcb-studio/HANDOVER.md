# GPU基板スタジオ 引き継ぎメモ

GPU ボードなどの基板設計を試作するブラウザアプリです。部品を選んで置き、自動で配置・配線し、3D で確認して KiCad に書き出せます。このメモは、別の AI アシスタントや開発者が作業を続けるための要約です。

## 1. どこに何があるか

- リポジトリ：`RyoheiOsaka-yellow/test_test_UIX`、作業ブランチ `claude/zealous-feynman-8h6b6t`（PR は未作成）
- アプリ本体：`pcb-studio/`
- 単体で開けるファイル：`pcb-studio/dist/gpu-kiban-studio.html`（three.js とコードを 1 ファイルにまとめたもの。オフラインで動く）
- 機能の一覧と制約：`pcb-studio/README.md`

## 2. 技術構成

- ビルドなしで動く素の ES モジュール。描画は Canvas 2D と three.js r128（cdnjs の UMD 版）
- 開発時は `pcb-studio/` で静的サーバを立てて `index.html` を開く

```bash
cd pcb-studio && python3 -m http.server 8765
```

- 単体ファイルは esbuild でまとめ、three.js と一緒に `index.html` へインラインで埋め込む

```bash
npx --yes esbuild@0.21.5 js/app.js --bundle --format=iife --minify --outfile=bundle.js
```

  そのあと `index.html` の `<script src="…three.min.js">` と `<script type="module" src="js/app.js">` を、それぞれの中身を入れた `<script>…</script>` に置き換える（`</script` は `<\/script` にエスケープ）。

## 3. ファイルの役割（`pcb-studio/js/`）

| ファイル | 役割 |
|---|---|
| `core.js` | 基板モデル（単位 mm、配線グリッド 0.5mm、配線層 4 層）、未配線の列挙、配線の役割分け（`ROLES` / `netRole`）、保存・復元 |
| `library.js` | 部品カタログ、フットプリント生成、部品の高さ表 |
| `templates.js` | 構成プリセット（flagship / highend / radeon / mid / entry）と基板の生成 |
| `placer.js` | 自動配置：電源の流れから領域を割り当て → ブロックを組み立て → 焼きなまし → 重なり解消 |
| `router.js` | 自動配線：グリッド A*（45° 対応、ビア、引きはがし再配線）、等長配線、電源プレーンへのビア接続と救済、手配線 |
| `planes.js` | 電源プレーンの層割り当て（10 層構成） |
| `electrical.js` | 電源経路の電圧降下・損失の概算 |
| `cooler.js` | 冷却機構との干渉チェックと熱の概算（1 次元の熱回路） |
| `kicad.js` | KiCad の `.kicad_pcb` / `.kicad_pro` 書き出しと読み込み |
| `render.js` | 平面表示と、3D 用の基板テクスチャ描画 |
| `view3d.js` | 3D 表示（基板、部品、ブラケット、冷却機構、発光する線） |
| `app.js` | 画面の状態、操作、自動レイアウトの進行、タイムライン、比較、レポート |

`index.html` には `<!--page-->…<!--/page-->` と `<!--body-->…<!--/body-->` の目印があり、公開用の断片を切り出すのに使っています。

## 4. 主な機能

- 構成を選んで基板を生成し、部品をつかんで動かす・回す・裏返す・差し替える
- 自動レイアウト：計画・整列 → 焼きなまし → 配線 → 裏面確認。過程をタイムラインに記録し、任意の時点から再開できる。段階ごとに止めて手直しも可能
- 手配線（層の切り替え、ビア、引き直し）
- 3D 表示が主画面：実物風の仕上げ（黒レジストなど）、部品の刻印、透視、層の分解、ブラケット、冷却機構の重ね表示
- 冷却：段差つきベースプレート、切り欠き、干渉チェック、熱の概算。ヒートパイプの本数・ファンの風量・ファンの位置を変えられる
- 電源経路の概算、案の比較、HTML レポート、KiCad / JSON の保存と読込
- 未配線の線は役割ごとに色分けして発光表示。表示メニューの「配線を役割で色分け」で配線済みの線も同じ色で表示

役割の色：メモリ信号＝水色、PCIe＝黄、映像出力＝紫、電源＝赤、VRM 制御＝橙、監視・制御＝緑。

## 5. 現在の品質（計測済みの数値）

参照配置を自動配線した結果：

| 構成 | 配線 | 等長 | プレーン未接続ピン |
|---|---|---|---|
| フラッグシップ | 274/274 | 20/20 | 0 / 5977 |
| ハイエンド | 226/226 | 16/16 | 1 / 4386 |
| Radeon | 215/215 | 15/16 | 0 / 4320 |
| ミドル | 169/169 | 12/12 | 0 / 2699 |
| エントリー | 129/129 | 8/8 | 0 / 1396 |

- 自動レイアウト後（シード 6）も配線は全構成 100%、部品の重なり 0。等長は Radeon のみ 14/16。プレーン未接続は構成により 0〜10 ピン残る
- KiCad 7.0.11 の `pcbnew` でゾーンを塗って DRC を実行：ミドル・ハイエンド・エントリー・Radeon でクリアランス違反 0。未接続はハイエンドの 1 ピンのみ。フラッグシップは未実行
- DRC に出る `lib_footprint_issues` は、ライブラリを持たない独自フットプリントのための警告

## 6. 既知の課題と注意点

- **ハイエンドの未接続 1 ピン**：メモリの角のパッド。まわりが HDMI の等長配線と GND ビアに囲まれ、どかすと等長が崩れるため救済を戻している
- **自動レイアウト後のプレーン未接続**：信号配線のあとにビアを打つ順序のため、置き場所がなくなるピンが出る
- **Radeon の等長**：1〜2 組が長さをそろえきれない
- **ファンの位置の設定**：ファンが基板のほぼ全長を覆うため、温度差は 1℃以内でほとんど効かない
- **「電源経路を優先（VRM を両側に分ける）」設定**：VCORE の電圧降下と損失はおおむね半分になるが、温度はほぼ変わらない
- **熱と電気の数値はすべて概算**：熱伝達係数、ヒートパイプの等価熱伝導率などは仮定値。部品の高さは一部（16 種）のみ実寸確認済み
- **3D のちらつき修正**：カメラの描画範囲を基板に合わせて絞る方式で直した。計測はヘッドレスブラウザのみで、実機の画面では未確認
- 配線幅は全ネット 0.15mm、クリアランス 0.2mm、ビア径 0.45mm（ドリル 0.2mm）で統一。電源の太い配線や差動ペアの間隔管理は扱っていない

## 7. 進め方の約束

- 依頼者は「常に最適解を見つけたいので、議論と提案を繰り返す」進め方を希望。毎回の返答の最後に番号つきの「次の論点」を出し、依頼者が「1〜3で」のように選ぶ
- 返答は日本語
- 変更のたびに：ブラウザで動作確認 → README 更新 → 単体 HTML を再ビルド → コミットして作業ブランチへ push
- 結果は正直に報告する（未達の数値や未確認の項目も書く）

## 8. 次の候補（直近の提案）

1. 配線中の線だけ強く光らせる、発光の強さ・太さを調整できるようにする
2. 信号配線の前に電源・GND ピンのビア位置を確保し、自動レイアウト後のプレーン未接続を 0 にする（配線率との兼ね合いを確認）
3. 等長グループを先に配線する順序に変え、Radeon の残りを解消する
4. 効かないファン位置の設定を外すか、風の向きまで扱う設定に作り直す
