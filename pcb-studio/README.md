# GPU基板スタジオ（PCB レイアウト プロトタイプ）

グラフィックスカード基板を題材にした、ブラウザで動く PCB 配置・配線の試作ツール。

## 起動

```bash
cd pcb-studio && python3 -m http.server 8765
```

`http://localhost:8765/` を開く（ES モジュールのため file:// では動きません）。依存ライブラリ・ビルドなし。

## できること

- 主画面は 3D：床と影の上に基板を置き、グループ色の立体部品、白い接続線、配線が進むと銅色に変わる基板面を表示。
  部品は 3D 上で直接つかんで動かせる（空いた場所のドラッグで回転、Shift+ドラッグで移動、ホイールで拡大）。`3` キーで 2D 設計ビューへ
- 作成過程の記録と巻き戻し：自動レイアウトの全過程（配置の動きと配線が引かれる順）を記録し、シークバーで任意の時点へ戻して再生できる
- 基板の仕上げ（3D）：緑レジスト／黒レジスト／参考画像風を切り替え。レジスト越しの銅箔（ベタと配線の隙間）、金めっきのパッド、
  レジストで覆われたビア、白いシルク（外形・部品番号・1 番ピン・基板名）、めっきされた取り付け穴、FR-4 色の断面。
  凹凸・粗さ・金属度のマップで、レジストの艶とパッドの反射、部品の影を出す
- 透視（T キー）：基板と部品を半透明にして内層の配線を見せる。手配線で内層に入ると自動で切り替わる
- 手配線の編集：Backspace で一手戻す、Alt+クリックで区間を消す、引いた線の上をクリックして途中から続ける
- 途中から作り直す：シークバーで戻した時点を「今の状態」にして編集し、「続きを実行」でそこから焼きなまし・配線を再開できる
- 手配線：パッドから経路を自分で引く（クリックで確定、1〜4 キーで層替え＝ビア、同じネットのパッドで接続）。
  クリアランスを守る経路だけが引ける。手配線は自動配線・保存・取り消しをまたいで保持され、KiCad にも書き出される
- 立体の部品形状：足のある IC、角を落としたインダクタ、台座と極性マークつきの電解コンデンサ、両端に電極のあるチップ部品、ピンの見えるコネクタ
- 段階ごとの一時停止：計画・整列 → 焼きなまし → 配線 の合間で止め、手で直してから次へ進める
- 「作り方」ガイド：構成 → 部品 → 配置 → 配線 → 検査 → 書き出し の進み具合を表示し、各ステップの操作へ移動。
  自動レイアウトの設定（領域割り当て、ブロックの組み立て直し、等長化、探索量、seed）を切り替えて結果を比べられる
- 構成プリセット（RTX 5090 級〜エントリー）から GPU・メモリ枚数・VRM 相数・部品型番を選んで基板を生成
- 部品のドラッグ／回転／表裏変更／削除。動かすと関連ネットを引き剥がして自動で再配線
- 自動配線：4 配線層のグリッド A*（45°配線、貫通ビア、引き剥がし再配線）。
  クリアランス 0.2mm、配線幅 0.15mm、ビア 0.45/0.2mm、基板端 0.5mm を守る
- 電源・GND：ピンごとにビアを打って内層プレーンへ接続。レールの領域が重ならないよう電源層へ自動で割り当て、層構成を決める
  （小電流の +5V / +3V3 / +PEX は配線で引く）
- 等長配線：メモリ 1 枚ぶん・映像 1 ポートぶんを 1 グループとし、短い配線にミアンダを挿入して最長に合わせる
- 自動レイアウト再生：計画・整列 → 焼きなまし → 配線 → 裏返し → 表へ
  - 領域は「12V 入力 → VRM → GPU」の電源の流れと、GPU を囲むリングから自動で割り当てる
  - ブロック（DrMOS＋インダクタ＋コンデンサ、メモリ＋デカップリング）の内部配置はネットリストから組み立てる
  - 相ブロックは列に整列、メモリは GPU 側ボール群の正面へ、GPU 裏のコンデンサは格子に置く。残りだけ焼きなまし
- 電源経路の概算：レールごとの電流・経路長・有効幅・電圧降下・損失と、降下 2% 以内に必要なプレーン枚数
- 表示：ネット強調、レイヤ切替、ラッツネスト、電源プレーン領域と電流の流れ、グループ凡例、実物風表示
- 3D 表示（three.js r128 を CDN から読み込み）：回転・拡大、銅箔 4 層を上下に分解して確認
- 検査：未接続・重なり・基板外・プレーン未接続を基板上にマークし、一覧から該当箇所へ移動。ネット一覧で検索・強調
- 部品ライブラリ（実機の分解記事などを調査。出典確認／未確認を表示）、代替部品への一括置換、BOM
- 保存・読込：JSON、KiCad `.kicad_pcb`（ゾーン・層構成つき）と設計ルール `.kicad_pro` の書き出し、`.kicad_pcb` の読み込み

## KiCad での検証（KiCad 7.0.11）

書き出したファイルを `pcbnew` の Python API で読み込み、ゾーンを塗りつぶして DRC を実行した結果：

- 部品・パッド・ネット・配線・ビアの数がこのツールと一致。10 層基板として読み込まれる
- 添付の `.kicad_pro`（クリアランス 0.2mm、最小ビア 0.4/0.2mm）で、クリアランス・穴・基板端の違反は 0
- 未接続は 5 構成で 0〜4 箇所。このツールが「未接続」「プレーン未接続」として表示する箇所と同じもの
- 残る警告は「フットプリントがライブラリ未登録」のみ（独自フットプリントのため）
- KiCad が保存し直したファイル（KiCad 7 の書式、塗りつぶし済みゾーン入りで約 25MB）も読み込める

| ファイル | 役割 |

| `js/core.js` | 基板モデル、幾何、ラッツネスト、シリアライズ |
| `js/library.js` | 部品カタログと簡略フットプリント |
| `js/templates.js` | GPU 基板のパラメトリック生成 |

| `js/kicad.js` | KiCad 形式の書き出し・読み込み |
| `js/app.js` | UI と操作 |

## 制約

- フットプリントは 0.5mm グリッド向けの概念モデルで、実ピン配置・ボール数とは異なる（GPU のボール数は非公開）
- 差動ペアは 1 経路として配線し、2 本線で描画する（P/N を個別には配線しない）
- スイッチノードなど大電流の配線も 0.15mm 幅で引く（実設計ではベタにする部分）
- 電源経路の数値は、一様に広がる平面電流を仮定した概算。銅箔温度、ビアの抵抗、リターン経路、電流の集中は含まない
- 画面上の電源プレーン領域は供給経路の近似。KiCad に書き出すゾーンはレールごとの凸包で、実際の塗りは KiCad が行う
- 等長化は空きがないと未達になる（検査サマリに表示）
- KiCad の読み込みは部品・パッド・ネット・外形の範囲を取り込み、配線は引き直す。90°以外の回転や非矩形外形は近似。
  回路図がないため、デカップリングの所属やスイッチノードは配置と接続から推定する
- 3D は閲覧専用。インピーダンス、熱、製造ルール（はんだ・シルク）の検査は未実装
