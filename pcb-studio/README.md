# GPU基板スタジオ（PCB レイアウト プロトタイプ）

グラフィックスカード基板を題材にした、ブラウザで動く PCB 配置・配線の試作ツール。

## 起動

```bash
cd pcb-studio && python3 -m http.server 8765
```

`http://localhost:8765/` を開く（ES モジュールのため file:// では動きません）。依存ライブラリ・ビルドなし。

## できること

- 構成プリセット（RTX 5090 級〜エントリー）から GPU・メモリ枚数・VRM 相数・部品型番を選んで基板を生成
- 部品のドラッグ／回転／表裏変更／削除。動かすと関連ネットを引き剥がして自動で再配線
- 4 配線層のグリッド A* 自動配線（45°配線、貫通ビア、引き剥がし再配線）
- 等長配線：メモリ 1 枚ぶん・映像 1 ポートぶんを 1 グループとし、短い配線にミアンダを挿入して最長に合わせる
- 自動レイアウト再生：計画・整列 → 焼きなまし → 配線 → 裏返し → 表へ
  - 領域は「12V 入力 → VRM → GPU」の電源の流れと、GPU を囲むリングから自動で割り当てる
  - 相ブロック（DrMOS＋インダクタ＋コンデンサ）は剛体として列に整列、メモリは GPU 側ボール群の正面へ、
    GPU 裏のコンデンサは格子に置く。残りのブロックだけを焼きなましで配置する
  - 全プリセットで重なり 0・配線 100%、配線長は手書きのリファレンス配置より 8〜14% 短い（seed 6 での計測）
- 検査：問題箇所（未接続・重なり・基板外）を基板上にマークし、一覧から該当箇所へ移動。ネット一覧で検索・強調
- ネット強調、レイヤ表示切替、ラッツネスト、電源プレーン（供給経路に沿った帯、幅は想定電流に比例）、グループ凡例
- 3D 表示（three.js r128 を CDN から読み込み）：回転・拡大、銅箔 4 層を上下に分解して確認
- 部品ライブラリ（実機の分解記事などを調査。出典確認／未確認を表示）、代替部品への一括置換
- 検査サマリ（配線完了率、等長、重なり、VRM 余裕率、入力電力）、BOM
- 保存・読込：JSON、および KiCad `.kicad_pcb` の書き出し／読み込み

## 構成

| ファイル | 役割 |
|---|---|
| `js/core.js` | 基板モデル、幾何、ラッツネスト、シリアライズ |
| `js/library.js` | 部品カタログと簡略フットプリント |
| `js/templates.js` | GPU 基板のパラメトリック生成 |
| `js/router.js` | 自動配線 |
| `js/placer.js` | 散布・焼きなまし・重なり解消 |
| `js/render.js` | Canvas 描画、3D 用テクスチャ |
| `js/view3d.js` | 3D 表示 |
| `js/kicad.js` | KiCad 形式の書き出し・読み込み |
| `js/app.js` | UI と操作 |

## 制約

- フットプリントは 0.5mm グリッド向けの概念モデルで、実ピン配置・ボール数とは異なる（GPU のボール数は非公開）
- 電源・GND は内層プレーン扱いで配線しない。プレーン形状は供給経路の近似で、銅箔の実形状や電流密度の計算ではない
- 差動ペアは 1 経路として配線し、2 本線で描画する（P/N を個別には配線しない）
- 等長化は空きがないと未達になる（検査サマリに表示。プリセットでは最大差 1.4mm 以内）
- 自動配置の相ブロック内部の並びは、実行時点の配置から引き継ぐ（ばらけている場合は横一列に詰め直す）
- KiCad 書き出しは自前の往復テスト（全パッドの位置・ネット一致）のみで、KiCad 本体での読み込みは未検証。
  読み込みは部品・パッド・ネット・外形の範囲を取り込み、配線は引き直す。90°以外の回転や非矩形外形は近似
- 3D は閲覧専用。インピーダンス、熱、製造ルールの検査は未実装
