# みなとみらい 立体地図 3D

新宿駅「構内図 3D」（屋内地図オープンデータ版）の みなとみらい版。
みなとみらいには国交省の屋内地図オープンデータが存在しないため、**PLATEAU の実測 3D 都市モデル**を骨格に、
OSM の多層歩行者ネットワークと、公開情報に基づく駅構内の近似モデルを組み合わせている。

完成物: `dist/index.html`（単一ファイル、約 5.6 MB。データは gzip + base64 で埋め込み。モダンブラウザで開くだけで動く）

| 鉄道 | OSM 鉄道線形。みなとみらい線（地下）、根岸線（高架）、東海道線・横須賀線・京急・相鉄・ブルーライン・高島線（貨物）を路線色で |
| 歩行者ネットワーク | OSM の歩道・階段・エスカレーター・エレベーター・デッキ・地下通路を 階層（2F/1F/GL/B1〜B5）付きグラフ化（約 9,400 ノード / 10,400 リンク） |
| 駅構内（近似） | みなとみらい駅（島式 B4 ホーム／B3・B2 改札／地上までの吹抜け）、新高島駅（相対式 B5 ホーム／B2 改札）、馬車道駅（島式 B3／B2 改札）、桜木町駅（JR 高架ホーム・ブルーライン B2）、高島町駅、横浜駅（地平ホーム形状のみ）。**公開情報からの近似モデルであり実測データではない** |

## 再生成手順

```bash
cd minatomirai
npm install
pip install pyproj shapely numpy pillow mapbox-vector-tile
npm install --no-save draco3d            # decode_b3dm.js 用

export MM_WORK=/tmp/mm                   # 中間ファイル置き場（数百 MB）
python3 tools/fetch_plateau.py
node tools/decode_b3dm.js $MM_WORK/nishi_lod3 $MM_WORK/naka_lod3 --out $MM_WORK/dec_lod3.json
node tools/decode_b3dm.js $MM_WORK/brid_lod2 --out $MM_WORK/dec_brid2.json
node tools/decode_b3dm.js $MM_WORK/brid_lod3 --out $MM_WORK/dec_brid3.json
python3 tools/fetch_osm.py
python3 tools/build_data.py              # -> data/minatomirai.pack
python3 tools/fetch_floorguide.py        # -> data/floorguide.csv (公式フロアガイド)
python3 tools/make_underlays.py          # -> data/underlays/*.jpg, data/underlays.json
python3 tools/fit_underlays.py           # 下敷きの自動位置合わせ (時間がかかる)
python3 tools/extract_zones.py           # -> data/zones.json (MARK IS の区画形状)
python3 tools/extract_cores.py           # -> data/cores.json (エレベーター・エスカレーターの位置)
# 国土数値情報 バスルート N07-11_14_GML.zip を $MM_WORK/mode/n07 に展開してから
# (任意) ODPT_KEY=... python3 tools/fetch_gtfs_bus.py   # -> data/bus_gtfs.json (バスの現行ダイヤ)
python3 tools/mode_split.py              # -> data/mode_split.json (鉄道以外の手段の内訳)
npm run build                            # -> dist/index.html
```

`build_data.py` は `dec_*.json` から範囲内の地物を選び、重心ごとの索引 (`idx_*.json`) を作りながら
座標を平面直角座標 IX 系（EPSG:6677、原点＝みなとみらい駅）へ変換し、頂点を 10 cm 単位で量子化・溶接して格納する。
標高は、建物最下点の楕円体高と DEM 標高の差の中央値からジオイド高を推定して揃えている。

## フロアガイド CSV（公式サイト取得＋手入力）

`tools/fetch_floorguide.py` が公式フロアガイド（MARK IS みなとみらい／ランドマークプラザ／クイーンズタワーA／
みなとみらい東急スクエア）から店舗一覧を取得して `data/floorguide.csv` を生成する（約 400 区画、source=official）。
MARK IS はフロアマップの区画番号を zone に持つので、番号順に区画が並ぶ。
区画の割り付けは「通路＋両側（交互配置）」「グリッド」「帯」から選択でき、区画クリックで詳細
（用途・階・区画番号・出典）を表示、左パネルの用途フィルタで飲食だけ等に絞り込める。
取得スクリプトの仕様はサイト構造に依存するため、サイト改修時は正規表現の調整が必要。

### 公式フロアマップの下敷き表示

`tools/make_underlays.py` が MARK IS・ランドマークプラザの公式フロアガイド PDF から階ごとのフロアマップを切り出し、
`data/underlays/*.jpg` と `data/underlays.json`（配置パラメータ）を生成する。ビルド時に画像を埋め込み、建物選択時に
各階の床面へ貼る。図面範囲（白背景中の描画部分）を自動検出して建物主軸に合わせ、アンカー地物（横浜美術館・
ランドマークタワー）の方向で 0°/180° を自動判定する。ずれは右パネル「下敷きの位置合わせ」の回転・拡縮・平行移動・
不透明度スライダーで直し、「underlays.json 保存」で書き出した JSON を `data/underlays.json` に置けば既定値になる。
断面カットと併用すると、該当階の平面図として確認できる。

### 名札の間引き・店舗詳細

名札は「自動間引き（画面上で重なるものを隠す。カーソルの階を優先）」「カーソルの階のみ」「すべて」「なし」を選べる。
区画クリックの詳細には、公式サイトの店舗ページ URL、営業時間（ランドマークプラザは店舗ごと、他は施設共通）、
電話番号、店舗公式サイトを表示する（`fetch_floorguide.py` が詳細ページから取得）。

### 下敷きの自動位置合わせと区画の自動抽出

- `tools/fit_underlays.py`: 建物の実フットプリントと図面の建物領域の IoU が最大になる回転・拡縮・平行移動を
  探索し、`data/underlays.json` に書き戻す（アンカー地物で 0°/180° を決めてから ±16° を探索。全 20 階で約 40 分）。
- `tools/extract_zones.py`: MARK IS の公式マップから彩色された区画面を連結成分として検出し、区画番号を OCR
  （RapidOCR）と、検出済み番号から学習した字形テンプレートの照合で割り当てる。面の凸包を下敷きと同じ変換で
  世界座標にして `data/zones.json` に書く。画面では抽出済みの区画は実形状で、未抽出の区画だけ帯分割の近似
  （薄い塗り）で表示する。現状の抽出率は約 8 割。

### リアル表示（three.js の物理ベース描画）

スタイルの「リアル」を選ぶと、線画ではなく実写寄りの描画に切り替わる。

- **空と太陽**: `Sky`（大気散乱モデル）に、みなとみらい駅の緯度経度から計算した太陽位置を与える。時刻（0〜24 時）と月のスライダーで、朝焼け・日中・夕景・夜景を連続的に変えられる。太陽高度に応じて露出・霧の色・環境光も変わる。
- **影**: 太陽光の 4096px シャドウマップ（PCF ソフト）。建物・樹木が地面と他の建物に影を落とす。
- **AO**: GTAO（スクリーン空間の環境光遮蔽）で建物の足元や入り隅を暗くする。SMAA でエッジを滑らかにする。
- **地表**: 地理院タイル「全国最新写真」(z17) を平面直角座標に再投影した航空写真（`data/ground.jpg`、`tools/make_ground.py`）。
- **水面**: `Water`（平面反射＋ノイズ法線）。海面が空と建物を映す。
- **建物**: PBR マテリアル。建物ごとに外装の色味を変え、昼はガラス窓の青み、夜は窓明かりを出す。
- **樹木・街灯**: OSM の `natural=tree` / `highway=street_lamp` を InstancedMesh で配置（`header.trees`）。街灯は夜だけ発光する。

影・AO・反射・航空写真・道路の詳細・車の流れはそれぞれチェックボックスで切れる（低スペック機向け）。

### 道路の精密化（車線・横断歩道・歩道・車の流れ）

リアル表示では、PLATEAU の道路面 (LOD1) と OSM の道路中心線から道路を組み立て直す（`tools/road_detail.py`、`src/roads.js`）。

- **車道**: OSM の `lanes` / `oneway` / `lanes:forward` などから車線数を決め、中心線を車線幅 3.25 m × 車線数でバッファしてアスファルト面にする。細街路 (`residential` 等で車線タグ無し) は幅 5 m の共用車線。
- **歩道**: PLATEAU 道路面から車道面を引いた残りを 15 cm 高い面として押し出し、縁石の段差を出す。駅前広場なども歩道扱いになる。
- **区画線**: 外側線 (実線)、中央線 (2 車線は破線、4 車線以上は実線)、車線境界線 (破線 5 m / 5 m)、横断歩道の縞 (幅 45 cm、ピッチ 90 cm、横断歩道幅 4 m)、停止線 (横断歩道の 2 m 手前、進行方向ごと)。横断歩道は OSM の `footway=crossing` の経路と `highway=crossing` ノードから置く (`crossing=unmarked` は除く)。
- **車の流れ**: 車線ごとの走行経路 (左側通行、車線中央をオフセット) に沿って約 4,000 台の車を InstancedMesh で流す。速度は道路種別で変え、夜はヘッドライトとテールランプが点く。橋の上の経路は PLATEAU 橋梁メッシュから路面高さを取る。
- PLATEAU 横浜市 2024 の道路 LOD3 (`14100_tran_lod3`) も確認したが、対象範囲では南端 (桜木町〜関内) にしか無く、3D Tiles に車道/歩道/区画線の属性も入っていないため使っていない。

リアル表示では歩行者ネットワークの破線は自動で非表示になる（チェックで再表示できる）。

### 人の流れ（駅の乗降人員にもとづく推計モデル）

歩行者ネットワーク上に、目的地を持った歩行者を流す（`src/people_model.js`、`src/people.js`）。以前のランダムウォークの粒子は廃止した。**実測の人流データではなく、公表値と仮定から組み立てた仮のモデル**である。

- **発生量**: 各駅の 1 日平均乗降人員を使う。半分が降車（駅→街）、半分が乗車（街→駅）。

  | 駅 | 1 日平均 | 出典 |
  |---|---|---|
  | みなとみらい駅 | 85,853 人（乗降、2024 年度） | 横浜高速鉄道 |
  | 新高島駅 | 13,140 人（乗降、2024 年度） | 横浜高速鉄道 |
  | 馬車道駅 | 44,296 人（乗降、2025 年度） | 横浜高速鉄道 |
  | 桜木町駅（JR） | 72,477 人（乗車、2024 年度。乗降は 2 倍と仮定） | JR 東日本 |
  | 桜木町駅（地下鉄） | 40,139 人（乗降、2024 年度） | 横浜市交通局 |
  | 高島町駅 | 10,031 人（乗降、2024 年度） | 横浜市交通局 |
  | 横浜駅（東口方面） | 約 156,000 人（公表値なし。人流オープンデータの較正で推定。較正前の仮定は 120,000 人） | 推定 |

  参考: みなとみらい21地区の就業者は約 14.4 万人、来街者は約 8,260 万人/年（2024 年、横浜市都市整備局）。モデルの通勤到着は 1 日 約 11.5 万人で、同じ桁に収まる。
- **目的と時間帯（仮定）**: 通勤・来街（買物・観光）・住民の 3 目的に分け（平日 50:36:14、休日 13:72:15）、目的ごとの時間帯分布（通勤は 8 時台と 18 時台にピークなど）を掛ける。加えて昼食（通勤者の 30% が 11:30〜13:30 に近くの飲食へ往復）と回遊（来街者が集客施設の間を歩く）を発生させる。
- **目的地の配分**: 建物ごとの集客力（建築面積 × 階数を延床の目安とし、用途で 1 人あたり面積を変える）と駅からの歩行距離による重力モデル。用途は OSM の `building` / `shop` / `tourism` / `office` タグ、店舗数、名称、高さから推定する（`tools/build_data.py` が建物メタに `u` と `a` を付ける）。公園・緑地（4,000 m² 以上）も来街の目的地。
- **経路**: 駅のホームから建物の最寄りノードまで、歩行者ネットワーク（地下・デッキ・エスカレーター含む）の最短経路。階段・エレベーターには歩行コストの係数を掛ける。
- **表示**: 歩行者は目的別に色分けした点（1 点 = 1 人。リアル表示ではカプセル形の人）。**通行量マップ**はリンクごとの通行量（人/時）を帯の太さと色で示す。パネルには歩行中の人数、最も混む区間、24 時間の推移（目的別）、駅ごとの「駅→街」「街→駅」（人/時）を出す。建物を選ぶと、その建物の出入り（駅との間）の推計も出る。
- **操作**: 時刻スライダー（リアル表示の太陽の時刻と共通）、「1 日を再生」、平日/休日、歩く速さ（見やすさのための倍速）。建設モードで架空ビルを建て替えると、その規模に応じた人流が加わる。

### 人流モデルの較正（国交省 人流オープンデータ）

`tools/fetch_jinryu.py` が「全国の人流オープンデータ（1km メッシュ別の滞在人口）」（国土交通省、G空間情報センター、政府標準利用規約）の神奈川県分を取得し、対象範囲にかかる 12 メッシュの 2019 年の値を `data/jinryu.json` にまとめる。`node tools/calibrate_people.mjs` がモデルをこの実測値に合わせ、係数を `data/people_calib.json` に書く（ビルド時に埋め込まれる）。

- **合わせたもの**: 建物の集客力（業務は平日昼、来街は休日昼の「昼間人口 − 在宅住民」のメッシュ別分布に、住民は深夜人口に合わせる）、横浜駅から対象範囲へ歩く人数（公表値が無く 12 万人/日と仮定していたものを、横浜駅東口メッシュの実測から **約 15.6 万人/日** と推定）、休日の総量係数（0.92 → **1.11**）、月別係数。
- **合わせられないもの**: 時間帯分布。このデータの時間区分は昼（11〜14 時台）・深夜（1〜4 時台）・終日の 3 つだけで、1 時間ごとの値は無い。
- **分かったこと**: 鉄道で来た人の滞在だけでは、実測の昼間人口の約 45% しか説明できない（比率 κ = 2.21）。残りは車・バス・徒歩で来る人やモデル外の滞在。街路の通行量は「駅と建物の間を歩く人」に限った値である。
- **検証表示**: パネルの「検証: 1km メッシュの昼間人口」で、メッシュごとの実測値とモデル値（κ 倍後）を地図上に並べて見られる。対象範囲との重なりが 45% 未満のメッシュは較正に使っていない。

### 混雑度・信号待ち

- **歩道の有効幅員**: 地上の歩道は「PLATEAU 道路面 − 車道」の歩道ポリゴンの中での幅（リンク上の点から境界までの距離 × 2）、それ以外は種別ごとの既定値（階段 2.5 m、エスカレーター 1.2 m、横断歩道 5 m、デッキ 5 m、屋内 6 m、歩行者専用道 10 m など）。OSM に `width` があればそれを使う。`tools/build_data.py` がリンクに幅員とフラグ（横断歩道・屋根あり）を付ける。
- **混雑度**: 流動係数 = 通行量 ÷ 有効幅員（人/m/分）を Fruin の歩行者サービス水準 A〜F で色分けする（帯の表示を「混雑度」に切替。帯の幅は有効幅員に比例）。水準 A を超えると歩行速度が落ち、F で 35% まで下がる。
- **信号待ちの柱**: 「信号待ちの人数を柱で表示」を入れると、横断歩道の手前で待っている人を約 28 m の升目でまとめ、人数を柱の高さと色（黄から赤）で示す。信号の周期で増減するので時間方向にならし、上位 6 か所には人数のラベルを付ける。混雑度の帯は、水準 A でも見えるよう青を濃くし、幅を有効幅員の 1.25 倍（最小 2.6 m）、不透明度を 0.86 にした。
- **信号待ちの分析**: 分析パネルの「集計」に、信号待ちの多い交差点の順位表（上位 10）と 1 日の推移を出す。横断歩道ごとの通行量 q（人/秒）から、平均の待ち人数 = q × R² ÷ (2C)、赤の終わりの最大 = q × R（周期 C = 90 秒、赤 R = 52 秒、到着は一様と仮定）を求め、約 40 m の升目で交差点にまとめる。行をクリックするとその交差点へ移動し、柱の表示が入り、その交差点の推移が全体の線に重なる。「信号待ち CSV」で全交差点の位置、横断の通行量、平均と最大、時刻別の平均を書き出す。歩行者を動かして数える柱とは別の計算で、同じ仮定のばらつきの無い値である。
- **信号待ち**: 横断歩道（OSM の `footway=crossing`、1,269 区間）の入口で、歩行者信号が赤の間は止まる。1 サイクル 90 秒・青 38 秒と仮定し、交差点ごとに位相をずらし、直交する横断歩道は逆位相にしている。車は信号に従わない（未対応）。

### シナリオ（通常時との比較）

- **イベント**（来場者数・時刻は仮定）: K アリーナ横浜の公演（2 万人、18:00 開演 / 21:00 終演）、ぴあアリーナ MM の公演（1 万人）、パシフィコ横浜の展示会（3 万人、10〜17 時）。開演前に駅から会場へ集まり、終演後に一斉に駅へ向かう。利用駅は会場からの歩行距離と駅の規模で配分する。
- **雨天**（仮定）: 屋根の無い区間の歩行コストを 1.7 倍にして経路を選び直す（屋内・地下・屋根付きへ寄る）。来街 0.8 倍、回遊 0.4 倍、公園の集客 0.1 倍。
- **比較**: シナリオ中はパネルに通常時との差（歩行中の人数、最も混む区間、混雑区間の延長、屋根のある区間を歩く割合、イベントの利用駅）が出る。帯の表示を「通常との差」にすると、増える区間が赤、減る区間が青になる。24 時間の推移には通常時の合計が破線で重なる。

### 建物内の人の動き

建物を選択してフロアを展開すると、館内を移動する人が点で流れる（`src/indoor.js`）。入館・退館の量は人流モデルのその建物と駅の間の歩行者から、館内の移動は滞在人数 ×（商業 5 回/時、それ以外 0.5 回/時）から決める。入口は歩行者ネットワークからその建物に入るノード（地上・デッキ・地下）、行き先はフロアガイドや区画のある階ではテナント区画（用途で重み付け、点は用途色）、無い階では執務フロア内の点。昇降は建物の長軸上に 1〜3 か所のコアがあると仮定し、4 層以内はエスカレーター、それ以上はエレベーターの所要時間で移動する。壁や実際の通路形状は考慮していない。

### 分析パネル（ヒートマップ・建物の色分け・建物内・集計・データ）

画面右下の「分析」パネルで、公開データと人流モデルを重ねて見る（`src/analysis.js`）。

- **ヒート**: 10 m 格子のラスタを地表に重ねる。歩行者密度と滞在人口（モデル、時刻に連動）、実測の滞在人口（人流オープンデータ 1km、昼・深夜）、夜間人口と 65 歳以上人口（国勢調査 250m）、従業者数（経済センサス 500m: 全産業、小売・飲食・宿泊、宿泊業、集客施設、百貨店）、病院・診療所の数、用途地域と指定容積率（PLATEAU）、店舗・飲食店の密度（OSM）、最寄り駅までの徒歩時間。カーソル位置の値が読める。
- **建物の色分け**: 滞在人数、出入りのピーク、推定用途、高さ、津波・高潮・洪水の浸水深（PLATEAU の建物属性）、最寄り駅までの徒歩時間。
- **比較**:
  - 画面分割: 画面を左右に分けて 2 つの指標を同じ視点で並べる。境界線はドラッグで動かせる。
  - 差分ヒートマップ: 休日 − 平日、シナリオ − 通常、現在 − 1 時間前。増える場所が赤、減る場所が青。
  - 散布図: 250m メッシュ単位または建物単位で 2 指標の関係と相関係数を出す。点をクリックするとその場所へ移動する。
  - 範囲集計: 地図をドラッグして四角形で囲むと、歩行中・滞在（モデル）、実測の昼間人口、夜間人口、従業者数（メッシュ統計は面積按分）、建物数、店舗数が出る。
- **推移**: 対象範囲の全体、選択中の建物（滞在・来る・出る）、地点（区間の通行量とピーク時の混雑度）、選んだ範囲について 24 時間のグラフを出す。平日と休日を重ね、シナリオ中は通常時も併記する。グラフをクリックするとその時刻に移動する。
- **建物内**: 建物を選ぶと、階ごと・区画ごとの推計滞在人数（棒グラフと上位の区画）、階別の用途構成、その建物の属性、内部について使えるデータの有無が出る。
  - 「商圏・回遊の流線」で、その建物にどの発着点（駅・駐車場など）から何人来るかと、次にどの建物へ向かうか（回遊・昼食）を、立体の弧と表で示す。
  - 「フロアと区画を推計人数で色分け」で、展開したフロアと区画がヒートマップになる。
  - 「通路の動線密度」は、区画形状のある階で、建物の外形から区画を除いた部分を通路とみなした 1.5 m 格子を作り、昇降コアと入口から各区画の前までの最短経路を重ねたもの。館内を歩く人もこの通路に沿って動く。通路の形が取れていない階は階全体を歩ける前提になる。昇降コアの位置は仮定である。
  - フロアガイドのある建物（MARK IS、ランドマークプラザ、クイーンズスクエアなど）を、店舗数・用途構成・階ごとの店舗数・推計滞在人数で並べて比較できる。
  - 階ごとの人数は、建物の滞在人数を階と区画の用途で按分した推計である。
- **集計**: 歩行中・滞在（モデル）、実測の昼間人口、夜間人口、従業者数、津波浸水想定 0.5 m 以上の建物数とそこに滞在する推計人数。滞在人数の多い建物と通行量の多い区間のランキング（行をクリックで移動）。西区・中区に滞在している人の発地構成（人流オープンデータ、区単位）。建物指標 CSV、区間の通行量 GeoJSON、メッシュ統計 CSV を出力できる（緯度経度は原点からの近似変換）。
- **データ**: 使っているデータと、調べたが使えなかったデータの一覧。

### 昇降コアの実位置（MARK IS・ランドマークプラザ・クイーンズスクエア）

`tools/extract_cores.py` が公式フロアマップから、エレベーターとエスカレーターの位置を取り出し、`data/cores.json` に書く。下敷き画像と同じ変換で世界座標にし、館内の人の動きと動線密度の昇降コアに使う（無い建物は長軸上の仮定位置）。

| 施設 | 検出の方法 | エレベーター | エスカレーター | 階数 |

| MARK IS みなとみらい | エレベーターは「北・中・南」の色つきマークを色で検出。エスカレーターは凡例の絵記号と照合（大きさを 3 段階に変えて試す） | 18 | 27 | 8 |

### 鉄道以外の来訪者と車の信号

- **鉄道以外の来訪者**: 駐車場 397 か所、バス停 101 か所（OSM）、対象範囲の外周のノードを発着点に加え、最寄りの発着点からの距離で目的地を配分する。総量は、較正で分かった「鉄道だけでは実測の昼間人口の約 45% しか説明できない」分（鉄道の κ − 1 = 1.21 倍）。パネルのチェックで切れる。駐車場の多くは建物内にあるため、車で来る人は街路をほとんど歩かない。
- **手段の内訳（公開データからの見積もり）**: `tools/mode_split.py` が `data/mode_split.json` を作り、ビルド時に較正結果へ合流する。当初は 車 50%・バス 15%・徒歩/自転車 35% と仮定していたが、次の見積もりに置き換えた。

  | 手段 | 平日の内訳 | 平日（片道の人数） | 休日（片道の人数） | 根拠 |
  |---|---|---|---|---|
  | 車 | 11% | 約 32,000 人 | 約 46,800 人 | 駐車場の収容 約 28,100 台 × 回転率 0.88 回/日 × 1 台あたり 平日 1.3 人・休日 1.9 人 |
  | バス | 19% | 約 55,900 人 | 約 46,400 人 | 国土数値情報 バスルート（N07, 2011 年度）の範囲内 176 系統、平日 4,658 便・日祝 3,863 便 × 1 便あたり 12 人 |
  | 徒歩・自転車・その他 | 71% | 残り | 残り | 総量から車とバスを引いた残り。範囲内の居住者や宿泊者も含む |

  - **駐車台数の実数**: 主要 16 施設の収容台数（計 9,759 台）を `data/parking_facilities.json` に持ち、出所の種別を `kind` に書いている。

    | 種別 | 施設数 | 台数 | 施設 |
    |---|---|---|---|
    | 公式情報で確認 | 9 | 7,794 | クイーンズスクエア横浜 1,700、横浜ランドマークタワー 1,400、みなとみらい公共駐車場 1,154、MARK IS みなとみらい 900、横浜ワールドポーターズ 約 800、横浜ベイクォーター 730、そごうパーキング館 560、横浜ハンマーヘッド 350、横浜市馬車道地下駐車場 200 |
    | 駐車場案内サイトの掲載値 | 7 | 1,965 | 横浜駅東口地下 500、タイムズ HULIC みなとみらい 483、スカイビル 400、横浜野村ビル 190、パシフィコ横浜ノース 152、横浜三井ビルディング 151、横浜北仲ノット 89 |

    案内サイトの 7 施設は、公式サイトに台数の記載が無いか、公式サイトへ接続できなかった。横浜赤レンガ倉庫の 179 台（公式）は平面駐車場として OSM の面積に含まれるので足していない。そごう横浜店は契約駐車場を含めて約 2,500 台と案内しているが、他の施設と重なるため使っていない。
  - **台数が分からない施設の補正**: 延床 20,000 m² 以上の 78 施設は「延床 250 m² に 1 台」で見積もり、実数が分かる施設での 実数 ÷ 見積もり の比（0.51）を掛ける。補正前は 23,915 台、補正後は 12,296 台。以前はこの補正が無く、館内駐車場を 41,313 台と過大に見ていた。
  - **それ以外の収容台数**: OSM の capacity タグ 281 台、平面駐車場の面積 ÷ 27 m² で 4,440 台、立体駐車場（5 階と仮定）1,306 台。
  - **発着点**: 実数が分かる施設は、その施設の位置も車の発着点に加える。
  - 回転率は、みなとみらい公共駐車場の利用実績（横浜市会資料、2012 年度 369,328 台）を収容 1,154 台と 365 日で割った値。商業施設の駐車場はこれより高い可能性がある。
  - 1 台あたりの人数と、バス 1 便あたりの降車人数は仮定。
  - 横浜市は、みなとみらい 21 地区の年間来街者数（2024 年 約 8,260 万人、2025 年からは人流データによる推計で約 1 億 180 万人）を公表しているが、手段別の内訳は公表していない。
- **バスの現行ダイヤ（GTFS）への置き換え**: `tools/fetch_gtfs_bus.py` が GTFS / GTFS-JP の zip から、範囲内のバス停に停まる便数を 平日・土曜・日祝 と 時間帯別 に数えて `data/bus_gtfs.json` に書く。これがあると `mode_split.py` は、その事業者の系統を N07（2011 年度）の本数ではなく現行の便数に置き換え、時間帯別の便数をバスで来る人の時間帯分布の重みに使う（1 日の合計は変えない）。横浜市営バスの GTFS-JP は公共交通オープンデータセンターで公開されているが、開発者サイトでの利用者登録で発行されるアクセストークンが必要なため、**実データはまだ適用していない**（試験用の小さな GTFS で処理が通ることだけ確認した）。市営バスは範囲内 176 系統のうち 59 系統を占める。京浜急行バス、相鉄バス、神奈川中央交通の GTFS は同センターに掲載が無く、神奈川県の GTFS データリポジトリにも範囲内を走る路線バスの掲載は無かったので、市営バス以外は当面 N07 のままになる。

  ```bash
  ODPT_KEY=<アクセストークン> python3 tools/fetch_gtfs_bus.py   # または手元の zip を引数で渡す
  python3 tools/mode_split.py && npm run build
  ```
- **車の信号対応**: 車線と横断歩道の交点（1,808 か所）を停止位置とし、歩行者信号が青の間、車はその手前で止まる。前の車との車間も保つ。時間の進み方は歩行者と同じ倍率にしている。すべての横断歩道に信号があるとみなしており、交差点内の右左折や車どうしの信号制御は扱っていない。

### ガイドツアー

左パネルの「ガイドツアー」で、場面ごとに視点・時刻・テーマ・人流と分析の表示を切り替え、画面下に説明文を出す（`src/tour.js`）。説明文の人数はその場面の推計値をその場で計算して入れる。「前へ」「次へ」、丸印で任意の場面へ、自動再生（1 場面 13 秒）、矢印キーと Esc に対応。終了すると開始前の表示に戻る。

| # | 場面 | 切り替える内容 |
|---|---|---|
| 1 | 街の全体像 | 平日 15 時、通行量の帯と歩行者 |
| 2 | 朝の通勤 | 8:15、歩行者を軌跡で表示 |
| 3 | 混雑と信号待ち | 8:30、帯を混雑度（サービス水準）に、信号待ちの人数を柱で、桜木町駅前 |
| 4 | 昼の滞在 | 12:30、滞在人口を立体の柱で |
| 5 | 等値線で見る歩行者密度 | 12:30、歩行者密度の等値線と数値 |
| 6 | 建物の中の動き | MARK IS を階分解し、動線密度を床に表示 |
| 7 | どこから来て、次にどこへ行くか | ランドマークプラザの商圏の弧 |
| 8 | K アリーナ横浜の終演 | 夜景、21:15、通常時との差 |
| 9 | 雨の日 | 晴れの日との差 |
| 10 | 浸水のリスク | 建物を高潮の想定浸水深で色分け |

**編集**: 説明文の箱の「編集」で、場面を追加・変更できる。

- 「今の表示を追加」: 今の視点・時刻・テーマ・人流と分析の表示を、いまの場面の次に新しい場面として入れる。「今の表示で上書き」はいまの場面を置き換える。
- 題と説明文はその場で書き換えられる。説明文には `{時刻}` `{歩行者数}` `{信号待ち}` `{駅から街へ}` `{街から駅へ}` を差し込め、表示のたびにその場面の推計値に置き換わる。
- 並べ替え、削除、「初期に戻す」。組み込みの場面を書き換えると、その時点の内容を固定した場面に変わる（丸印に橙の縁が付く）。
- 編集内容はブラウザに自動保存される（localStorage）。「ファイルに保存」で `minatomirai_tour.json` を書き出し、「ファイルを読込」で他の人の環境でも同じツアーを再生できる。
- **表示秒数**: 自動再生でその場面を見せる秒数を場面ごとに指定できる（3〜120 秒、既定 13 秒）。

**発表向け**:

- 「発表」: 左右の操作パネルを隠して説明文を大きくし、できる環境では全画面にする。矢印キーで前後、スペースで自動再生の開始と停止、Esc で戻る。
- 「HTML に書き出す」（編集の中）: 全場面を順に表示して画像を撮り、題・条件・説明文と並べた 1 つの HTML（`minatomirai_tour.html`）を保存する。目次付きで、印刷にも使える。

### 見やすさの調整

- **商圏の弧のラベル**: 太い弧から順に置き、画面上で重なる場合は弧に沿って位置をずらす。どこにも置けないものは隠す（視点を動かすたびに再計算）。
- **等値線**: 画面上の太さを指定できる線（three.js の `LineSegments2`）で 2.6 px に太くし、各等値線の上に値のラベルを置く（互いに 320 m 以上離して最大 3 個、最上位の値には単位を添える）。
- **歩行者の軌跡**: 同じく太さ 2.4 px の線にし、長さと尾の濃さを上げた。

### 表示状態の保存・共有とレポート

「集計」タブから、現在の表示（テーマ、時刻、月、曜日、シナリオ、視点、選択中の建物、分析パネルの設定）を保存できる。

- **リンクをコピー**: 状態を URL の `#s=…` に入れる。そのリンクで開くと同じ表示になる。
- **状態を保存 / 読み込む**: 同じ内容を JSON ファイルで保存・復元する。
- **レポートを出力**: 表示中の地図の画像、凡例、主要指標、ランキング、サンキー図、推移グラフ、散布図、範囲集計、選択中の建物の内訳、再現用リンク、データの出典を 1 つの HTML にまとめる。

### 建設モード（架空の商業ビル）

左パネル「建設モード（架空ビル）」で、架空の超高層商業複合ビル「みなとみらい セントラルタワー（架空）」を
その場で生成・配置できる（`src/construct.js`）。既定は新高島駅南西の空き街区、高さ 331 m（85 階＋冠部）でエリア最高。
階数・商業層数・低層部幅・塔の幅・オフィス比率・向きをスライダーで変え、「敷地を指定」で地図をクリックすると
その位置に建て直す。既存建物との重なりを警告し、延床面積の概算を表示する。
低層部の商業テナントは MARK IS の階ごとの用途構成比を参考に架空名で生成し（source=fictional）、上層はオフィス／
ホテル／展望に割り当てる。正面エントランスは歩行者ネットワークに接続され、人流・経路検索の対象になる。
「評価」ボタンで、エントランスから各駅までの最短歩行距離（Dijkstra）と、指定階からの 24 方位の眺望
（遮蔽建物までの距離、海が見える方位）をコンパス図で表示する。画面上では「架空の建物」と明示する。
点描・ボクセル表現と断面キャップは架空ビルには適用されない。

### ランドマークプラザの区画形状

`extract_zones.py` はランドマークプラザの公式マップからグレーの区画面も抽出する（番号なし）。画面では区画の
形状だけを描き、OSM の店舗 POI がその区画内にあれば店名と用途を付ける。2〜4F は塗りが薄く検出数が少ない。

### 手入力

`data/floorguide.csv` に「建物名, 階, 区画記号, テナント名, 用途, 幅比, 出典」を書くと、建物選択時に各階を
主軸方向の帯で区画分けして描画し、用途色（飲食／物販／サービス／オフィス／医療／公共／宿泊）で塗る。
画面右パネルの「この建物の CSV 雛形」で階数ぶんの空行入り CSV を書き出し、編集後に「CSV 読み込み」で即時反映できる
（ビルド不要）。`tools/make_floorguide_seed.py` は OSM の階層つき店舗 POI から雛形を生成する。

```
building,floor,zone,name,category,share,source
MARK IS minatomirai,4F,A,KAMAKURA,飲食,1,osm
MARK IS minatomirai,4F,B,HONOLULU COFFEE,飲食,1,osm
```

クイーンズスクエア横浜・ランドマークプラザ・MARK IS など、PLATEAU で複数部位に分かれる大型施設は
`MERGE_NAMES`（build_data.py）で 1 棟に統合している。

## テナント・区画データについて

- 区画（テナント境界ポリゴン）やフロア構成は PLATEAU にも OSM にも含まれないため、本ツールでは
  「建物の高さ ÷ 階高 3.6m」で階を推定し、OSM の `level` タグを持つ店舗 POI をその階に置いている。
- 大規模商業施設（MARK IS、ワールドポーターズ、コレットマーレ等）は OSM の登録が多く、フロア別に表示できる。
  オフィスビルは登録が少ない。区画まで正確に出すには、施設側のフロアガイド等を別途入力する必要がある。

## 座標系・階層

- 原点: みなとみらい駅（EPSG:6677 で E −18292.7, N −60134.6）。three.js では x=東, y=標高, z=南。
- 対象範囲: 原点から 西 1.3 km／東 1.5 km／南 1.35 km／北 1.2 km（横浜駅東口〜新高島〜みなとみらい〜桜木町〜新港・赤レンガ〜馬車道・北仲）。
