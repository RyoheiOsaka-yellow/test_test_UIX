修繕データ一元管理「AAA」プロトタイプ

社内試用の進め方およびデモ台本(案)

作成日2026年11月18日
版第1版(案)
対象試用の進行担当者

1. 試用の目的

  1. プロトタイプの画面構成と操作の流れが、担当者の実務(物件の状況把握、オーナーへの説明、指摘の記録)に合うかを確認する。
  2. 迷う箇所、分かりにくい表示、不足している情報を、モック完成(12月末)までに洗い出す。
  3. 現地での指摘登録について、入力の手間が許容できるかの感触をつかむ。

2. 実施要領

対象者担当者(営業・管理)3〜5名。可能であれば点検担当者1名を含める
所要時間1名あたり30分(デモ5分、操作課題15分、聞き取り10分)
形式1対1。進行担当者が横で操作を観察し、気づきを記録する
使用する物プロトタイプのHTMLファイル(tatemono-karte.html)、PC(Edge または Chrome)。可能であればiPadも用意
記録試用者は画面右下の「意見を送る」、進行担当者は本書末尾の観察記録票に記入

3. 事前準備

  • HTMLファイルを試用に使う端末に保存し、ダブルクリックで開けることを確認する(iPadはファイルアプリから開く)。
  • 左メニュー下の「デモを初期状態に戻す」を押し、前の試用者の操作内容を消しておく。
  • 前の試用者の意見を回収済みであることを確認する(5章)。
  • 表示データはすべて架空であること、操作内容は保存されないことを試用者に伝える準備をする。

4. デモ台本(5分)

進行担当者が操作しながら説明する。…は説明の例。

時間画面・操作説明のポイント
0:00ダッシュボード修繕に関する情報を1か所にまとめ、今どこに手を打つべきかが分かる画面です
早急対応の件数、オーナー未提案の件数、点検・審査の期限を示す。
0:45「優先して動く案件」の行を押す → 物件詳細(サンライズコート石神井)物件ごとに、状態・指摘・試算・履歴・やり取りがまとまっています
配置図の番号と写真、対応状況の変更(変更後に「元に戻す」が出ること)を示す。
2:00「AAA(説明用)で開く」→「お客様に見せる」オーナー様にはこの画面を見せながら説明します。社内メモなどは自動で隠れます
①建物の状態 → ②修繕箇所 → ③先送りした場合の費用(約280万円の追加)→ ④履歴の順に見せる。
3:30「お客様向けレポートを開く」同じ内容をA4のレポートとしてお渡しできます
「説明画面に戻る」で戻り、「社内表示に戻す」を押す。
4:15物件詳細 →「指摘を登録」現地ではiPadからこの画面で指摘を記録します
配置図を押して位置を指定できることだけ示し、入力は試用者に任せる。

5. 操作課題(15分)

試用者に次の課題を口頭で伝え、説明なしで操作してもらう。進行担当者は手を出さず、迷った箇所・探した箇所・口にした疑問を記録する。

#課題確認したいこと目安
1あなたの担当物件のうち、オーナーへの提案が止まっている案件を見つけ、その物件のオーナー向け説明を準備してくださいダッシュボードから目的の物件にたどり着けるか。説明用画面の存在に気づくか5分
2「グリーン常盤」で、外壁にひび割れを見つけたとします。写真付きで指摘を1件登録してください配置図での位置指定、必須項目、写真の追加で迷わないか。入力にかかる時間5分
3防水工事を過去に行った物件を探し、金額の合計を確認してください全体検索、指摘・修繕データの絞り込みが使えるか3分
4気づいたことを「意見を送る」から1件以上送ってください意見の送り方が分かるか2分
課題2では、写真は「デモ用のサンプル写真を追加」で代用してよい。iPadで試す場合は「撮影・写真を選ぶ」から実際に撮影できる。登録した内容は再読み込みで消える。

6. 聞き取り(10分)

  1. この画面を実際の業務で使う場面はありますか。それはどんなときですか。
  2. オーナーへの説明で、足りない情報や、逆に見せたくない情報はありましたか。
  3. 今のやり方と比べて、手間が増えると感じた所はどこですか。

7. 意見の回収とまとめ

  1. 試用後、「意見を送る」→「これまでの意見を見る」→「CSVで書き出す」で意見を回収する(ファイル名: AAA_feedback_日付.csv)。
  2. CSVと観察記録票を、進行担当者がまとめて共有フォルダに保存する。
  3. 「デモを初期状態に戻す」を押してから、次の試用者に交代する。
  4. 週次定例会議で、集まった意見を「直す・保留・やらない」に仕分ける。
意見は端末のブラウザ内に保存される。ブラウザの閲覧履歴の削除や、プライベートモードでの利用では消えるため、試用ごとに回収する。
