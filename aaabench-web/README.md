## これは何か

エージェント一体。ブラウザで動く実物のレンダラ。MCP 越しの制御面。厳しい要求書と、production
知識の棚。人間の助けはない。

地形も、区画も、道路も、建物も、人も、交通も、天候も、ゲーム自身の画面も、壊れたときに何を直すかも、
すべてエージェントが決める。誰も何も指差さない。

```bash
./bin/setup-capabilities.sh    # 依存・プロジェクト・ブラウザ・性能キャリブレーション
./bin/prep-project.sh          # センサーが答えるか確認してから走らせる
./bin/run-agent.sh             # ゲームを起動し、要求書を渡し、走り続けさせる
```

> **唯一のルール。** 条件・資源・要求は与えてよい。診断・修正・答えは絶対に渡さない。
> モデルが自分の失敗に**自分で気づくか**が測定対象なので、ヒントは一つ残らず「もう主張できない結果」に
> 変わる。[`HARNESS-RULES.md`](HARNESS-RULES.md) を読むこと。

## 本家との違い

| | ukanwat/aaabench | この移植版 |
|---|---|---|
| エンジン | Unreal Engine 5.8（要インストール、macOS 前提） | three.js + WebGL2（`npm install` だけ） |
| 制御面 | Epic の MCP サーバ + VibeUE | 常駐 headless Chromium を包んだ自作 MCP サーバ（`mcp/server.mjs`） |
| 目 | エディタのビューポートキャプチャ | Playwright のスクリーンショット + フレーム内容の自動判定 |
| 再生 | Play-In-Editor | 実キー・実マウスを流し込む `play`（入力が何かを動かしたかを報告） |
| 性能予算 | 実 GPU 上の絶対 fps | **空ステージ比**（GPU 非搭載機ではソフトウェアラスタライズになるため）+ 描画コール等の絶対値 |
| 動作要件 | UE5 が入った Mac | Node 22 と Chromium があるコンテナ |

要求書（`PROMPT.md`）とハーネス規則の**思想は本家そのまま**で、対象エンジンに合わせて書き直してある。

## 何を測っているのか

世界を作らせることは、異様に完全なテストになる。既知の課題のパターン照合では通らないからだ。

- **現実世界の理解。** 深い水がどこに港を決めるか。工業が鉄道と水に沿うこと。金が丘の上・風上に建つこと。
  日照が街路の高さを縛ること。裁判所の周りに保釈保証屋が生えること。これを知らずに作られた街は、
  専門知識のない誰が見ても一瞬で「嘘」に見える。
- **例ではなく原因からの推論。** 「見栄えがいいからそこに置いた」を要求書が禁じている。すべての区画・
  街区・敷地が、地質・水・交易・金・法・時間のいずれかから導出できなければならない。
- **長期実行。** 一つのコンテキストに収まらない仕事。冷たく始まるセッション。連続性は、エージェントが
  自分で書き残したものだけ。誰も再開させてくれない。
- **書くこと。** 設定資料、キャラクター、ミッション、看板、ブランド、通りの名前。散文は飾りではなく、
  設計そのものが起きる場所であり、そのまま品質として読める。
- **自己検証。** エージェントには目がある — ビューポートキャプチャ、実プレイ、自分のスクリーンショット、
  そして実写の参照画像。自分の仕事を見て、他人なら「作り物だ」と言う点に気づき、言われる前に直せるか。
  **気づくかどうか**が測定対象。
- **システム思考。** 交通、群衆、時刻、天候、経済 — 独立したシステムが互いに交差し、フレーム予算の中で
  「振る舞う」こと。
- **敵対的な表面での工学。** 落ちるビルド、思い出せず発見するしかない API、黙って失敗するツール、
  もっともらしい数値で不可能な場所を記述するジェネレータ。

成果物の見出しは「遊べる世界」。面白いデータは、その上の全部。

## 中身

```
PROMPT.md            要求 — これがベンチマーク本体
HARNESS-RULES.md     運用と「エージェントの仕事」の境界線
bin/                 走らせる・生かし続ける・動いているか確かめる
tools/               エージェントの道具：目、計器、プレイ、参照写真
mcp/                 制御面（MCP stdio サーバ）
docs/                参照してよいハンドブック
project/             three.js プロジェクトの骨組み（空のステージ + センサー契約）
.claude/skills/      16 のスキルパック
```

| パス | 中身 |
|---|---|
| `PROMPT.md` | **要求。** 規模、基準、失敗とは何か、必要な内容。これがベンチマーク |
| `bin/run-agent.sh` | 1 セッション：dev サーバ起動、センサー確認、要求書の受け渡し、停止したら再開、使用量制限や 5xx は nudge を消費せず待つ |
| `bin/supervise.sh` | ランナーを 1 つだけ、無期限に生かす（持久力の測定） |
| `bin/run-many.sh` | 毎回**コールドスタート**で N セッション（連続性の測定） |
| `bin/health.sh` | プロセス、ポート、進捗、エージェントの生存、`--deep` で描画確認 |
| `tools/viewport.mjs` | 名前付きポーズからの撮影。フレームが「単色＝何も描かれていない」かを毎回判定して報告 |
| `tools/qa.mjs` | 統計・シーン記述・エラー・性能・予算判定・キャリブレーション |
| `tools/play.mjs` | 実入力でのプレイセッション。**入力で何かが動いたか**を報告 |
| `tools/refs.py` | 実写参照（Openverse、キー不要、ライセンス表示付き） |
| `mcp/server.mjs` | 常駐ページを持つ MCP サーバ：capture / describe / perf / console / eval / play / reload |
| `project/src/engine/harness.js` | センサー契約 `window.__aaabench`。外から世界を見るための唯一の窓口 |

## 設計上、重要な判断

- **画像はパスで返す。インラインでは返さない。** 1600×900 の PNG は base64 で 1 MB を超える。
  この作業に必要な「見る」頻度でインライン化すると、コンテキストが思考ではなく転送に消える。
- **平坦フレーム検出。** キャプチャのたびに輝度平均・分散・色数をサンプルし、`FLAT — one colour`
  なら「何も描かれていない／カメラがジオメトリの内側／マテリアルが壊れた」と先に言う。
  灰色の虚空を撮った PNG と街を撮った PNG はファイル名では区別できず、この取り違えがこのループで
  最も高くつく。
- **性能予算は空ステージ比。** GPU がない環境では ANGLE が SwiftShader に落ちる。絶対 fps を目標に
  すると「世界」ではなく「機械」を最適化することになるので、`.harness-baseline.json` に空ステージの
  コストを記録し、その 2 倍（上限 4 倍）を予算とする。描画コール・三角形・テクスチャ・ヒープは絶対値。
- **`play` はカメラの移動量を報告する。** 「4 秒 W を押して 0.0m」は、スクリーンショットには写らない
  ビルドの事実。

## 結果を公開するときに一緒に出すもの

正確なモデル ID、エージェント CLI、実行機と **GPU の有無**、`.harness-baseline.json`、セッション数と
実時間、コールドスタートと再開の内訳、そして**汚染ログ**。空の汚染ログは既定値ではなく、一つの主張。
