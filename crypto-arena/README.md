# Crypto.com Arena — 1to1 マーケティング基盤 (xStadium Digital Twin)

ブレックスアリーナ宇都宮版デジタルツインと**同一のアーキテクチャ文脈**で
Crypto.com Arena (Los Angeles) を再現し、その上に **個客 (1to1) レベルの分析基盤** を実装したもの。

**➡ [`index.html`](index.html) を開くだけで動きます**（単一ファイル・3.8MB・外部依存なし・完全オフライン）

- 所在: 1111 S Figueroa St, Los Angeles, CA / 中心 34.043018, -118.267254
- 収容: **19,079**（バスケ）/ 18,250（アイスホッケー）/ 20,000（コンサート）
- 開業 1999-10-17 / 設計 NBBJ / 建設費 $375M
- テナント: Lakers (NBA) / Kings (NHL) / Sparks (WNBA) / コンサート興行

| モード | 内容 |
|---|---|
| **SOLID** 実体 | 押し出し建物・道路リボン・地表 |

| **WIRE** 線画 | 稜線のみ |

**移動経路モデル**（ご要望）

`tools/` の道路データから **19,743ノードの道路グラフ**を構築し、A*（バイナリヒープ + 空間ハッシュ）で
実経路を探索する。歩行者はフリーウェイを歩けず生活道路を選び、車両は幹線を優先する。

| 出発地 | 交通手段 | 距離 |
|---|---|---|
| Pico 駅 (Metro A/E) | METRO | 338 m |
| 7th St/Metro Center (A/B/D/E) | METRO | 1,412 m |
| I-110 北 / 南 オフランプ | CAR | 767 / 1,673 m |
| I-10 東 オフランプ | CAR | 1,162 m |
| L.A. LIVE 駐車場 | CAR | 366 m |
| ライドシェア降車ゾーン | RIDESHARE | 1,419 m |

| DTLA 徒歩 | WALK | 1,644 m |

- 出発地の構成比は **1to1レイヤーの商圏分布（AGG.reg）に追従**する
- 人流エージェントは到着カーブに沿って走り、人数カウンタはカーブの積分から出す
  （表示球は「1体 ≒ N人」のサンプル）
- 退場後は **直帰3種 + 周辺回遊4先**に分岐し、`場外消費 = Σ 人数 × 客単価` を算出。
  これは**アリーナが街に落とす金額**として自治体・周辺事業者向けの数字になる

**賑わいヒートマップ（通り単位・31,758セグメント）**
通常日の素の賑わい（POI・商業地・駅）／試合日／**アリーナ寄与（差分）**を切り替え。
興行が周辺のどの通りにどれだけ人を落としているかが読める。

**OD分析**

可視化（KDEサーフェス + 16本のグラデーションアーク、タイムライン再生で質量が移動）に加え、
**分析ボードの「OD・移動」タブ**で数字として回せる。

- **出発地別サマリ** — 人数 / シェア / 平均距離 / 平均所要 / 平均LTV / チケット収益 / 場内購買
- **交通手段分担** — 商圏別のモード分担表から算出（CAR 54% / RIDESHARE 20% / METRO 14% / WALK 12%）
- **駐車需要 vs 供給** — 車利用者 ÷ 2.6人/台 と、OSM駐車場ポリゴンの実面積（1台=28m²換算）を突き合わせる
- **OD行列** — 商圏 × 出発地
- **出発地 × 席ティア** — 「遠方 × プレミア」を特定してパッケージ販売の対象にする
- **ゲート別負荷** — ターンスタイル25通り・2.2人/分での捌き時間
- **退場OD** — 回遊先 × 人数 × 客単価 × 場外消費（年間の地域経済インパクト）

所要は**ドアツードア**推計：当日移動距離 ÷ 手段別速度（近距離ほど遅く長距離は速い関数）
＋ 端末アクセス徒歩（実道路経路長 ÷ 80m/分）＋ 待ち時間（Metro 7分 / 配車 6分 / 駐車 9分）。
州外・海外客は市内に宿泊している前提で、**居住地距離ではなく宿泊拠点からの距離**を使う。

**到達圏（等時線）** — 道路グラフ上の Dijkstra。車は 3/6/9/12/15分、徒歩は 5/10/15/20/30分でバンド分け。
リンク速度は道路クラス別（車 12〜54km/h・試合日実勢 / 徒歩 4.8km/h）。
バンドごとの道路延長と建物棟数を出し、**圏内の受け皿規模**の代理指標にする。

**座席レイヤー「来場OD」** — どの出発地から来た席かで3D座席を着色し、出発地で絞り込める。
選択中の出発地の席ティア内訳・セグメント内訳が同時に出るので、**OD × 席の交差分析**ができる。

**交通インフラの正確な再現**（ご要望）
OSM の `bridge` / `tunnel` / `layer` タグを反映し、**高架は橋桁＋橋脚を立体で生成、
地下は半透過で地下断面として可視化**。

- フリーウェイ **I-110 Harbor Fwy / I-10 Santa Monica Fwy**（ランプの高架構造まで）
- 幹線 Figueroa St / Olympic Blvd / Pico Blvd / Chick Hearn Ct
- **Metro A / B / D / E Line** を公式ラインカラーで描き分け（B・D Lineは地下・半透過）
- 最寄 **Pico 駅**（A/E Line）はアリーナ中心から 280m。7th St/Metro Center ほか駅マーカー12件

## 2. 1to1 マーケティングレイヤー

**19,079席 = 19,079の顧客接点。** 1席1レコードで個客属性・取引・行動・媒体露出を保持する。

### 席マッピング演出
L2 に初めて入ると、**19,079席が1席ずつ生成されながら個客レコードに紐づいていく**掃引が走る。
コート中心から外周・上層へ進み、掃引が通過するまで座席そのものが存在せず、
通過時に少しオーバーシュートして着地する。パネルの「▶ 席マッピングを再生」で再生でき、
**点群ビューでも同じ演出**が走る。

### 発火時刻モデル
個客ごとの入場時刻から逆算する。500m圏接近 = 入場−12分、着席 = 入場+6分、
退場ゲート = 22:02 + **上層ほど遅い**（ボミトリー〜コンコースの捌け）+ ばらつき。
1興行あたり **24,821件** の配信がスケジュールされる。

### コンソール画面
- **ジャーニー一覧** — フェーズ別。クリックでON/OFF、対象人数・配信済み・増分売上・コストを表示
- **リアルタイム配信ストリーム** — 誰に・いつ・どのチャネルで・**何と書いて**送ったかが流れる。
  クリックするとその個客の3D座席へ飛ぶ
- **フェーズ別 時間分布** — 配信がいつ集中するかを積み上げで表示。現在時刻カーソル付き
- **効果サマリ** — フェーズ別増分売上 / チャネル別対象人数 / ジャーニー別ランキング
- **配信ログCSV** — 発火時刻・ジャーニー・トリガー・チャネル・fan_id・席・文面 まで出力

効果は**コントロール群との差分（増分）**のみを計上する。
座席レイヤー「**接触本数**」で、どの席の個客に何本のジャーニーが当たっているかを3Dで見られる。

### 座席レイヤー（12種）
観客 / **セグメント** / **来場OD** / **抽出セグメント** / **接触本数** / **LTV** / **離反リスク** / 販売率 / 席種 / **スポンサー露出** / **視認等級** / 価格最適化

### 個客プロファイル（座席クリック）
`fan_id` ・セグメント・商圏・年代・LTV・来場回数・継続年数・今回の取引（定価/実売/入場時刻/ゲート）・
場内購買・**RFM**・**更新見込**・**この席から見える媒体と視認等級**・**Next Best Action（期待CVR上振れ・想定増分）**

### 分析モデル

| 指標 | 式 |
|---|---|
| 媒体露出重み | `w = 正対度^0.8 × 視線一致^0.5 ÷ (1 + (視距離/22)^1.35)` |
| 視認等級 | 文字視角 `arcmin = 文字高 ÷ 視距離 × 3437.75`　A≥60′ / B≥35′ / C≥18′ / D≥8′ |
| 実効露出単価 | `年間契約額 ÷ (実効露出 × 年44興行)` = 1人に1試合しっかり見られる単価 |
| 媒体デリバリー額 | `Σ (年間契約 ÷ 44) × (今回の実効露出 ÷ 満席時の実効露出)`（シーズン積算で契約総額に一致） |
| 価格最適化 | `f = 0.74 + 0.40×区画販売率 + 0.12×露出 + 0.08×需要弾性`（0.82〜1.32） |
| 離反リスク | セグメント基準離反率 × (1 − 0.34×ロイヤルティ) + 右裾ノイズ |

### セグメントビルダー & キャンペーン試算

1to1施策の「**対象定義 → 効果試算 → 実行データ**」を一画面で回す。

1. **対象を定義** — セグメント / 商圏 / 交通手段 / 席ティア / LTV下限 / 更新見込上限 /
   来場回数下限 / 露出スコア下限 / オプトイン / アプリ保有
2. **規模と価値をライブ集計** — 人数・LTV合計・平均LTV・平均更新見込・チケット収益・場内購買・配信可率。
   条件を変えると **3Dの座席が即時に光る**ので、対象がどのブロックに固まっているかが分かる
3. **キャンペーン試算** — チャネル5種（メール / アプリPush / SMS / 運用型広告 / DM）×
   オファー8種。**コントロール群と施策群の差分（増分）だけを成果に計上する**アップリフト評価で、
   増分CV・増分売上・増分CPA・**増分ROAS**を出し、成立可否を判定する
4. **CRM用CSV書き出し** — fan_id・席・属性・RFM・更新見込・OD・NBA を付けて出力

チャネル単価・反応率は業界実勢レンジの初期値。`crm_engagement.csv`（配信ログ）を投入すると
自社の実績値に置き換わり、試算がそのまま実績ベースの予測になる。

### ツール
- **2D席図** — 19,079席を平面展開。3Dと双方向連動、クリックで同じ個客カード
- **分析ボード** — **OD・移動** / 媒体・スポンサー / セグメント / 価格 / リテンション の5タブ
- **個客ジャーニー再生** — 高LTV×高離反リスクの個客を選び、ゲート→コンコース→ボミトリー→着席を3D再生

## 3. データ

現在の個客データは **決定的PRNGによる合成データ**（同じ席は毎回同じ人物になる再現性あり）。
GIS・アリーナ形状・区画構成・交通網は**実データ / 公式資料準拠**。

実データへの差し替えは [`docs/DATA_SPEC.md`](docs/DATA_SPEC.md) の通り。
パネルの「📥 tickets.csv を読み込む」から区画別販売率を即時上書きできる
（`game,section,sold,capacity` または `game,section,rate`）。
