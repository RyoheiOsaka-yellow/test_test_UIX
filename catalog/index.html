00 — HOW TO READ

表現でつくり、社会で使う。
ひとつの技術が5つの領域を通り抜ける。

作品はばらばらの実験に見えて、順番があります。左から右へ、「おもしろい」を「役に立つ」に翻訳していく過程です。 各カードの下部にある3つの欄——WHAT / HOW / WHERE——を読めば、 その作品が系譜のどこに位置し、次のどの領域へ渡されたかが分かります。

01 EXPRESSION

表現をつくる

触れた瞬間に返ってくる応答をつくる。流体・群れ・分割——「場の計算」をリアルタイムで走らせる基礎体力をここで得る。

02 LEARNING

学びに変える

美しいだけで終わらせず、パラメータとモデル式を露出させる。遊びが仮説検証になり、体験が理解になる。

03 ARCHITECTURE

建築に落とす

理解した仕組みで案を生成し、評価する。かたちと空間の設計に、生成と採点のループを持ち込む。

04 ENTERTAINMENT

体験にひらく

設計したものを、来場者が身体で分かる展示にする。企画書の中でプロトタイプがそのまま動く。

05 PUBLIC DESIGN

RUN LIVE

画面をなぞってインクをかき混ぜる

LIVE別タブ

WHAT / 何をするもの

画面をなぞると、その軌跡に沿って顔料が水中へ流れ出し、渦を巻きながら混ざり合います。速く動かすほど濃い墨が落ちるので、筆圧のかわりに速度が濃度になります。

手を止めると2つの「点滴」が静かに巡り、橙と朱を垂らし続ける。放置していても絵が完成しない——終わりのない一枚です。

HOW / 技術のしくみ

WebGPUのコンピュートシェーダでナビエ–ストークス方程式を解いています。128×72の速度場に対し、移流 → 渦度閉じ込め → 発散 → 圧力ヤコビ反復 → 射影を毎フレーム実行し、その速度場で512×288の顔料場を運びます。

肝は表示です。染料をRGBではなく「顔料の量」として保持し、Beer–Lambert則(吸収係数=−ln(インク色))で和紙の白から引き算する。だから橙と墨が重なると、加算合成の白飛びではなく現実のインクと同じ減法混色で暗く沈む。粒状ノイズとヴィネットが紙の質感を補います。

WHERE / どこへ効くか

ブランドの世界観を「見る」から「触れる」へ変える装置として、常設サイネージ、展示ブースの壁面、企業サイトのヒーローに。

同時にこれはGPU汎用計算の実地訓練でもあります。ここで確立した「場を解いて可視化する」パイプラインが、のちの現象シミュレーション(W—04)や都市データの可視化(W—08)にそのまま転用されます。

RUN LIVE

ドラッグで場に触れる / AIRボタンでカメラ入力

LIVE別タブ

WHAT / 何をするもの

画面全体をひとつの正方形として、四分木(quadtree)で再帰的に分割し続けるフィールドです。動きのある場所ほど細かく刻まれ、静かな場所は大きな面のまま残る。

季節が移ろい、詩のようなキャプションが下部に現れては消えます。右下のAIRボタンを押すとカメラが起動し、画面に触れずに手の動きだけで場を乱せます。

HOW / 技術のしくみ

適応的四分木分割 + 季節ステートマシン。分割の深さは局所的な「エネルギー」で決まり、ポインタや手の動きがそこへ注入されます。情報量に応じて解像度を変えるという、可視化設計そのものの発想です。

非接触入力は getUserMedia のフレーム差分によるモーション検出。専用センサーなしで、ブラウザだけでハンドトラッキングが成立します。HUDは env(safe-area-inset) 対応で、スマホでもフルスクリーン表示が崩れません。

WHERE / どこへ効くか

触れずに操作できるので、不特定多数が通る展示空間——ミュージアム、商業施設、イベントブース——の常設インタラクションに向きます。センサー導入コストがゼロなのも現場では効きます。

「注目度に応じて細かくする」という適応分割の考え方は、大規模データの可視化やLOD制御へ直接持ち込めます。

RUN LIVE

ドラッグで回転 / クリックで餌 / スライダーで群れの性格を変える

LIVE別タブ

WHAT / 何をするもの

結束・整列・分離の3つの操舵力だけで魚の群れを成立させるBoidsシミュレーション。スライダーでその配分を変えると、群れの性格——密集するか、散開するか——が即座に変わります。

体は8節の距離拘束で頭を追い、尾びれは泳ぐ速さに比例して強く振れる。ときどき緋色の一匹が混ざります。

HOW / 技術のしくみ

使っているのは mathcat カーネル(vec3 / mat4 / random / easing / color)だけ。全バッファを起動時に Float32Array で確保し、以降は subarray ビュー越しに op(out, a, b) 規約で演算する——フレーム中のアロケーションはゼロ、つまりGCによるカクつきが原理的に起きません。

クリック位置は invert(viewProj) でレイを飛ばし、水槽内の一点へ逆射影して餌に。乱数はシード付きなので、リロードしても必ず同じ群れが生まれます(再現性のあるシミュレーション)。

WHERE / どこへ効くか

群衆流動、交通、生態系——「個の単純なルールから全体の挙動が立ち上がる」系のシミュレーション基盤です。工場の人・モノの動線解析(W—06)や、来場者の回遊予測へ直結します。

ゼロアロケーション設計と再現性は、そのまま組込み機器・サイネージでの長時間安定動作という実務要件を満たします。表現作品でありながら、性能設計の実証でもある一本です。

LIVE別タブ

WHAT / 何をするもの

22の宇宙・332の現象を収めた実験室のコレクションです。入口は展示ではなく問い——「もし、こうしたら？」。その問いをたどると、対応する実験室が開きます。

各ラボにはプリセット / パラメータ / 初期条件 / 世界の数 / メトリクス / モデルが並び、あそぶ → 見る → しくみ の3モードで段階的に深く潜れる。迷ったら「おまかせで開く」。気に入った状態はURLで共有できます。

HOW / 技術のしくみ

332の現象すべてを単一のHTMLファイルに内包し、インストールもサーバーも不要で配布できる構成。状態はURLへシリアライズされるので、先生が設定した初期条件をそのままリンクで生徒に渡せます。

特筆すべきは「全ラボ動作検査」——各ラボが既知解と一致するかを自己診断するテストを内蔵しています。教材が壊れていないことを、教材自身が証明する。「科学的テスト」ボタンから誰でも実行できます。

WHERE / どこへ効くか

科学館の常設展示、学校のICT教材、企業のR&D説明資料。1ファイル配るだけで成立するため、ネットワーク制限の厳しい学校・自治体の環境でも運用できます。

この章の成果は「触れる表現に、モデルと検証を足す」という型そのもの。次章の建築(W—05/06)は、この型を設計案の生成と評価へ持ち込んだものです。

RUN LIVE

左のつまみを動かす / 🎲で新しい図面 / PNG保存

LIVE別タブ

WHAT / 何をするもの

FORM / STRUCTURE / SITE / MEDIA のつまみを回すと、SF建築の図面が手描きの線で自動生成されます。🎲を押せば別案、「引き直す」で同じ条件の別ドローイング。

描画アニメで線が引かれていく過程が見え、線画モードにすれば塗り絵として配れる。凡例、方位、SHEET LOG(ストローク数・パーツ数・作図時間・用紙・画材)まで、図面の作法をきちんと踏んでいます。PNG／高解像度で書き出し可能。

HOW / 技術のしくみ

SVGフィルタ(feTurbulence + displacement)でペン先の揺らぎと紙の滲みを再現。定規で引いた直線ではなく、手が震えた線になっているのが本質です。CADの冷たさを避けるための意匠であり、初期案に「まだ決まっていない」という余白を残す装置でもあります。

形状はseedベースの手続き生成。同じseedなら同じ図面が再現され、つまみを1つ変えれば差分だけが変わる——案の比較検討ができる乱数設計です。Canvasへストロークを逐次描画し、高解像度ラスタライズで印刷にも耐えます。

WHERE / どこへ効くか

建築の初期スタディ、コンペのイメージ出し、クライアントとの発散フェーズ。「10案見せてください」に数分で応えるための道具です。

子ども向けワークショップでは塗り絵として配れる。生成AIの前段にある「大量に出して選ぶ」という設計行為そのものを、絵の温度を落とさずに自動化しています。

RUN LIVE

設備をドラッグして動かす / 混雑表示 / BIM表示（4MB・読込に時間がかかります）

LIVE別タブ

WHAT / 何をするもの

敷地全体からライン単位まで踏み込める3D工場シミュレータ。設備をドラッグで移動・回転・複製し、稼働を再生すると人とモノが流れ出します。混雑表示でボトルネックが赤く浮かび、SLP評価指標がレイアウト案を採点します。

「基準を記録」してゴーストで重ねれば改善前後を直接比較できる。生産性分析から改善提案の自動計算、搬入出口の最適化まで。BIM表示に切り替えるとMEP(電気・空調・給排水)の系統が現れ、干渉チェックと系統図を確認できます。図面モードで2D化、配置はJSONで書出・読込。

HOW / 技術のしくみ

WebGLの3Dシーン上に、SLP(Systematic Layout Planning)の評価関数を実装。搬送距離／日・動線交差・最長動線・全社の物流工数／日を、設備を動かした瞬間に再計算します(フォークリフト7km/h＋徒歩4km/hで敷地と建屋内を合算)。W—03のBoids的な流動計算が、ここでは人とフォークリフトの動線として働きます。

MEPレイヤーはダクト・配管・電路をジオメトリとして持ち、クラッシュ判定で物理的な衝突を列挙。現地写真も同梱され、実測とモデルを突き合わせながら検討できます。

WHERE / どこへ効くか

製造業の設備投資判断と施工前の合意形成。生産技術・建築設計・情シス・経営が、同じ画面を見ながら議論するための共通言語になります。

従来は専用CAEと専門オペレーターが要った検討を、ブラウザで誰でも触れる形にしたことが要点。決裁者が自分の手で動かして納得できるかどうかが、プロジェクトの速度を決めます。

WHAT / 何をするもの

2027年国際園芸博覧会(GREEN×EXPO)へ向けた企画資料です。横浜市の3つの行政区・部局が取り組む脱炭素・資源循環施策を題材に、代理店側の企画立案として体験型の展示什器を設計し、3案件を提案しました。

② クイズ！みなとみらいのリサイクル(みなとみらい21区／脱炭素の取り組み可視化)：◯×クイズで街の取り組みを知る。
③ 楽にたくさん水を運んじゃお！(横浜市水道局／水源林保全と省エネ水道システム)：蛇口をひねって、水がどう届くかを体感する。

HOW / 技術のしくみ

各ケースに企画コンセプトと素材・仕様を記した通常の提案パートがあり、その隣で実際に触れるデモが動きます。ハンドルは長押しで回り、クイズは採点され、蛇口はひねれば水が出る。

資料はHTML1枚。模型写真や図版を内包し、メールで送ってブラウザで開けば、その場で体験が始まります。「こういう展示になります」を説明する代わりに、その展示のミニチュアを渡す——これが提案の速度と精度を変えます。

WHERE / どこへ効くか

行政・自治体の広報展示、博覧会、企業パビリオン。エンターテイメントとして成立させながら、脱炭素・水源林保全といった政策メッセージを確実に届ける形です。

行政デザインの入口でもあります。ここで培った「市民に伝わる翻訳」が、次章の都市データダッシュボード(W—08)で行政の内側の意思決定へ折り返していきます。

WHAT / 何をするもの

羽田イノベーションシティを中心に据えた人流・図面ダッシュボードです。建物はIFC図面から起こしたフロア(B1F〜RF)を持ち、スライダーでフロアを展開して中身を露出できます。壁・ガラスの図面ライン、滞留ヒートマップ(5日間)、バス経路——見たいレイヤーだけを重ねる。

時刻を進めるとK-fieldの実測位置ログ(2020/9/18–22)による人流がリプレイされます。周辺は建物点群・LOD1ボリューム・道路網・鉄道の実線形・多摩川と東京湾・空港の滑走路まで含み、新空港線(蒲蒲線)構想を有無で切り替えた経路検索、2026年シナリオ(低・中・高)の指標比較まで行えます。

HOW / 技術のしくみ

都市ジオメトリと実測人流データを単一HTML(13.6MB)に内包。外部サーバー・APIキー・タイル配信に依存しないので、閉じたネットワークの庁内環境でもそのまま開けます。行政案件では、この「持ち運べること」が採用可否を左右します。

WebGLで描画し、駅構造の階層モデル・路線の高さプロファイル・駅勢圏ヒート(乗降×時間帯)を同一空間に重ねる。W—01で鍛えたGPUパイプラインとW—04の「パラメータを触ると状態が変わる」UIが、そのまま都市スケールへ拡張された構成です。出典(IFC図面／OpenStreetMap／地理院タイル)と、推計値である箇所を画面上に明示しているのも実務資料としての要件。

WHERE / どこへ効くか

エリアマネジメント、テナント誘致、交通インフラの投資判断、行政オープンデータの可視化。来訪指数・平均滞在・年間来訪・経済波及といった指標つきで議論できるため、そのまま合意形成の場に出せます。

表現から始まった一連の技術が、最後に街の意思決定の道具になる——このカタログの物語は、ここで一周します。

06 — LINEAGE

技術の系譜 —— 8作品は、1本の線でつながっている。

それぞれ独立した作品に見えますが、実際には同じ技術が領域をまたいで受け渡されています。 下の表は、その受け渡しの記録です。

01 EXPRESSION
場の計算を手に入れる。流体(W—01)・分割(W—02)・群れ(W—03)。毎フレーム更新される状態を、手の動きに応答させる技術の芯。ゼロアロケーションと再現性のある乱数という、実務の性能要件もここで確立。
02 LEARNING
その場にモデルと検証を足す(W—04)。パラメータを露出させ、メトリクスを並べ、自己診断テストまで内蔵する。「触れる」が「わかる」になった瞬間、作品は教材になる。
03 ARCHITECTURE
生成と評価のループを設計へ(W—05 / W—06)。案を大量に出す側(手続き生成＋手描きの温度)と、案を数値で採点する側(SLP評価・干渉チェック)。発散と収束が同じブラウザに乗る。
04 ENTERTAINMENT
設計を身体で分かる体験に翻訳(W—07)。同時に、企画書そのものがインタラクティブになるという提案形式の発明。決裁者は読むのではなく、体験して判断する。
05 PUBLIC DESIGN
すべてが街の意思決定の道具へ収束(W—08)。GPUパイプライン、パラメータUI、レイヤー比較、そして単一ファイルで持ち運べること。行政の現場で使えるかどうかは、最後にこの「配れること」が決める。

通底する3つの原則

リアルタイムに触れること

説明の前に、手が先に動く。応答が返るまでの時間がゼロに近いほど、人はモデルを信じ、自分で仮説を立て始めます。8作品すべてが、この一点を守っています。

しくみを隠さないこと

数式・パラメータ・評価指標を表に出す。ブラックボックスは感心されますが、信頼はされません。触りながら理由が読めることが、教育でも行政でも採用の条件になります。

1ファイルで配れること

インストール不要、サーバー不要、外部API不要。HTMLを1枚送れば相手のブラウザで動く。この制約を守り抜くことが、学校・自治体・工場という「導入が難しい現場」への最短経路でした。
