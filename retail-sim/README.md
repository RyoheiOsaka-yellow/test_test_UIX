# xAD 店頭販促シミュレーション プロトタイプ

コンビニ店頭に販促商品を置いた際の消費者行動を 3D エージェントシミュレーションでモデリングし、
xAD 販促ボード仕様のダッシュボードで可視化するプロトタイプ。

**起動方法**: `retail-sim/index.html` をブラウザで開くだけ（単一HTML・完全オフライン動作・依存なし）。

## v2 の主な機能

- **2ページ構成**: 「3Dシミュレーション」と「分析ボード」をトップバーで切替。分析は全幅2カラムの専用ページ
- **施設切替**: コンビニ（新宿駅前店）⇔ 百貨店（デパ地下フロア）。売場構成・通路グラフ・客数・単価が施設ごとに変わる
- **リアルな売場**: 全棚に商品陳列（InstancedMesh）、細線ワイヤーフレームの建築調表現、ガラスケース・レジ・天井照明・入口サイン
- **棚クリック → 売場詳細**: 通過→視線→立寄→購買のファネル、視線獲得率、累計視線時間、販促商品は在庫バーまでその場で確認
- **折り畳みパネル**: 設定パネル・BEACON LOG・分析カードすべて折り畳み可能
- **ライトテーマ**: 明るいトーンに刷新（チャートパレットはCVD検証済み）
- **見やすい動き**: 速度プリセット ×1/×3/×10/×30（既定×3）、歩行ボブ、立寄インジケータ、追従カメラ

## v4: 棚割シミュレーター（棚フォーカスタブ）

「どの段・どの位置に置くか／どのPOPを付けるか／ベタ付け（おまけ添付）をするか」を棚単位で検証する専用タブ。

- **棚プレビュー**: 4段×8列の棚正面図。クリックで配置変更、スロットごとの視線ヒート予測、ゴールデンゾーン（床上85〜150cm）帯を表示
- **設定**: POP 5種（なし/プライスカード/スイングPOP/トップボード/床置き大型）、フェイス数1〜4、ベタ付け（35円/個）、客動線の向き
- **予測**: 棚前通過→視線→手取→購買のファネル、販売数/売上/対基準リフト±CI、増分粗利−コスト（POP費・おまけ原価・フェイス機会コスト込み）
- **要因分解**: 段位置×横位置×フェイス×POP×ベタ付けの倍率を可視化
- **最適配置を提案**: 全組合せを探索し増分粗利−コスト最大の構成を提案（ワンクリック適用）
- **3Dへ反映**: 選択構成を視線・転換係数として3Dシミュレーション本体（PLANO係数）へ接続

係数の根拠（実名）: ゴールデンゾーンに什器売上の8〜9割が集中（エイジス・インパクトホールディングス・リテール・リーダーズ等の解説）／POP設置で認知+25%・売上約2倍の事例（キンコーズ・ジャパン等のコラム）。ベタ付けは本プロトタイプ内のノベルティRCT実測と整合。

## v7: シミュレーション深化（カテゴリB）

- **ペルソナ（顧客セグメント軸）**: 通勤・オフィス／主婦・主夫／学生／シニア／インバウンドの5種。時間帯で構成比が変化（昼夕=通勤、日中=主婦・シニア、夕方=学生。百貨店は訪日客比率↑）。歩行速度・滞在時間・買い回り数・カテゴリ選好・客単価がペルソナ別。3Dでは体色で判別（凡例つき）、分析ボードにセグメント別 構成比・購買率・客単価カード
- **レジ待ち行列**: 物理的な行列形成（レジ別スロット整列）、混雑検知でレジ2番を自動開放、行列5人以上で約45%が離脱する機会損失（balking）モデル。平均待ち時間・最大行列・機会損失額のオペレーションカードと、閾値超過時の「レジ増員」AIアクション
- **天候シグナル（状態型）**: 猛暑35℃／晴れ26℃／雨22℃を切替。来店率・カテゴリ需要（猛暑=飲料+45%、雨=日用品+40%等）・ウォーターフォールの季節項が連動し、3D背景色も変化。猛暑時は「冷ケース前サイネージ強化」アクションが自動出現
- **競合セールイベント**: 近隣競合のセールで推定人流-15%。検知ログと「防衛CP」アクションが発火

## v10: 人の動きとヒートの連動を可視化

計測（人の動き）→ ヒート（蓄積）の因果が画面上で追えるようにした。

- **視線レイ**: 立寄・通過中の客の頭から、棚面の実際の注視点へ「光の粒」が流れる（ペルソナ色。追跡中の客は強調）。
  どの人がどこを見て、そのヒートが生まれているかが一目で分かる
- **注視スプラット**: 見られた瞬間に注視点へ光点が落ち、減衰しながら累積ヒートへ溶けていく
- **ライブ発光レイヤー**: 直近に見られたセル（半減期 約25秒）が白く発光し、時間とともに累積ヒートの色へ戻る
- **床の回遊ヒート**: 歩行の蓄積をバイオレット系の面で表示（視線ヒートの青→赤と色相で区別）。対数スケールで通路の筋まで読める
- **通常表示でも連動**: 直近に見られている棚が脈動して明るくなる（更新間隔 0.12秒）
- **HUD**: `NOW GAZING ▸ 弁当・チルド / 上段 6列目`（追跡中の客が今見ている棚と位置）、視線イベントのレート `19 GAZE/s`
- **検出ドット**: 注視中の客は脈動＋発色が変わる
- ヒートの再投影間隔を 1.0秒 → 0.3秒 に短縮し、人の動きに追随させた

## v11: 人の動きとヒートの連動を突き詰める

「いま誰が、どこを見て、その結果ヒートがどう変わったか」が画面上で完結して追える。

- **ライブ窓を既定に**: 点群モードに入ると `ライブ` 表示になり、**本日累計ヒートの地図の上に、いま見られているセルが
  「見ている人のペルソナ色 → 強いほど白熱」で重なる**。数秒で褪せて累積へ溶けるため、変化が常に目に見える
  （`ライブ / 直近30分 / 本日累計` の3段切替）
- **注視セル枠**: 客が見ている 12×6 グリッドのセルを、その人のペルソナ色の枠で脈動表示。
  「この人がこのセルを計測している」ことが1対1で分かる
- **床のライブ足跡**: 歩いた直後だけ白く光る足跡レイヤーを追加。人が歩くとその軌跡が床に描かれ、
  数十秒かけて累積の回遊ヒート（バイオレット）に沈んでいく（通常表示の床ヒートにも反映）
- **LIVE ACTIVITY パネル**: 店内の全員について「#ID ペルソナ ▸ 注視 弁当・チルド 上段6列 +12.9s」のように
  状態と注視先・累積注視秒をライブ表示。ヒートの供給源が誰なのかが一覧できる
- **注視を自動追跡カメラ**: 注視中の客を捉え続け、その人が注視をやめたら次に見ている人へ自動で乗り換える。
  棚の正面側に回り込むので、視線レイ → セル枠 → 発光 → 累積という連鎖が常に画面内で起きる
- **ヒートを消して描き直しを観察**: 蓄積をゼロにするボタン。押すと真っさらな棚に、人の動きがヒートを描き直していく
- 早送り時に減衰が正しい回数適用されず、ライブ層が不自然に消える不具合を修正
- ヒート再投影を 0.25秒間隔に短縮

## v12: 視線分布の現実性（「棚の下が全く見られない」を解消）

v11までのモデルは「立寄1回＝注視点1つ」で、その高さをアイレベル近傍の単一正規分布から引いていた。
その結果、最下段（床上30cm）の実測注目度が **0.02**（平均1に対して）となり、
5mの壁面什器では **72セル中28セルが一度も視線を受けない** という、実店舗ではあり得ない計測結果になっていた。
v12では棚前行動そのものをモデル化し直した。

**① 注視高さ＝4つの行動の混合分布**（`sampleFixation`）

| 成分 | 重み | 内容 |
|---|---|---|
| 快適域 | 44% | アイレベル−45cm を中心（σ19.5cm）。ゴールデンゾーンが成立する主因 |
| 上下走査 | 25% | 什器全体（床上10cm〜視野上限）を舐めるように探索 |
| 目当ての段 | 21% | 買う予定の商品がある段へ直行。段は什器の全高に分布（重み 0.15/0.33/0.34/0.18） |
| 下段の確認 | 10% | 価格・容量・在庫を見るためにしゃがむ／見下ろす（床上8〜55cm） |

1回の立寄の中で 1.5〜3.8秒ごとにサッケード（注視点の移動）が起き、通過中も周辺視で視線が入る。

**② 立ち位置が什器の長手方向に分散**（`approachSpot`）

- 目当てのフェイス付近に立つ（立ち位置 `standU` を什器長に沿ってサンプリング）
- 立寄中も 4〜11秒ごとに**サイドステップ**して別のフェイスを見に行く
- 視線判定を「什器の中心点」から**線分（最近傍点）**へ変更。5mの棚の端に立った客が
  「その棚を見ていない」と判定される問題を解消
- 横走査幅を什器長に比例させ、什器外へはみ出した注視点は端に張り付かせず折り返す

**③ 段別較正をカーネル回帰に変更**（`measuredTierProfile`）

什器高さが 1.4〜2.0m とばらつくため、最近傍バケツ割当だと低い什器の最上段が「上段」に混入して
段プロファイルが歪んでいた。実測グリッドを「床上高さ→注目密度」の関数とみなし、
ガウス核（バンド幅20cm）で各段の基準高さ上の密度を推定するよう変更。

**結果（DAY15・約6万視線秒の実測）**

| 段 | v11 実測 | v12 実測 | モデル係数 |
|---|---|---|---|
| 最下段（床上30cm） | 0.02 | **0.55** | 0.58 |
| 中下段（床上75cm） | 0.29 | **0.92** | 1.00 |
| ゴールデン（床上115cm） | 2.83 | **1.41** | 1.47 |
| 上段（床上155cm） | 0.86 | **1.12** | 0.95 |

- 視線ゼロのセルは **全什器で 0**（百貨店版でも 504セル中1）
- 什器別の最下行シェアは 5.6〜7.9%（アイトラッキング文献の最下段 8〜12% と整合的な水準）
- 上段が +0.18 とモデルを上回るのは、1.5m級ゴンドラの最上段（床上137cm）が実質ゴールデンゾーンに
  入っているため。これは較正カードが「最大乖離＝上段」として提示し、**実測でモデルを較正**できる

## v13: 人の動きと視線を物理的に正しくする

ダミーデータでも「人の動き」と「どこを見られているか」は実測に耐える精度で出す、という方針で
歩行と視覚のモデルを作り直した。

### 視線: 中心視は常に1点

v12までは視野円錐（±45°）に入った棚すべてに同じ重みで視線秒を積んでいた。
人間の中心視は1点しかないので、これは「同時に4つの棚を注視している」という非現実的な計測になる。

- **注視点（fixation）を1点だけ持つ**。頭部姿勢 → 注視点 → 計測セルが完全に一致する
- **二重ガウスの視力減衰**で離角に応じて配分: 中心窩 σ≈7°（重み0.74）＋ 有効視野 σ≈22°（重み0.26）。
  53°を超えた方向は打ち切り。20°離れた棚は約18%、35°離れれば約7%しか積まれない
- **遮蔽判定**: 視線の線分が他の什器の箱を貫くなら見えていない。
  ゴンドラ越しに反対側の棚を「見た」ことになる問題を解消
- **頭部と体の分離**: 首の可動域は体に対して ±74°。
  これを超える向きは体ごと回るか、取れない姿勢として視力が落ちる
- **俯角の制約と屈み込み**: 俯角が −42° を超える（＝立ったままでは最下段が見えない）と、
  膝と腰を折って目線を下げる。滞在時間の約16%がこの姿勢
- **平ケース（デパ地下の平台）** は天面との交点で計測。格子の v 軸を高さではなく奥行きに対応させた

### 動き: 歩行を物理で回す

- **経路の平滑化**（Chaikin 1パス）でノードを直線で結ぶカクつきを解消
- **加減速**（加速 1.15 / 減速 1.6 m/s²）。曲がるとき・到着するとき・混むときに減速する
- **旋回角速度の上限** 2.4 rad/s（低速時はその場で向きを変えられるので上限が上がる）
- **対人回避**: 前方1.2m以内の他客を避けて横にずれ、詰まっていれば減速
- **什器へのめり込み防止**（回避ステアリングの保険）
- **等身大の人体**: 目線高さ（ペルソナ別 1.50〜1.66m）を基準に骨格を組み直した。
  什器 1.4〜2.0m との相対関係が正しくないと「どこを見ているか」を目視で検証できないため
- **歩幅・歩調が実速度に連動**。屈み込み（膝を曲げて腰を落とす）、商品へ手を伸ばす動作を追加
- **顔の向きが見えるマーカー**を頭部に追加。視線の向きが一目で分かる

### 可視化: 通常表示にも視線レイ

3Dビューの通常表示に **「視線レイ・注視点」レイヤー**（既定ON）を追加。
各客の目線高さ（屈んでいれば下がる）から、計測に使っている注視点そのものへ線が伸び、
注視点に点が乗る。点群モードに切り替えなくても「誰がどこを見ているか」が直接見える。

### 検証結果（4,000ステップの自動計測）

| 検証項目 | 結果 |
|---|---|
| 注視している棚＝最も強く計測された棚 | 3,437 / 3,465（99.2%） |
| 視線レイが什器を貫通した回数 | **0 / 3,818** |
| 首の可動域（体に対する頭部角） | 最大 73.9°（上限74°） |
| 屈み込み姿勢の時間シェア | 15.9% |
| 歩行速度 | p10 0.39 ／ 中央 0.66 ／ p90 1.04 ／ 最大 1.35 m/s |
| 視線ゼロのセル | コンビニ 0／864・百貨店 0／1,152（平ケース含む） |
| 段別プロファイル（モデル 0.58/1.00/1.47/0.95） | コンビニ 0.57/1.05/1.32/1.06・百貨店 0.57/1.10/1.46/0.88 |

## v14: 視線 → 購買の因果を閉じる

v13までの購買判定は `shelf.base × persona × 天候 × 棚割係数` の掛け算で、
**その客が実際にどこを何秒見たかと無関係**だった。`gazeMap` は集計表示にしか使われておらず、
「視線を集めたから売れた」という、このプロダクトの中心にある因果が閉じていなかった。

### 注意の量と質を購買行動へ接続

アイトラッキング×購買の知見にもとづく3成分で、立寄ごとに手取・購買の確率を決める。

| 成分 | 内容 | 基準点 |
|---|---|---|
| ① 注視時間 | 効果は飽和する（対数）。最初の数秒が効き、それ以上は逓減 | 21.5秒 |
| ② 比較行動 | 一度見た段へ戻るサッケードの回数。購買の強い予測子 | 2.55回 |
| ③ 注視位置 | 同じ秒数でもゴールデン帯（床上85〜150cm）で見たほうが手に取られやすい | シェア56.8% |

いずれも基準点（実測分布の中央値）で係数1.0になるよう正規化してあるため、
**全体のKPIは公開統計への較正を保ったまま**、個々の棚では「見られた棚ほど売れる」が成立する。
なお売上着地・客単価などの見出しKPIは `STORE` の較正済み定数から推計しており、この変更の影響を受けない。

さらに **段の到達コスト**（`TIER_REACH = [0.70, 0.95, 1.12, 0.80]`）を独立した経路として追加した。
見つけた後に実際に掴む段階のコストで、最下段は屈む必要があり、上段は腕を伸ばして棚の奥が見えない。

**効いていることの確認**（DAY15・約2,450立寄）:

| 注視秒の四分位 | 平均注視 | 購買率 |
|---|---|---|
| 第1四分位 | 8.8s | 16.8% |
| 第2四分位 | 15.2s | 24.0% |
| 第3四分位 | 22.7s | 35.2% |
| 第4四分位 | 37.0s | 50.7% |

比較サッケード回数別でも 0回 16.3% → 6回以上 49.4% と単調に増える。

### 段の効果を「自然実験」で推定する

段係数は本来「その段に置いたら何個売れるか」の係数なので、注目度だけでは足りない。
本シミュレーションでは**客が探している商品がどの段にあるかが立寄ごとに無作為に割り付けられる**ので、
その割付を条件にした購買率の差が、そのまま段の因果効果になる。

較正カードに3本のバーが並ぶようになった:

| 段 | 注目度（AIカメラ視線） | 売上係数（段別購買率±95%CI） | モデル係数 |
|---|---|---|---|
| 最下段（30cm） | 0.56 | **0.75 ± 0.12** | 0.58 |
| 中下段（75cm） | 1.05 | **0.97 ± 0.08** | 1.00 |
| ゴールデン（115cm） | 1.33 | **1.22 ± 0.09** | 1.47 |
| 上段（155cm） | 1.05 | **1.07 ± 0.17** | 0.95 |

読み取れること: 最下段は**注目度（0.56）より売上係数（0.75）のほうが高い** —
見られにくいが、見つけさえすれば買われる。逆にゴールデンは通説の係数1.47ほどは効いておらず、
較正するとモデルが実測へ引き寄せられる。注意の按分では分子と分母が同じ量になり識別できないため、
この無作為割付を使っている。

### 注視効率 —「見られているのに売れていない」の切り分け

**注視効率 = 1,000視線秒あたりの購買数**を棚別テーブルと売場詳細に追加した。
コンビニ実測で 3.8（雑誌・書籍）〜15.9（弁当・チルド）と4倍の開きが出る。
低い売場は「見られていない」のではなく「見たうえで選ばれていない」＝
置き場所ではなく商品・価格・POPの問題として切り分けられる。

これをAIアクションカードにも接続した（`source: L2 / 注視効率`）。
機会損失を粗利換算し、ゴールデン帯シェアと「購買者の平均注視 vs 全体平均」を根拠として添える。

売場詳細パネルには「注意の質」4指標（1立寄の平均注視／ゴールデン帯シェア／注視効率／購買者の平均注視）を追加。
購買者の平均注視が全体平均を大きく上回るほど「見られること」が購買条件になっている売場で、
差が小さい売場は指名買いが中心、と読める。

## v15: AIカメラの計測誤差モデル（真値 ≠ 計測値）

v14までのシミュレーションは「実際に何が起きたか」（真値）だけを生成していた。
CCTVの視錐台も床カバレッジも**描いているだけ**で、`app_core.js` にカメラへの参照が1つもなく、
カメラから見えない場所でも完璧に計測できてしまう状態だった。実機はそうならない。

### 観測値を別レイヤーとして生成する

カメラ定義を `app_core.js` へ移し、真値と並行して「設置CCTVが実際に観測できた値」を積む。

| 制約 | モデル |
|---|---|
| カバレッジ | どのカメラの視錐台（半頂角35.5°）にも入らない位置は計測できない |
| 遮蔽 | 什器の陰はレイキャストで判定。他客が0.85m以内にいるとフレームが落ちる |
| 検出率 | 1フレームあたりの人物検出率は93%（良条件）。品質に応じて下がる |
| 姿勢推定誤差 | 頭部の向きの推定に σ≈8.9°（1台・良条件）。台数が増えると σ ∝ 1/√台数 で縮む |

注視セルは `gridObs` に、視線秒は `gazeSecObs` に、真値とは別に積まれる。

**コンビニ実測（DAY15）**: 視線秒の捕捉率 **83.6%**／セル位置の一致率 **51%**／
棚面カバレッジ 75%（視線加重）／平均カメラ台数 1.9台。
売場別では カバレッジ 33〜100%、捕捉率 63〜93%、セル一致率 20〜66% とばらつく。

### 確信度ラベルが計測品質から決まる

分析ボードに「**計測品質｜真値 vs AIカメラ計測値**」カードを追加。
全体指標と、計測品質が低い売場4件（カバレッジ／カメラ台数／捕捉率／セル一致率／確信度）を出す。
確信度は `捕捉率×0.4 + カバレッジ×0.35 + セル一致率×0.25` から高／中／低を決める。

デジタルツイン（点群×CCTV）に「**ヒートの出どころ**」切替（真値／AIカメラ計測値）を追加。
同じ画面で、実機が実際に取れるヒートマップと真値を見比べられる。

### カメラ増設提案

「注目されているのにカバレッジが低い売場」を `視線秒 × (1 − カバレッジ)` で選び、AIアクションに出す。
**実行するとシミュレーションに実際にカメラが増設される** — 棚の正面側・通路上の候補位置を
9点探索して棚面カバレッジが最大になる場所に置き、デジタルツインにも視錐台が描かれる。

実測例: 「パン・スイーツ」向けに1台増設 → 当該棚のカバレッジ **42% → 100%**、
店舗全体の視線加重カバレッジ 74.7% → 78.6%。

計測は打ち手ではないが、打ち手の確信度を上げる前提条件、という位置づけで L0 レイヤーに置いている。

## 何をシミュレーションしているか

| モデル | 内容 |
|---|---|
| 来店 | 時間帯カーブ（通勤・昼・夕ピーク）× 店前人流レベル × デジタルCP由来の来店リフトでポアソン到着 |
| 店内回遊 | 通路グラフ上の経路探索＋買い回り計画（人気度加重で棚を選択、最近傍順に巡回、レジ→退店） |
| 棚ごとの視線検知 | 各エージェントの視野（±45°・2.9m）と棚正面の交差を常時判定。通過・視線獲得・立寄・手に取り・購買のファネルを棚別に集計 |
| デジタルCP連動 | 広告予算 → 広告接触客比率と指名来店（販促棚への直行）が増加。接触客は販促商品の購買確率が上がる |
| ノベルティ配布（RCT） | 入口スタンド通過客を無作為に処置群/対照群へ割付。対象商品購買率のリフトを z 検定し、CI・MDE・有意性到達度を表示 |
| 消費予測 | ライブ購買レートから欠品時刻を予測。欠品中は「在庫内生性」（買いたくても買えない＝機会損失）を別カウント |

## ダッシュボード（xAD 販促ボード仕様）

`docs/xAD_UI_handoff.md` / `docs/addash_analytics_spec.md` の以下の器を実装:

- **KPIカード**: 点推定 ± 95%CI ＋ 確信度3段階ラベル（高=推奨/中=要サンプル/低=互角）
- **成果分解ウォーターフォール (L1)**: 総売上 = ベースライン + デジタル広告増分 + ノベルティ増分 + 人流寄与 + 季節要因。各項に確信度
- **O2O FUNNEL 二重接続**: 上段=集団・因果（広告接触→増分来店→iROAS）、下段=個人・実購買（ノベルティ受取→対象商品購買→再来店）、中央に突合バッジ（整合/乖離警告）
- **TIME CHART**: 実績14日＋本日ライブ＋予測3日（信頼区間バンド）、CP開始の異常検知マーカー
- **棚別テーブル**: 視線獲得率・立寄・転換率ランキング（行クリックで3Dカメラが棚へ移動）
- **BEACON LOG**: 店内行動の質的サンプルフィード
- **AIアクションカード**: ハンドオフ仕様の接続契約（priority / impact±ci / confidence / verification）に準拠。実行→効果確認のループつき
- **確信度の統一表現**: 全推計値が「点推定 ± 信頼区間 ＋ 確信度ラベル」フォーマット

## 操作

- 左パネル: シナリオ（広告予算 / ノベルティ配布率 / エンド陳列 / 人流レベル）とレイヤー表示（視線ヒート・回遊ヒートマップ・視線コーン・動線トレイル）
